# 収益モデル: AI自動リサーチ→有料ニュースレター

## 何を売るのか

売り物は「情報」ではなく **読者が調べる時間** です。無料で読める一次情報を
毎日追いかける代わりに、選別済み・分析済みの数項目を受け取る対価として課金します。

AIで自動化できるのは **制作** の部分だけです。制作原価がほぼゼロになるので、
ボトルネックは最初から最後まで **配布（読者を集めること）** に移ります。
この前提を外すと「毎日号は出るが誰も読んでいない」状態になります。

## ユニットエコノミクス

1号あたりのAPI原価（Claude Opus 5、実測ベースの見積り）:

| 工程 | 入力/出力トークン | 原価 |
|---|---|---|
| 選別（20件を採点、effort=low） | 約 3,000 / 800 | 約 $0.035 |
| 本文生成（6件、effort=high） | 約 4,000 / 5,000 | 約 $0.145 |
| **合計** | | **約 $0.18 / 号** |

発行頻度別の月間API原価:

| 頻度 | 号数/月 | API原価/月 | Pro($30)換算の損益分岐 |
|---|---|---|---|
| 週次 | 約 4.3 | 約 $0.8 | 有料1人 |
| 平日毎日 | 約 22 | 約 $4.0 | 有料1人 |

API以外の固定費（実運用で必ず発生する）:

| 項目 | 目安/月 | 備考 |
|---|---|---|
| 配信サービス | $9〜29 | Buttondown / MailerLite など。読者数で増える |
| 決済手数料 | 売上の約3.6%+固定 | Stripe等 |
| ドメイン・独自LP | $1〜10 | |

**結論**: 有料購読者が2〜3人いれば全原価を回収できます。制作コストは意思決定の
論点になりません。投じるべきリソースは、読者獲得と解約率の抑制です。

`moneyloop report` が実測の粗利・1号あたり原価・損益分岐購読者数を毎回計算します。

## 価格設計

| プラン | 価格 | 受け取るもの | 狙い |
|---|---|---|---|
| Free | $0 | 号のティザーと要点1つ | 見込み客プール。ここが実質の広告枠 |
| Pro | $30/月 | 全文 + 明日やることリスト | 主力。個人の経費で決裁できる上限に置く |
| Team | $120/月 | 全文 + 社内共有権 | 法人予算。少数で売上の柱になる |

B2B向けニッチでは、単価を下げるより **読者を絞る** ほうが総売上は伸びます。
$5で1000人を集めるより、$120で50人のほうが到達しやすく、解約も少ない構造です。

## 目標から逆算する

```bash
moneyloop plan --target-profit 3000 --conversion 5
```

月間利益$3,000（約45万円）を$30プランで達成するには有料101人、
無料→有料の転換率5%なら無料読者2,020人が必要、と算出されます。
**この2,020人をどう集めるかが事業計画の本体** で、コード側では解決できません。

## 立ち上げ手順（0→最初の課金）

1. **ニッチを1つに絞る** — 「AI全般」ではなく「製造業の生産管理でのAI活用」のように、
   読者が自分のことだと認識できる粒度にする。
2. **`--dry-run` で2週間分を回す** — 課金なしで、選別の質と号の体裁を確認する。
   ここで「自分が金を払って読むか」を判定し、駄目なら `angle` と情報源を変える。
3. **本番で無料号を4〜8週間出し続ける** — 有料化はアーカイブが積み上がってから。
   実績ゼロの状態で課金導線を置いても転換しない。
4. **Stripeの購読リンクを1本用意し、`sub add --plan pro` で登録を反映する** —
   決済の真実はStripe側に置き、こちらは配信と会計だけを持つ。
5. **`moneyloop report` を毎月確認する** — 転換率が2%を割るなら、価格ではなく
   無料版の内容（価値の証明が足りているか）を疑う。

## 追跡すべきKPI

| 指標 | 見る場所 | 危険水域 |
|---|---|---|
| 無料→有料 転換率 | `report` の conversion_rate | 2%未満 |
| 号あたり原価 | `report` の cost_per_issue_usd | $1超（設定を見直す） |
| 粗利率 | `report` の gross_margin | 80%未満 |
| 発行の欠落 | `run` の skipped_reason | 週2回以上のスキップ |

## 守るべき線（法務・信頼）

この仕組みは放置すると簡単に「AIスパム」に転落します。以下は機能ではなく規律です。

- **著作権**: 一次情報の丸写しはしない。要約と分析を書き、必ず出典リンクを付ける。
  プロンプト（`llm.EDITOR_SYSTEM`）にこの制約を入れてあるが、抜き打ちで実際の出力を確認すること。
- **事実確認**: 生成物は無検証で配信できる状態にあるが、有料である以上、
  少なくとも数値と固有名詞は人間が確認してから送る運用を推奨する。
  自動配信するなら、その旨を読者に開示する。
- **特定商取引法**: 日本で継続課金を行う場合、事業者名・連絡先・解約方法の表示が必要。
- **ステマ規制（景表法）**: アフィリエイトや提供記事を混ぜるなら広告表記を明示する。
- **配信同意**: 取得していないアドレスへ送らない。解約導線を全号に入れる。

## この仕組みが解決しないこと

- **読者獲得**: コードは1人も連れてきません。
- **専門性**: 一次情報を読める編集者がいないニッチでは、選別の質が担保できません。
- **差別化**: 同じ公開情報から同じ要約を作る競合はすぐ現れます。守りになるのは
  `angle`（誰に向けて何を切り取るか）と、独自の情報源だけです。
