# 広告収益モデル: 実用ツールサイト

## なぜ「動画」でも「アプリ」でもなくサイトなのか

3つとも広告で収益化できますが、収益が出るまでの距離が違います。

| 手段 | 収益開始の条件 | 単価の目安 | 主なコスト | 立ち上げの難所 |
|---|---|---|---|---|
| **Webサイト** | AdSense審査に通ること（数日〜数週間） | RPM $2〜8 | ドメイン代のみ | 検索流入が育つまで3〜6か月 |
| 動画(YouTube) | 登録者1,000人 + 総再生4,000時間（またはShorts 1,000万回/90日） | RPM $1〜4 | 制作時間が支配的 | 条件到達までの制作量 |
| アプリ | ストア審査 + インストール獲得 | eCPM $1〜10 | 開発 + ストア年会費 | インストールを取る手段がない |

**動画とアプリは、収益がゼロの期間に投じるコストが大きい**のが難点です。
YouTubeは収益化条件に届くまで1円も入らず、その間の制作工数は全額先出しになります。
アプリはインストールを取る導線を別に用意しなければならず、
結局そこで広告費を払うことになりがちです。

Webサイトは審査を通れば1PV目から収益が発生し、初期費用がドメイン代だけで済みます。
そのため**まずサイトで検索流入を作り、そこを起点に動画やアプリへ広げる**のが、
先出しコストを最小にする順序です。この実装はその1段目にあたります。

## なぜ「記事」ではなく「ツール」なのか

AIで記事を量産して広告を貼る手法は、現在は成立しません。

- Googleの検索スパムポリシーは「**スケールされたコンテンツの不正使用**」を明示的に禁止しています。
  生成手段がAIかどうかではなく、検索順位を目的に大量生成されたかが判断基準です。
- AdSenseは「価値の低い、独自性のないコンテンツ」を審査で落とします。
  公開情報の言い換えだけのサイトは、まず通りません。
- 仮に通っても、コアアップデートで飛んだ時点で収益はゼロになります。

**ツールは違います。** 計算という具体的な用が足せるので、独自性の説明がつきます。
再訪・ブックマークされやすく、検索意図（「LLM 料金 計算」）が明確なぶん
競合も少なく、被リンクも付きやすい。同じ労力なら、記事100本よりツール3本のほうが
広告収益の期待値は高くなります。

このリポジトリのツールは、AI導入の稟議で実際に必要になる3つの計算を扱っています。

- LLM API料金の月額試算
- テキストからのトークン数見積もり
- 業務自動化のROIと投資回収期間

## 収益の規模感

広告は**規模の商売**です。これが購読モデルとの決定的な違いです。

RPM（1,000PVあたりの収益）を$4（約600円）とした場合:

| 月間PV | 月間収益 | 日次PV |
|---|---|---|
| 10,000 | 約 6,000円 | 約 330 |
| 50,000 | 約 30,000円 | 約 1,700 |
| 175,000 | 約 105,000円 | 約 5,800 |
| 500,000 | 約 300,000円 | 約 16,700 |

```bash
adsite forecast --target 700 --rpm 4     # 目標$700/月 → 必要PVを逆算
```

同じリポジトリの購読モデル（moneyloop）では、月10万円を有料34人で達成できます。
広告で同額を出すには**月17万PV**が要ります。**桁が3つ違う**というのが、
この2つのモデルの本質的な差です。

したがって、両方やる場合の役割分担はこうなります。

- **広告** — 無料ツールで広く薄く。訪問者の大半は二度と来ないが、それでいい
- **購読** — 同じサイトの訪問者から、深い需要のある人だけを有料に引き上げる

`adsite ingest` で取り込んだ広告収益は moneyloop の台帳に入るので、
`moneyloop report` で両方を合算したPLとして見られます。

## RPMを上げる前に、PVを増やす

収益 = PV × RPM ですが、**触るべき順番はPVが先**です。
RPMは$2〜8のレンジで、努力してもせいぜい2倍。PVは100倍にできます。

RPMに効く要素（優先度順）:

1. **記事の題材** — 金融・保険・BtoBソフトは単価が高く、エンタメは低い
2. **読者の地域** — 日本と米国では2〜3倍違う
3. **表示位置** — 本文中 > サイド > フッター
4. **広告の数** — 増やすと表示回数は増えるが、表示速度と離脱率が悪化して**PVが落ちる**

4番目が落とし穴です。広告を増やしてRPMが1.2倍になっても、
表示速度の悪化で検索順位が下がりPVが半分になれば、総収益は減ります。
このリポジトリでは、1ページの広告数を上限3枠に制限し、
広告枠の高さを事前確保してレイアウトのずれ（CLS）を防いでいます。
これは体裁の問題ではなく、Core Web Vitalsが検索順位の評価対象だからです。

## AdSense審査で落ちる典型

| 原因 | 対処 |
|---|---|
| コンテンツ不足 | 実質的な内容のあるページを最低10〜15枚。1ページ1,000字以上が目安 |
| プライバシーポリシーがない | `site/content/privacy.md` を自分の情報に書き換えて公開する |
| 運営者情報・連絡先がない | `site/content/about.md` を埋める |
| 独自性がない | 公開情報の要約だけのページを作らない。ツールと実務知見で差をつける |
| ナビゲーションが壊れている | 全ページからトップとポリシーに到達できること（このテンプレートは対応済み） |

審査は**申請前にコンテンツを揃えてから**出してください。
落ちてから直して再申請するより、最初から揃えるほうが早く通ります。

## 運用の流れ

```bash
adsite check                  # 公開前チェック（説明文の欠落、広告非掲載ページの検出）
adsite build                  # 静的サイトを生成
adsite serve                  # ローカルで確認
adsite ingest report.csv      # AdSenseのCSVを台帳に取り込む
moneyloop report              # 広告 + 購読を合算したPL
```

デプロイは `.github/workflows/deploy-site.yml` がGitHub Pagesへ自動で行います。

## KPIと危険水域

| 指標 | 見る場所 | 危険水域 |
|---|---|---|
| 月間PV | Search Console / アナリティクス | 3か月連続で横ばい |
| RPM | `adsite ingest` の出力 | $1未満（題材か地域を見直す） |
| CTR | `adsite ingest` の出力 | 10%超（誤クリックを疑われ、アカウント停止のリスク） |
| ページ表示速度 | PageSpeed Insights | LCP 2.5秒超 |
| 収益上位ページ | `adsite ingest` の出力 | 上位1ページに依存しているとリスク集中 |

CTRが異常に高いのは良い兆候ではありません。
広告とコンテンツの区別がつかない配置になっている可能性があり、
AdSenseは無効クリックとみなしてアカウントを停止します。
このテンプレートが広告に「広告」ラベルを付け、
インタラクティブ要素の隣に置かないのはそのためです。

## 法務・ポリシー上の注意

- **プライバシーポリシーの掲示**は必須です。Cookie利用、第三者配信、オプトアウト方法を明記します。
- **EU/UK向けにはGoogle認定のCMP**が必要です。自作の同意バナーでは要件を満たしません。
  `config/site.json` の `ads.consent_cmp_script` に認定CMPのタグを入れてください。
- **ステマ規制（景品表示法）** — アフィリエイトや提供コンテンツを混ぜる場合は広告表記が必要です。
- **自己クリックは禁止**です。テスト目的でも自分の広告をクリックしないでください。
- **ツールの出力は概算**である旨を明示してください（免責は雛形に含めてあります）。

## この仕組みが解決しないこと

**検索流入は自動的には増えません。** ツールを作って公開しただけでは、
Googleに認識されるまで数週間、順位が付くまで数か月かかります。
その間の収益はほぼゼロです。

打てる手は、検索エンジンの外から最初の流入を作ることです。
関連コミュニティで実際に役立つ場面に出す、既存の記事から導線を張る、
といった地道な作業が要ります。ここはコードでは代替できません。
