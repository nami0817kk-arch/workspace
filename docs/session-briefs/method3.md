# 方式3 — ブラウザゲーム

最初に読むもの: `docs/monetization-plans.md`、`docs/public-identity.md`、`CLAUDE.md`、`docs/session-faq.md`、このフォルダの `_common.md`。

## 中身

ブラウザで遊べる小さなゲームを作り、ゲームを集めた配信サイトに載せる。配信サイトがゲームに広告を出し、その収益を分けてくれる。

**8方式のなかで当たり外れがいちばん大きい。** 企画書に「見た目だけ変えた量産は通らない」とある。同じものに皮をかぶせて数を出すと審査で落ちる。

## 最初にやること

**「量産」の意味を決め直す。** 中身が本当に違うものを複数作るのか、1本を作り込むのか。決めずに作り始めない。

- 配信サイト各社の審査基準・収益分配率・支払いの下限を一次情報で調べる
- 既に出ているゲームの当たりの分布を見る（プレイ数が公開されていれば数字で）
- 月◯円を得るには何本・何プレイ要るかを出し、ユーザーに判断してもらう

ユーザーは `projects/soccer-manager` と `projects/soccer-career` で Flutter のゲームを作っている。勘所は参考になるが、流用は前提にしない。

当たり外れの大きさに見合わないと判断したら、理由を1行残して畳んでよい。
