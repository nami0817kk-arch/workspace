# アプリ（Flutter / 広告・課金）で踏んだ穴

`projects/soccer-manager` `projects/soccer-career` `projects/goso-boat` のように、
広告と課金を入れて App Store に出すアプリを作るときの落とし穴。**実際に踏んで、
利用者に届いてしまったもの**だけを書いている。新しくアプリを作るとき、
収益化を足すとき、掲載画像を用意するときに、この一覧を当てること。

どれも「例外が出ない・テストが落ちない」形で壊れる。だから**検査の形まで**書いてある。

---

## 1. 払ったのに届かない（2026-09-26 / soccer-career・soccer-manager）

**症状**: 購入したのに特典が付かない。資金パック（消費型）は「復元」でも戻らず、
払った額がそのまま消える。

**原因**: ストアからの購入通知を、`await` している側にだけ返していた。待っている人が
居ないときに届いた購入は、**完了通知だけ返して捨てられる**。待ち手が居ない場面:

- アプリを落としている間に決済が通った
- 家族の承認（Ask to Buy）が後から下りた
- こちらが待つのをやめた（5分の上限）後に届いた
- 別の端末で買ったぶんが起動時に流れてきた

**直し方**: 渡すほうは待っているかどうかを見ない（`onDelivered`）。受け取りを1か所に
集める。**受け取りが終わるまで完了通知（`completePurchase`）を返さない**——返すと
ストアは二度と送ってこない。

**検査**: 「待っている人が居なくても届いた購入を受け取る」「再起動後も残る」
「二度渡らない」。差し替え実装が**結果を返す前に通知で届ける**形になっていること。
買う操作の戻り値だけで特典を渡すテストは、壊れた形を追認してしまう。

## 2. 広告を見終えた後に画面を離れると、回数だけ減って何も入らない（2026-09-26）

**症状**: リワード広告を最後まで見たのに特典が入らない。その日の回数だけ消費される。

**原因**: 受け取りを `if (!mounted) return;` の後ろに置いていた。広告を見ている間に
画面を離れると State が捨てられ、そこで返る。**広告は再生されきっているので、
こちらには収入が立ち、利用者には何も入らない。**

**直し方**: 受け取りは `mounted` を見ない位置に置く。`mounted` は画面の更新だけに使う。

**検査**: 広告の再生を止めたまま画面を離し、その後に再生を終わらせて、資金が
入っているかを見る（`Completer` で再生を制御する差し替え広告）。

## 3. 広告の期限切れを扱っていない（2026-09-28 / soccer-manager）

**症状**: 広告リクエストばかり増えて表示が増えない（実測で7日 231回に対して6回）。
利用者から見ると「受け取るを押したのに広告が出ない」。

**原因**: **AdMob の広告は1時間で期限切れになる。** 公式が「キャッシュを捨てて
1時間ごとに読み直せ」と書いている。読み込んだ参照を持ち続け、
`isRewardedAdReady` が `_ad != null` を返していた。期限切れでも「準備できている」と
答え、出そうとして失敗する。

> Ads expire after an hour, and you should clear this cache and reload with new ads every hour.
> — https://developers.google.com/admob/android/rewarded

**直し方**: 読み込んだ時刻を持ち、55分（1時間より手前）を過ぎたら捨てて読み直す。
**出るまでが長い広告は、起動時に先読みしない。** シーズンの切り替わりのように
何十分も先に出るものは、出す直前に読む（数秒待って、読めなければ広告なしで進める）。

**検査**: 期限の判定（直後・手前・超過・未読み込み）と、`adLifetime < 1時間`。
「起動時に先読みしていないこと」「出す直前に読んでいること」は原文を見て確かめる。

## 4. 掲載画像が白紙のままストアに出ていた（2026-09-28 / soccer-manager）

**症状**: App Store の掲載画像の1枚目が、読み込み中の丸だけが写った白紙。
**公開から3週間、検索結果のいちばん目立つ枠がそれだった。**

**原因**: 生成器の疑似時間 `pump` では、裏で読み込みを待つ画面（`FutureBuilder` +
`SharedPreferences` など）の待ちが終わらない。読み込み中の状態を撮っていた。
この絵は**例外もはみ出しも出さない**ので、それまでの検査を全部すり抜けた。

**直し方**: 撮る前に `tester.runAsync` で実時間を進める。そして**撮るたびに
「撮れていること」を検査する**。

```dart
expect(find.byType(CircularProgressIndicator), findsNothing,
    reason: '$name が読み込み中のまま撮られている');
expect(find.byType(Text), findsAtLeastNWidgets(3),
    reason: '$name に文字がほとんど無い(描画を待たずに撮っている)');
```

**見つけ方（既存の画像を疑うとき）**: ファイルの大きさで当たりを付けられる。
白紙は 22,597 バイトだった。中身のある画像は 100KB を超える。

**ついでに**: タイトル画面・起動画面は撮らない。検索結果には先頭3枚しか出ないので、
何ができるゲームかを伝えない絵を置くと枠を捨てることになる。

## 5. `CFBundleLocalizations` だけでは、ストアの言語欄が直らない（2026-09-28）

**症状**: 日本語で動くアプリなのに、App Store の「言語」が英語だけ。

**原因**: `Info.plist` に `CFBundleLocalizations`（ja/en）を書いても足りない。
**実体として `ja.lproj/InfoPlist.strings` が入っていないと、Apple は言語として
認めない。** Flutter は `Base.lproj` しか持たない。

**直し方**: `ios/Runner/ja.lproj/InfoPlist.strings` を作り、Xcode のプロジェクトに
登録する（`PBXFileReference` ×2・`PBXVariantGroup`・`PBXBuildFile`・Resources への
追加・`knownRegions` に言語コード）。

**確かめ方**: **ビルドした IPA を開いて `Payload/Runner.app/ja.lproj` があることを
目で見る。** 申告を入れただけで直ったと思い込み、成果物を開かずに1日無駄にした。

```bash
unzip -q アプリ.ipa -d x && ls x/Payload/Runner.app/*.lproj
```

公開後は外から見える値で確かめる。

```bash
curl "https://itunes.apple.com/lookup?id=<App ID>&country=jp"
# languageCodesISO2A が ['JA','EN'] になっているか
```

## 通して言えること

**「直したはず」で終わらせない。** 4も5も、コードの上では直っていた。
成果物（IPA・PNG）を開いて中身を見るまでは直っていない。

**壊れ方が静かなものは、検査の形を決めておく。** 白紙の画像も、届かない購入も、
期限切れの広告も、例外を出さない。出ないものは人が気づかない。

関連: `projects/soccer-manager/docs/RELEASE_GUIDE.md` の「毎回のリリース手順」、
ユーザーレベルスキル `ios-app-release`。
