# 台本制作の仕組み（いつ・どこから・何を取るか）

取材は「毎回思い出しながらやる」と抜けが出る。手順を設定ファイルに落として、
**取材メモ → 検証 → 台本** を一本の流れにしてある。

```
config/sources.yaml   いつ・どこから・何を取るか（計画）
        │  scan                     朝いちど、候補を広く拾う
        ▼
research/YYYYMMDD_candidates.yaml   候補（見出しだけ。深掘りはまだしない）
        │  pick → plan              採点して枠に割り振り、取材メモの雛形を作る
        ▼
research/YYYYMMDD.yaml   取材メモ（拾った内容をここに書く）
        │  draft  ← ここで確度の条件を機械的に確認
        ▼
scripts/YYYYMMDD.md      台本
        │  build
        ▼
output/YYYYMMDD/         動画一式
```

## 1. いつ・どこから・何を（config/sources.yaml）

**1日3本**を前提に、時間帯で役割を分けてある。同じ形の動画を3本出すと
飽きられるので、枠ごとに扱うものと尺を変える。

| 枠 | 公開 | 何を1つ選ぶか | 尺 | 節の型 |
|---|---|---|---|---|
| `morning` | 07:00 | 夜のあいだに出た発表のうち最大の1件 | 約1.5分 | 何が起きたか→なぜ→これから |
| `noon` | 12:00 | 賛否が割れている話を1件 | 約1.5分 | 何が起きたか→なぜ割れているのか→次の焦点 |
| `evening` | 19:00 | その日いちばん大きいテーマ1つ | 約3分 | 何が→経緯→争点→数字→これから |

特別編として、試合の翌朝に使う `match`（試合結果）と、移籍期限日の `deadline_day` がある。

```bash
python -m src.cli plan --routine match
```

| 節 | 確度 | 内容 |
|---|---|---|
| 試合はこうなった | 確定 | スコアと得点者。リーグ公式で確かめる |
| 試合が決まった場面 | 報道 | 得点・退場・判定。何分の出来事かを控える |
| 数字で見ると | 報道 | xG・シュート数・ポゼッション・順位 |
| 順位と次の一戦 | 報道 | |

**スコアを読み上げて終わりにしない。** どこで試合が決まったのかを1つ挙げて掘る。
勝ったチームを褒めるだけにせず、負けた側に何が起きたかも入れる。

### 試合の収集はリーグごとに分ける

リーグをまたいで1本の検索で済ませると、どの試合の記事か分からないまま雑多に返ります。
`config/sources.yaml` の `leagues` に、リーグごとの引き先と検索語を書いてあります。

| リーグ | 公式（スコアの確認先） | 現地語 | 検索語 |
|---|---|---|---|
| プレミアリーグ | premierleague.com ほか | 英語 | `match report player ratings` |
| ラ・リーガ | laliga.com ほか | スペイン語 | `cronica resultado partido` |
| ブンデスリーガ | bundesliga.com ほか | ドイツ語 | `Spielbericht Noten Analyse` |
| セリエA | legaseriea.it ほか | イタリア語 | `cronaca pagelle partita` |
| リーグアン | psg.fr | フランス語 | `resume match note` |
| エールディヴィジ | — | オランダ語 | `wedstrijdverslag uitslag` |
| Jリーグ | jleague.jp | 日本語 | `試合結果 採点 OR 寸評` |

スキャンでは現地語の1本だけを出します（`scan.match_leagues` に並べたリーグぶん）。
公式はテーマが決まってから当たれば足ります。

```bash
python -m src.cli plan --routine match --league germany
```

```
■ ブンデスリーガ の試合レポートを引く
   ［ブンデスリーガ］ "Spielbericht Noten Analyse"  （kicker.de, sport1.de に限定）
   ［ブンデスリーガ］ "Spielbericht"  （bundesliga.com, fcbayern.com, bvb.de に限定）
   確認: スコアと得点者は公式で確かめる。見出しのスコアを鵜呑みにしない
```

深掘りでも同じで、候補に `league` を書いておけば、`league_official` と
`league_media` の検索がそのリーグの引き先だけに絞られます。

```
試合（公式レポート）: "Bayern Dortmund match report"      （bundesliga.com, bvb.de …）
試合（現地の報道）:   "Bayern Dortmund Spielbericht Noten" （kicker.de, sport1.de）
```

## 検索結果から候補ファイルを作る

検索結果を見ながら候補ファイルを手で書くと、URLを写し間違えるし、拾ったつもりで
抜けることもあります。タイトルとURLを貼れば下書きができます。

```bash
python -m src.cli collect < 検索結果.txt
```

受け付ける形は3つ。

```
見出し<タブ>https://...
見出し
https://...
https://...            （見出しは後で書く）
```

やることは4つです。

1. **URLからサイトと日付を読む**（`fresh` と同じ仕組み）
2. **同じ話をまとめる**。5媒体が同じ移籍を報じたら1件にして出典を並べる。
   動画は1本なので、候補が5件に増えても困るだけ
3. **英語の検索語を作る**。記事URLのスラッグから
   （`emiliano-martinez-signs-for-chelsea` → `Emiliano Martinez Chelsea`）
4. **確度の当たりをつける**。見出しの言い回しから

```
4件 → 候補2件　（サイトが分かったもの 3件 / 日付が読めたもの 0件）
  559463       Spurs 0-2 Newcastle: Tottenham suffer second defeat　＋1媒体
  —            Emiliano Martinez signs for Chelsea!　＋1媒体
```

**`tier` / `topic` / `league` は判断が要るので空のまま残します。**
見出しに書いてあることしか入れません（要約は使いません）。

### 確度の当たり

| 見出しの言い回し | 当たり |
|---|---|
| 公式発表 / official / confirmed / signs for | `確定` |
| **スコアが入っている**（0-2） | `確定`（点数は事実） |
| と報じ / sources / in talks / agreed | `報道` |
| 関心 / 浮上 / linked with / Paper Talk | `未確認` |
| **疑問形で終わる**（〜か？ / Does…?） | `未確認`（観測・分析） |

当たりでしかないので、`# 見て直す` と書いて残します。判断できなければ
`# 判断できず` と書きます。

## 世の中の言葉をどう入れるか

「誰の言葉か」で扱いが変わります。**同じ節に混ぜない。**

| | 確度 | 名前 | カード |
|---|---|---|---|
| 監督・選手・解説者 | `報道` | **出す**（デゼルビ監督、キャラガー氏） | `quote` |
| 一般のファン | `未確認` | **出さない**（「海外のファン」「X」まで） | `reactions` |

深掘りの検索も分けてあります。

```
識者・当事者の発言: "... said OR quotes reaction"  （skysports.com ほか）
反応（日本語）:     "... 反応 OR 声 OR 批判"        （日本語media）
反応（SNS）:        "... fans reaction"             （x.com）
```

### 捏造を止める仕組み

もっともらしいファンの声は、思いつきでいくらでも書けます。ここだけは警告ではなく
**通さない扱い**にしてあります。

- `reactions` カードに `sources` が無ければ `draft` が止まる
- ラベルにアカウント名（`@…`）を書くと止まる。個人が特定できる形では出さない

警告になるのは次の2つです。

- 反応の節を `報道` として出そうとしたとき（数人の投稿は世の中の総意ではない）
- 「〜という声が多い」「ほとんどのファンが」など、**数を数えた言い方**をしたとき。
  投稿を数えていないなら「こういう声もある」に留める

```
ヒント: 節『世の中はどう見ているか』: 「声が多」は数を数えた言い方です。
投稿を数えていないなら「こういう声もある」に留めてください
```

### 反応が取れないことは普通にある

SNSの検索は1〜2日遅れる（[情報源](news-sources.md)）ので、**試合直後の反応は取れません**。
Reddit も塞がれています。取れなければ節ごと落として、識者の言葉だけで組んでください。
無理に埋めると捏造になります。

### 条件は並べて書ける

`when` に並びを書くと「どちらも満たすとき」になります。

```yaml
  - {q: "{en} offiziell", domains: german, when: [germany, transfer]}
```

ドイツの**移籍**のときだけ出ます。スペインの移籍にも、ドイツの試合にも出ません。

**どの枠も「1本＝1テーマ」。** 速報枠でも複数の話題を並べない。
朝が短いのは節が少ないからで、掘り方が浅いわけではない。

節の型は `config/sources.yaml` の `structure` にあり、取材メモの雛形に反映される。

`morning` が夜の話題なのは時差の都合。欧州の試合と発表は日本の深夜に出るので、
**朝いちばんが一番ネタが溜まっている時間帯**になる。

特別編として `deadline_day`（移籍期限の当日と翌日）も用意してある。

「どこから」は `domains` に定義してある。**ここに無いサイトは検索対象にしない。**
`blocked` は実測で中身が取れなかったサイト（2026-08-31 時点で telegraph.co.uk と
talksport.com の2件）で、検索しても結果が返らない。詳細は [情報源](news-sources.md)。

「何を」は各 routine の `steps`。1ステップ＝1つの話題で、それぞれに
**既定の確度**と**検索の型**と**確認事項**が付いている。

## 2. 候補を拾って、選ぶ（scan → pick）

1日3本を毎日続けると、**選ぶところ**が一番の負担になる。
「拾う」と「選ぶ」を分けて、選ぶ基準を設定ファイルに固定してある。

### 拾う（朝いちど）

```bash
python -m src.cli scan --write
```

`scan` の検索を回して、返ってきた**見出しだけ**を候補ファイルに並べる。
ここでは深掘りしない。1件1行、5〜10件も拾えば足りる。

```yaml
candidates:
  - id: alvarez_barca
    title: アルバレスがバルサに行けない本当の理由
    en: Julian Alvarez Atletico Barcelona   # 英語サイトを引くときの語
    hours_ago: 4        # 何時間前の話題か
    tier: 報道           # 確定 / 報道 / 未確認
    topic: alvarez      # 話題のまとまり。同じ topic は1日1枠まで
    league: spain       # そのリーグの言語で深掘り検索が出る
    kind: transfer      # transfer / match / other。match なら試合むけの検索が出る
    reaction: true      # 賛否が割れる・驚きがあるか
    numbers: true       # 金額・記録など数字が立つか
```

`hours_ago` は**空でよい**。`url` を書いておけば `pick` が割り出す。

```bash
python -m src.cli fresh <拾ったURL> <URL> ...
```

記事の公開日はどこにも書いていないが、ニュースサイトのURLに入っている
記事IDが時系列に増えるので、それで新しさが分かる。Xの投稿は投稿URLから
正確な時刻が出る。詳しくは [情報源](news-sources.md)。

**索引が進んでいないと出た日は、朝の速報枠をあきらめる。** 古い記事を
「最新」として出すより、その日は速報を出さないほうがよい。

`en` は**英語サイトを検索するための語**。日本語の見出しで skysports.com を
引いても何も返らないので、選手名とクラブ名を英語で入れておく。
Jリーグの話題のように英語圏で報じられないものは、空のままでよい。
`big_club` は `scoring.big_clubs` の名前が見出しに入っていれば自動で立つ。

### 選ぶ

```bash
python -m src.cli pick research/20260829_candidates.yaml
```

やることは3つ。

**1. 採点する。** `scoring.weights` の配点で並べ替える。

| 項目 | 点 | 理由 |
|---|---|---|
| 新しさ | 3 | 6時間以内=満点、12時間=2/3、24時間=1/3、それ以降=0 |
| 反応 | 3 | 賛否が割れる話はコメントが伸びる |
| ビッグクラブ | 2 | 名前だけで再生が付く |
| 数字 | 1 | 金額・記録はサムネにしやすい |
| 得点 | 2 | 試合結果むけ。点が多く動いた試合は見られる |
| 番狂わせ | 3 | 試合結果むけ。格上撃破は伸びる |

内訳も一緒に出るので、**なぜその順になったかが読める**。
点数は並べ替えの目安で、最後に決めるのは人。違うと思えば手で入れ替えてよい。

**2. 直近で扱った話題を外す。** `research/covered.yaml` と突き合わせ、
`coverage.repeat_within_hours`（既定36時間）以内に出したものは候補から落ちる。
朝に出した話が夜にまた上がってくるのを止めるため。落ちたものも
「どの枠で既出か」つきで表示される。

**3. 枠に割り振る。** `scoring.slots` の方針で1枠1本ずつ、重複なく。

| 枠 | 方針 | 条件 |
|---|---|---|
| `morning` | いちばん新しいもの | 確度が 確定 か 報道 のものだけ |
| `noon` | 賛否が割れているもの | — |
| `evening` | 残りの最高点 | — |

条件に合う候補が無ければ全体から選ぶ（朝が空になるより出したほうがよい）。
**そのときは満たせなかった条件が表示される。** 黙って入れ替えると、
枠の狙いから外れていることに気づけない。

### 同じ話題を1日に2本出さない

大きい話が1つあると、3枠ともそれで埋まる。候補に `topic`（話題のまとまり）を
書いておくと、**同じ `topic` は1日1枠までになる**。

```yaml
  - id: alvarez_deadline
    topic: alvarez        # 同じ案件の別記事も alvarez にする
  - id: alvarez_laporta
    topic: alvarez        # → 2枠目には入らない
```

実際の効果。8月30日はアルバレス関連が2件あり、点数だけなら夜も
アルバレスになるところが、別の話題に振り替わった。

```
■ 朝の一報 → アルバレスに示された日曜という期限（7点）
■ 昼の話題 → 320億円使って最下位のトッテナム（7点）
■ 夜のまとめ・深掘り → リバプールがイスマイラ・サール獲得へ交渉（5点）
                       ↑ ラポルタ会長の話（7点・topic: alvarez）を飛ばした
```

### 同じ種類を3本続けない

`kind`（transfer / match / other）も散らします。**同じ種類は1日2枠まで。**
3本とも試合結果、3本とも移籍だと単調になるためです。
候補が全部同じ種類の日は、散らしようがないので何も言いません。

`topic` を書かない候補は、この判定では弾かれない。
どうしても他に無ければ重複を許すが、その旨が表示される。
`scoring.spread_topics: false` で無効にできる。

そのうえで、選んだテーマごとに**深掘りの検索**が出る。`deep` の雛形に
`{theme}`（日本語の見出し）と `{en}`（英語の語）が入る。
`{en}` を使う行は、候補に `en` が書かれているときだけ出る。

```
■ 朝の一報 → アルバレスがバルサに行けない本当の理由（9点）
   何が起きたか: "アルバレスがバルサに行けない本当の理由 詳細"
   何が起きたか（英語）: "Julian Alvarez Atletico Barcelona latest news"  （skysports.com … に限定）
   なぜそうなったか: "Julian Alvarez Atletico Barcelona why explained"  （skysports.com … に限定）
   反応: "Julian Alvarez Atletico Barcelona"  （x.com に限定）
   数字: "Julian Alvarez Atletico Barcelona fee OR record OR stats"  （skysports.com … に限定）
```

ここまでで**その日の3本のテーマが決まる**。あとは枠ごとに取材メモを書く。

## 3. 取材リストを出す

```bash
python -m src.cli plan --routine all          # 今日の3本ぶんまとめて
python -m src.cli plan --routine morning      # 朝の枠だけ
python -m src.cli plan --routine noon --write # 取材メモの雛形も作る
python -m src.cli plan --routine deadline_day --date 2026-09-01
```

日付は自動で埋まる。`confirmed transfers {period_en}` は
`confirmed transfers August 2026` に展開される。

追いたい選手がいるときは `config/sources.yaml` の `topics` に足す。
その選手ぶんの検索が自動で並ぶ。

```yaml
      - id: rumours
        topics: [Julian Alvarez, 佐野海舟]
```

## 4. 取材メモに書く（1本＝1テーマ）

**複数の話題を並べるまとめは作らない。** 1本で1つのテーマを掘る。

要は3つ。

1. **テーマ** … 何について話すか
2. **問い** … この動画が答える問い。ここが深掘りの軸になる
3. **節** … 問いに答えるための道筋（何が起きたか → なぜ → 争点 → これから）

```yaml
slot: evening
date: "2026年8月29日"

theme:
  id: alvarez_barca              # 重複判定に使う識別子
  prefix: 速報                    # 【速報】【朗報】【悲報】。docs/style.md
  title: アルバレスがバルサに行けない本当の理由
  hook: 移籍市場の閉幕をまえに、最大の焦点になっている移籍があります。
  question: なぜこれは、お金の問題ではないのか   # ← 軸

thumbnail:                        # サムネの帯。docs/style.md
  line1: アトレティコが完全拒否
  line2: バルサ移籍の可能性0%ｷﾀｰ！！
  tags: [そこまで言う？]

answer: 移籍金ではなく、ライバルに主力を渡すこと自体を拒んでいるから
watch: 本人がアーセナル行きに前向きになるかどうか。期限は9月1日

sections:
  - id: what
    heading: 何が起きたか
    tier: 報道
    telop: アトレティコ「バルサ移籍の可能性はゼロパーセント」
    say:
      - 本人はバルセロナへの移籍を望んでいると各紙が伝えています。
      - ところがアトレティコ側は「可能性はゼロパーセントだ」と…
    sources: [https://…, https://…]
    card: {…}                    # 任意。docs/cards.md 参照

  - id: background
    heading: ここに至る経緯
    tier: 背景                    # 新規の報道ではない前提の説明
    …
```

**問いを立てないと台本を作れない。** これが「まとめ」と「深掘り」を分ける一点なので、
`draft` は `question` と `answer` が空だと止まる。

生成される台本は、冒頭で問いを提示し、節で掘り、まとめで答える形になる。

```
オープニング  … つかみ＋「今回の問い: なぜ金の問題ではないのか」
何が起きたか  … 事実
ここに至る経緯 … 背景（画面に［背景］バッジ）
争点はどこか  … 核心
残された時間  … 数字・日程
これからどうなる … 見通し（未確認）
まとめ        … 問いへの答え＋次の焦点
```

### 「背景」という確度

深掘りには前提の説明が要る。それは新規の報道ではないので、
`tier: 背景` を使う。**出典は求められない代わりに、画面に［背景］と出る。**
視聴者に「ここは今日のニュースではない」と伝わる。

読み上げ文は**人名・数字をひらがなに開く**（誤読を防ぐ）。画面には `telop` の
漢字表記が出るので、見た目は変わらない。

## 5. 同じ話題を繰り返さない

1日3本を続けると「朝に出した話を夜にもう一度出す」が必ず起きる。
台本を作るたびに `research/covered.yaml` に記録され、次に作るとき突き合わせる。

`plan` には直近で扱った話題が出る。

```
　直近で扱った話題（繰り返さない）:
　　08/29 07:12 [morning] 鈴木彩艶がアストン・ヴィラへ
　　08/29 12:05 [noon] 佐野海舟の去就
```

`draft` は重なっていると止まる。

```
重複しています:
  - suzuki: 08/29 07:12 の［morning］で扱った話題です（鈴木彩艶が…）。
    深掘りとして出すなら follow_up: true を書いてください
```

**意図的に深掘りする場合**は取材メモに `follow_up: true` を書く。
夜の枠で朝の速報をまとめ直すのは普通の運用なので、そのための逃げ道。

判定の幅は `coverage.repeat_within_hours`（既定36時間）で変えられる。

## 6. 検証してから台本にする

```bash
python -m src.cli draft research/20260829_weekly.yaml
python -m src.cli draft research/20260829_weekly.yaml --check-only   # 検証だけ
```

**確度の条件を満たしていないと台本を作らない。** 条件は `config/sources.yaml`
の `tiers` にある。

| 確度 | 条件 |
|---|---|
| `確定` | 出典1本以上 **かつ** `official: true`（クラブ・当事者の発表） |
| `報道` | 出典**2本以上**（2社で一致していること） |
| `未確認` | 出典1本以上 |
| `背景` | 出典不要（新規の報道ではない前提の説明） |

構成についても止まる。

| 条件 | 理由 |
|---|---|
| `question` が必要 | 問いが無いものは深掘りではない |
| `answer` が必要 | 立てた問いに答えないまま終わらせない |
| 節が3つ以上 | 2つでは掘ったことにならない |

止まる例:

```
取材メモに不備があります:
  - a: 確度『報道』には出典が2本必要です（いまは1本）
  - b: 確度『確定』はクラブ・当事者の発表が条件です。
       発表を確認できないなら tier を下げてください
```

これは「急いでいるときほど確度を上げたくなる」のを機械側で止めるためのもの。
条件を緩めたいときは設定を変えることになるので、**判断が記録に残る**。

生成される台本には、章立て・確度バッジ・出典・まとめカードが入った状態になる。
あとは言い回しを整えて `build` すればよい。

## タグを話の中身から作る

タグは4つ固定でした（サッカー / 海外サッカー / サッカーニュース / 解説）。
**どの動画にも同じ4つが付く**ので、検索から見つけてもらう役に立っていません。

見出しに出ているクラブ・リーグ・話の種類は分かっているので、そこから足します。
`draft` が台本の frontmatter に書き込みます。

```

       移籍市場, トッテナム, マンチェスター・シティ, マンチェスターシティ]
```

クラブ名は中黒を抜いた形も入れます（「マンチェスターシティ」でも探されるため）。
**選手名は入れません。** 辞書が無いので、推測で書くことになります。

YouTube はタグの合計を500字までしか受け付けず、超えると投稿そのものが弾かれます。
前から大事な順に並べ、あふれたら後ろから落とします。`review` が合計を数えます。

```
  ✓ タグ　9個 / 合計86字
```

## 収集を一息で行う

フィード取得 → `collect` → 重複除去 → 候補ファイル を毎朝手で繋ぐと、
**どれかを飛ばします。飛ばしても何も言われません。**
「今日はフィードを見ていなかった」に後から気づくことになります。

```bash
python -m src.cli gather                    # フィードから
python -m src.cli gather --paste            # 検索結果を貼ったぶんも混ぜる
python -m src.cli gather --league germany   # そのリーグのフィードだけ
```

1回で次のことをします。

1. 期限日と、いま動いているリーグを言う
2. **確認済みの**フィードだけを取る（未確認は黙って飛ばさず、そう言う）
3. フィードの時刻で索引の水準を較正する
4. すでに動画で使った出典を外す
5. 網に無いサイトを控える
6. 候補ファイルを作り、埋めるところを挙げる

```
■ 収集　2026年8月31日
　移籍期限まであと1日　ブンデスリーガ（9月2日 05:00 JST）
　いま動いている（05:30）: ブンデスリーガ / プレミアリーグ ...

  取れたもの 12件
  すでに使った出典を2件外しました
  索引の水準を較正: skysports.com

候補9件　research/20260831_candidates.yaml
```

フィードが1本でも `verified: true` になっていれば、`today` の一手も
`scan --write` ではなく `gather` になります。

## 続報の差分を見る

移籍も監督人事も**1本では終わりません。** ところが記録には「扱った」としか
残っていないので、次に同じ話が上がってきたとき、

- 前回いつ、どこまで話したのか
- 今日の候補のうち、前回のあとに出たものはどれか

が分かりません。前回と同じことをもう一度話すか、新しく出た1件を落とすかの
どちらかになります。

```bash
python -m src.cli saga research/20260831_candidates.yaml
```

```
■ 続報の見え方　2026年8月31日　新しい話題 1件 / 続報 2件
  続　アトレティコのアルバレス、バルサ移籍が再燃
      16時間前にmorningで「アトレティコが公式声明「バルサとは交渉しない」」
      前回のあとに出た出典 1件:
        https://www.skysports.com/football/news/11661/13100001/alvarez
  新　バイエルンが新監督を発表
```

`pick` の一覧にも `［続報 2本目・前回16時間前］` と印が付きます。
**続報かどうかは点数に出ない**ので、印で見えるようにしています。

同じ話題かどうかは、`id` が同じか、`topic` と見出しから読めるクラブが重なるかで
見ます（日ごとに `id` を付け直しても追えるように）。3週間より前の記録は
別件として扱います。

2つ知らせます。

- **前回に無い出典がない** … 同じ材料で二度目を出すことになります
- **4本目以降** … 追い続ける価値があるか、いちど見直してください

これができるように、`draft` は使った出典と `topic` も記録に残すようになりました。

## 時間帯で取り逃さない

**欧州の発表は日本の深夜から早朝に出ます。** 日本時間の昼にプレミアを探しても、
そこにあるのは前夜の記事の焼き直しです。逆に朝5時半のスキャンでJリーグを探しても、
まだ何も動いていません。

リーグごとに「現地でこの帯に記事が出る」を書いておきます。

```yaml
leagues:
  england:
    utc_offset: 1          # BST（夏時間）
    active_local: "09:00-23:30"
```

日本時間に直したものを `scan` と `today` が使います。

```
　いま動いている（05:30）: エールディヴィジ / ブンデスリーガ / リーグアン / プレミアリーグ ...
　先に当たる: エールディヴィジ / ブンデスリーガ / リーグアン（あと1時間で静かになります）
```

`scan` の試合結果の検索も、**先に閉じるリーグから並べ替えます。**
閉じたあとは翌日まで新しいものが出ないので、順番がそのまま取り逃しになります。

`utc_offset` は**夏時間の値**です。欧州は10月最終日曜に1時間戻るので、
`clocks.summer_until` を過ぎると `doctor` が「offset を1つ減らせ」と言います。
時計のずれは黙って1時間の判断違いになるので、期限を持たせています。

## 網に足すサイトを見つける

検索は網の外のサイトも返します。今までは「網に無い」と言うだけで捨てていましたが、
**何度も出てくるサイトは、たいてい足すべきサイト**です。
`collect` が自動で控えます（`research/newsites.yaml`）。

```bash
python -m src.cli sources --new
```

```
■ 網に足す候補　控え2件のうち1件

  thesun.co.uk　2日 / のべ2回
    https://www.thesun.co.uk/sport/1
    https://www.thesun.co.uk/sport/9
```

数えるのは**別々の日に出てきた回数**です。1日のうちに同じサイトが5回出るのは
「その日そのサイトが当たっただけ」で、網に足す理由になりません。
2日以上に分かれて出てきたものだけを挙げます。

足すかどうかは人が決めます。**そのサイトが信用できるかは機械には分かりません。**
足すときは `domains` に書いたうえで、`domain_tiers` でその群に置ける確度の上限も
決めてください。開かないサイトは `blocked` に入れると、以後は控えません。

## 候補ファイルの書き間違いを落とす

候補ファイルは手で書きます。`legue: england` と綴っても、`tier: 確報` と書いても、
今までは黙って通っていました。**綴りを外した項目は既定値に落ちるだけ**なので、
「なぜかリーグの検索が出ない」「なぜか点が付かない」として後から効いてきます。

```bash
python -m src.cli lint research/20260831_candidates.yaml
```

```
■ 候補ファイルの点検　2026年8月31日　3件
  × a　league『englnad』は定義にありません（england / spain / germany / ...）
  × a　出典で置けるのは『未確認』までです（tier: 確定）
  × b　取得できないサイトが出典に入っています: www.bbc.com
  ・ b　league が空です（辞書からの当たり: germany）
```

3段階です。

| | 意味 |
|---|---|
| × | 直すまで `pick` に進めない（綴り違い・確度の踏み越え・塞がれたサイト） |
| ! | 見たほうがよい（網に無いサイト、同じURLの候補が2件） |
| ・ | 埋められる（`topic` `league` `en` の空欄。クラブ名の辞書から当たりを出す） |

`pick` は最初にこれを回します。× があれば深掘りの検索を出す前に止まります。
**間違ったまま深掘りに入ると、外した検索を10本打ってから気づくことになる**ためです。

いちばん効くのは確度の踏み越えの検出です。噂まとめだけを根拠に `tier: 確定` と
書くのが、いちばん起きやすい間違いなので、`domain_tiers` の上限と突き合わせます。

## クラブ名のゆれを吸収する

見出しは "Spurs" と書いたり "Tottenham" と書いたり「トッテナム」と書いたりします。
同じクラブだと分かっていないと、

- ビッグクラブの加点が効かない（`scoring.big_clubs` は日本語表記しか並んでいない）
- 別のクラブの話が同じ話としてまとまる（「アーセナルがDFで合意」と
  「マンUがDFで合意」は、合意・DF が共通しているだけの別件です）
- `league` を毎回手で埋めることになる

を取りこぼします。`config/clubs.yaml` に別名を書いておきます。

```yaml
clubs:
  - {canonical: トッテナム, league: england, big: true,
     aka: [Tottenham Hotspur, Tottenham, Spurs, THFC, トッテナム・ホットスパー]}
```

```bash
python -m src.cli clubs "Spurs hijack Man City move"   # 何が読み取れるか
python -m src.cli clubs                                # 一覧
```

効くところは3つです。

| | 前 | 後 |
|---|---|---|
| 採点 | `Spurs agree deal` は加点なし | ビッグクラブとして加点 |
| まとめ | 別クラブの話が混ざる／`Man Utd` と `Manchester United` が別件 | クラブが違えばまとめない、同じなら条件をゆるめる |
| 候補ファイル | `topic` `league` が空 | 辞書から当たりを入れる（違えば直す） |

**短すぎる別名は書かないでください。** `Madrid` はレアルにもアトレティコにも、
`Milan` は Inter Milan にも、`AFC` は AFC Bournemouth にも当たります。
照合は長い別名から順に行い、当たった箇所を伏せ字にしてから次を探すので、
`Inter Milan` が インテル と ミラン の2件になることはありません。
英字の別名は語の切れ目でだけ当てます（`Roma` が記者名の `Romano` に当たらないように）。

移籍は2クラブにまたがります。**リーグが1つに定まらないときは空のままにします。**
どちらのリーグの話として出すかは書き手が決めることなので、機械では決めません。

## 移籍期限日に備える

移籍期限日は1日で決着がつきます。**前日に気づいても間に合いません。**
`config/sources.yaml` の `calendar` に期限を書いておくと、
`today` と `scan` が毎回それを言います。

```yaml
calendar:
  notice_days: 5     # 何日前から告知するか
  after_hours: 36    # 期限が過ぎてから何時間「総括を出せ」と言い続けるか
  deadlines:
    - {league: england, at: "2026-09-02 07:00", local: "現地 9/1 23:00 BST", confirmed: true}
```

時刻はすべて**日本時間**で書きます。現地の23時は日本の翌朝7時で、
「今日中かどうか」を毎回換算していると間違えるためです。

```
■ 2026年9月1日 の進み具合
  ⚠ 移籍期限まで残り23時間　ブンデスリーガ（9月2日 05:00 JST／現地 9/1 22:00 CEST）
  移籍期限まであと1日　プレミアリーグ / ラ・リーガ / セリエA（9月2日 07:00 JST）
```

- 同じ時刻に閉まるリーグは1行にまとめます。5行並べると、どれが今日か読めません
- 現地時刻は、まとめた行の全員が同じときだけ添えます（英国の23時をラ・リーガの
  現地時刻として見せないため）
- 残り24時間を切ったら「日」ではなく「時間」で言います
- `confirmed: false` のものは「※日付は未確認」と付きます。**こちらで日付を
  確かめられていない期限を、確かめたように見せません。** `doctor` が数えます

当日と締切直後は、`scan` が特別編ぶんの検索も並べ、`today` が

```
今日は移籍期限日。3本の枠とは別に特別編を出す:
  python -m src.cli plan --routine deadline_day --write
```

を足します。`deadline_day` の節は「何が決まったか（確定）／壊れた話（報道）／
数字で見ると（確定）／世の中はどう見ているか（未確認）／これからどうなる（報道）」。
**期限を過ぎた案件は成立か不成立のどちらかしかありません。**
曖昧なまま並べる日ではないので、確定は公式発表まで辿ります。

## 計画を育てる

やってみて分かったことは `config/sources.yaml` に戻す。

- 使えた検索の型 → `queries` に足す
- 引っかかった落とし穴 → `check` に書く（取材リストに毎回出る）
- 追う選手が変わった → `topics` を入れ替える
- 伸びた動画・伸びなかった動画 → `scoring.weights` を調整する
- 新しくビッグクラブ扱いにしたいクラブ → `scoring.big_clubs` に足す

回していくと、回を重ねるほど取材が速く・正確になる。
とくに `weights` は、実際の再生数を見て動かすところ。
最初の配点はあくまで初期値で、当てるつもりの数字ではない。

## 収集の仕組みが効いているかを見る

```bash
python -m src.cli doctor
```

網も記録も、放っておくと効かなくなります。**塞がれるサイトがあり、返らなくなる
検索があり、扱わないままのリーグが増えます。** 別々のコマンドで見ていると
どれかを見忘れるので、まとめて点検します。

```
■ 収集の健康診断
  ✓ 情報源の網　62サイト。最終確認から0日
  ✓ 索引の記録　6行。ペースが出せるサイト 2件
  ✓ 検索の実績　まだ記録がありません（collect --from で貯まります）
  ✓ 記者の答え合わせ　まだ控えがありません
  × RSSフィード　8本のうち8本が未確認。運用PCで `fetch --check` を回してください
  × 日程　間近の移籍期限4件の日付が未確認: ブンデスリーガ / リーグアン / ラ・リーガ / セリエA
  ✓ 扱った話題　2本
  × 追えていないリーグ　6つ: ラ・リーガ / ブンデスリーガ / セリエA / リーグアン
```

見るのは7つです。

| | 効かなくなる理由 |
|---|---|
| 情報源の網 | 90日を過ぎると、塞がれたサイトも開いたサイトもある |
| 索引の記録 | 3日回していなければ、鮮度の判定ができない |
| 検索の実績 | 何度回しても1件も返さない検索が混ざる |
| 記者の答え合わせ | 的中が半分を切っている記者を出典に使い続けている |
| RSSフィード | URLが死ぬ。未確認のまま置くと、取れているつもりで空になる |
| 日程 | 間近の移籍期限の日付を確かめていないと、告知そのものが嘘になる |
| 追えていないリーグ | ずっと扱っていないリーグは、扱っていないのと同じ |

× が1つでもあると終了コードが1になります。
