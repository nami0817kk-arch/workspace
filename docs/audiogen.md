# audiogen 設計メモ

BGM と効果音をその場で合成するツールキット (`src/audiogen/`) の設計記録。

## 方針

**手続き的合成(procedural synthesis)を選び、生成 AI モデルは使わない。**

BGM / SFX を「生成する」手段は大きく2つある。

| 方式 | 長所 | 短所 |
|---|---|---|
| 生成 AI モデル (text-to-audio) | 表現の幅が広い、指示が自然言語 | API キー/課金/ネットワークが必要、生成が遅い、同じ結果を再現しにくい、ライセンス確認が要る |
| 手続き的合成(採用) | 依存ゼロ・即座に生成・完全に再現可能・パラメータで細かく制御 | 音色は合成音に限られる、生楽器やボーカルは作れない |

ラボでの試作・ゲームのプロトタイプ用途では「すぐ動く」「同じ設定なら同じ音が出る」ことの
価値が大きいため、後者を採用した。将来 text-to-audio を試す場合も、
`sfx.generate()` / `bgm.generate()` と同じ形の関数を別バックエンドとして足せばよい。

依存ライブラリは**ゼロ**。numpy も使わず、`math` / `random` / `wave` だけで完結させている。
音声は「-1.0〜1.0 の float を並べた `list`」で扱う。

## レイヤ構成

下から積み上げる形になっていて、上のレイヤは下のレイヤだけに依存する。

```
core        バッファ操作・ミックス・正規化・WAV 書き出し
  ├ oscillators   波形生成(位相積算式 + PolyBLEP による帯域制限)
  ├ envelope      ADSR / 指数減衰
  ├ effects       フィルタ・ディレイ・リバーブ・歪み・リミッター・サイドチェイン
  └ notes         音名・音階・和音・コード進行
       ├ instruments  波形を重ねた音色
       ├ drums        ドラム音源 + 16分グリッドのパターン
       ├ sfx          効果音プリセットとバリエーション生成
       └ bgm          作曲(compose)と合成(render_tracks / generate)
            ├ manifest  JSON からの一括生成と差分ビルド
            ├ preview   試聴ページの生成
            └ cli       コマンドライン
```

## 実装上のポイント

### 位相積算式のオシレータ

`oscillators.render()` は周波数を毎サンプル位相に足し込む。おかげで周波数に
`f(t) -> Hz` の関数を渡せる。レーザー音の急降下も、ジャンプ音の上昇も、
ビブラートも、すべて同じ仕組みで書ける。周波数を切り替えても波形が途切れない。

周波数が一定の場合は、波形ごとの専用ループに分岐して1サンプルあたりの
関数呼び出しを省いている。

### 段差の帯域制限(PolyBLEP)

ノコギリ波や矩形波の「段差」はナイキスト周波数を超える倍音を含み、そのまま鳴らすと
折り返して倍音列にない周波数に乗る。高い音ほど金属的に濁る原因になる。
段差の前後2サンプルだけを多項式でつなぐ PolyBLEP で抑えた。

固定周波数では素の波形を作ってから段差の位置だけを補正するため、
1サンプルごとに判定する必要がなく、生成時間はほぼ変わらない。

3000Hz を 8000Hz で生成し、3倍音が折り返す 1000Hz の成分を測った結果:

| 波形 | 対策前 | 対策後 |
|---|---|---|
| saw | 0.135 | 0.001 |
| square | 0.271 | 0.002 |
| pulse25 | 0.128 | 0.001 |

基音の大きさは変わらない。

### 直流成分(DC オフセット)を出さない

デューティ比を変えた矩形波は、素朴に ±1 で作ると平均値がゼロにならない。
duty=0.125 なら DC は -0.75 にもなり、ヘッドルームを食いつぶすうえ再生時に
プチッというノイズの原因になる。`square_shape()` は上下の振幅を面積が
釣り合うように取り、duty=0.5 では通常の矩形波と一致させている。
仕上げでは `core.remove_dc()` を通して残りの偏りも取り除く。

初期実装では実測で最大 -0.22 の DC が乗っていたが、対策後は 0.0006 以下。

### 継ぎ目のないループ

BGM はリバーブ/ディレイの残響が小節の終わりを越える。単純に切ると
ループ時に不自然に途切れるので、`core.wrap_tail()` ではみ出した残響を
先頭に折り返して加算している。出力長はちょうど「小節数 × 1小節」になるため、
そのまま繰り返し再生してよい。実測の継ぎ目の段差は最大 0.017。

### 再現性

`seed` を渡すと、メロディの生成もノイズ系の音色も完全に決定的になる。
気に入った素材の設定を控えておけば、いつでも同じ WAV を作り直せる。

## 作曲と合成の分離

「どの音をいつ鳴らすか」と「その音をどう合成するか」を分けてある。

- `compose(config)` が `Note` / `Hit` の並び(譜面)を返す。音の合成は一切しない
- `render_tracks()` はその譜面を音にするだけ
- `describe(config)` が区間・コード・メロディを JSON 化できる形で返す

音を作らずに中身を確認できるので、テストも「音がどう動いたか」ではなく
「音符がどう置かれたか」で書ける。CLI の `describe` サブコマンドはこれをそのまま使っている。

## メロディ生成のしかた

最初に1小節ぶんの短いフレーズ(モチーフ)を作り、以降はそれを展開する。

1. 音階上の「度数」の整数空間でランダムウォークし、モチーフと対の句を作る
2. 4小節ひとまとまりで `A / A / B / A'` と並べる(`B` は対の句、`A'` は末尾の音だけ変えた形)
3. 各小節で、フレーズ先頭の音がその小節の和音の構成音に乗る位置へまとめて移動させる
4. モチーフは曲全体で共有するので、A メロとサビが同じ素材でつながる

当初は毎小節ランダムに歩かせるだけだった。音は外れないものの、同じ形が二度と
返ってこず旋律として頭に残らなかった。モチーフの展開に変えたことで、
「聞き覚えのある形が返ってくる」音楽的なまとまりが出た。

## グルーヴ

音がすべて16分グリッドの上に等音量で並ぶと、正確ではあるが打ち込みらしさが強い。

- **スウィング**: 裏の8分音符だけを後ろへずらす(0.67 で三連符のシャッフル)
- **アクセント**: 小節頭 > 2拍目 > 裏拍 の順に音量を付ける
- **ヒューマナイズ**: タイミングと音量をごくわずかに揺らす

乱数はメロディ生成とは別系列にしてあるので、ゆらぎを変えても曲そのものは変わらない。
チップチューンだけは機械的に正確なままにしてある(そのほうが らしいため)。

## 音色

各パートが単一波形をそのまま鳴らしていたころは、正確だが痩せた音だった。
複数の波形を重ね、フィルタとエンベロープを通したものを「楽器」として定義している。

440Hz を 0.5 秒鳴らしたときの実効値がそろうよう楽器ごとに音量補正を持たせたので、
音色を差し替えても全体のバランスが崩れない。

ビブラートは1サンプルごとに周波数を変えると固定周波数用の高速経路が使えず
数倍遅くなるため、5ms ごとに周波数を更新して位相をつなぐ形にした。
毎秒5回程度の揺れには十分追随できる。

## 放送向けの曲想を足すときに必要だったもの

ゲーム向けの曲想だけでは報道・スポーツ番組の音にならなかった。
足りなかったのは音色ではなく、鳴らし方の型のほうだった。

- **和音を刻めること** — 和音は1小節伸ばすだけだった。報道やスポーツの曲は
  金管が刻んで前へ出る音楽なので、16分グリッドで和音を打てるようにした
  (`chord_pattern`)。空なら従来どおり伸ばす
- **アルペジオのパート** — 伸ばした和音の上を細かい音が走ると、報道番組の
  テーマらしい前進感が出る。和音の構成音を順に鳴らすパートを追加した
- **パートを持たない曲想** — `news_bed` は話し声とぶつからないようメロディを
  外す必要がある。どのパートを鳴らすかをスタイル側が決められるようにした
- **打楽器の語彙** — ティンパニ・タム・クラッシュ・ライドを足した。
  ティンパニとシンバルは余韻が持ち味なので、他の打楽器より長く鳴らしてよい
- **金管の音色** — 吹き始めに音が開いていく立ち上がりが要る。フィルタの
  スイープを「暗い方から明るい方へ」も指定できるようにして再現した

## 編曲の仕上げ

音色と曲想がそろっても、まだ「打ち込みらしさ」が残っていた。原因は音そのものより、
人が編曲するときに当たり前にやっていることを飛ばしていた点にあった。

### 声部連結

和音が変わるたびに全部の音を基本形(根音から積んだ形)へ飛ばしていたため、
いちばん上の声部が大きく跳ね回っていた。構成音は変えずにオクターブだけ選び直し、
前の和音から動きが最小になる組み合わせを選ぶようにした。

C メジャーの I-IV-V-I で測った、声部の総移動量:

| | 基本形 | 声部連結 |
|---|---|---|
| C-F-G-C | 42 半音 | 12 半音 |
| ドリアン i-vii-i-iv | 78 半音 | 30 半音 |

候補は各音を1オクターブ上下させた組み合わせ全部(三和音なら27通り)なので、
総当たりで最小を選べる。連結を優先しすぎて音域が上下へ流れないよう、
和音の中心が元の位置から7半音以上離れる候補は捨てている。

チップチューンだけは基本形で並ぶのが持ち味なので、この処理を切ってある。

### フィル

同じ手が最後まで続くと、区間が変わったことが伝わらない。区間の最後の小節だけ
ドラムのパターンを差し替えるようにした(小太鼓の詰め、タム落とし、
ティンパニの連打、一拍で止める形の4種)。1小節しかない曲では崩しに聞こえないので、
2小節以上あるときだけ適用する。

### 終止

刻みを続けたまま切ると「途中で止まった」ように聞こえる。`--ending` を付けると、
最後の小節を主和音へ帰し、和音を1小節伸ばし、メロディとリズムを止めて
シンバルとバスドラムで締める。残響も折り返さずそのまま鳴らしきる。

### 転調

サビで曲全体を半音〜全音持ち上げるのは、放送用の音楽で定番の盛り上げ方。
区間ごとの移調量を持たせ、和音・アルペジオ・ベース・メロディの根音すべてに
同じ量を足す。度数で組み立てているので、進行の形はそのままキーだけが動く。

`lift`(A メロ → サビ)と `broadcast`(イントロ → A メロ → サビ → 締め)の
2構成で、サビから最後まで全音上がったままにしてある。

### リタルダンド

一定のテンポのまま最後の和音に飛び込むと、演奏が途中で止まったように聞こえる。
終わりにかけてテンポを緩めると「締めた」感じになる。

音符は等速で組み立てておき、あとから時間軸を伸ばす形にした。テンポ倍率が
``speed(s)`` のとき実際の時刻は ``∫ds/speed(s)`` で、直線的に緩める場合は
対数の閉じた形になる。音の長さも同じ物差しで伸ばすので、緩めた区間では
音符自体も長くなる。

緩めた曲はループできないので、残響は折り返さずそのまま鳴らしきる。

### 経過音

ベースが根音と5度を往復するだけだと、和音が変わる瞬間が唐突になる。
小節の最後の音で次の和音の根音のひとつ下へ寄せると、次の頭が「着地」に聞こえる。

## マスター段

ピークだけを見て正規化すると、まばらに飛び出す音に引きずられて曲全体が小さくなる。

- **limiter**: しきい値を超えたぶんだけ滑らかに抑え、山を削ってから正規化する
- **soft_clip**: 天井付近だけ丸める。前段が取りこぼす立ち上がりの一瞬をここで受ける
- **サイドチェイン**: バスドラムの頭でドラム以外を 22% 下げ、低音の場所を空ける

同じピーク(0.86)での実効値の変化:

| スタイル | 変化 |
|---|---|
| battle | +3.77dB |
| adventure / chiptune | +3.20dB |
| menu | +3.13dB |
| tension | +2.87dB |
| calm | +2.02dB |
| night | +0.92dB |

## 帯域バランスについて測ったこと

仕上げにマスター EQ(30Hz 以下の削り、200〜450Hz を -2.5dB、2.5kHz 以上を +4dB)を
入れた。ただし効果の大きさは正直に書いておく。

- 3k〜8k と低域の差は **-21.9dB → -19.3dB**(+2.6dB)
- 同じピークでの実効値は **-0.04〜-0.39dB**(わずかに小さくなる)

つまり「音圧が上がる」類の改善ではなく、帯域の傾きが少し変わるだけ。
入れた当初は「高域が -26dB は問題」と考えたが、基準を確かめると
この種の音楽では珍しい値ではなかった。低い方に energy が偏るのは
音源の音域配置(ベース・和音・打楽器が下に集まる)から来るもので、
EQ で作れる差ではない。

楽器側も測った。ハン窓つき FFT でスペクトル重心を出すと、`brass` は
基音の 2.2 倍で素のノコギリ波(2.3 倍)とほぼ同じ。フィルタで
締めすぎてはいなかったので、音源側は触っていない。

窓関数なしで測ったときは純サイン波の重心が 1929Hz と出た。
リークで高域が持ち上がるためで、この値を根拠に音作りを変えなくて正解だった。

## リバーブの反射密度

コムフィルタ4本 + オールパス2段では反射が薄く、尾に同じ間隔の繰り返しが
立っていた。これが金属的な響きの正体になる。

指標を3つ測って比べた。

| | 現状 4コム+2AP | 6コム+4AP | 8コム+4AP |
|---|---|---|---|
| 反射密度(高いほど良い) | 0.194 | **0.305** | 0.290 |
| 尾の周期性(低いほど良い) | 0.246 | **0.187** | 0.209 |
| 0.5秒ぶんの計算 | 0.011s | 0.016s | 0.019s |

6本が両方で最良で、8本にすると**むしろ悪化する**。本数ではなく遅延長の
散らし方が効いている。

なお「遅延長を互いに素にする」と書きかけたが、実際に確かめると Freeverb の
系列は最大 36 の公約数を持っていた(1116 と 1188)。効いているのは公約数の
有無ではなく、一方が他方の2倍・3倍にならないこと。この系列の比はどれも
1.05〜1.34 に収まっている。

スペクトル平坦度も測ったが、6本にすると 0.151 → 0.127 とわずかに下がった。
2048点の窓ではコムの共振の間隔を分解しきれておらず、金属感の判断には
使えなかった。自己相関のピーク(周期性)のほうが、聞こえ方に対応している。

計算量は 45% 増える。リバーブは生成時間の最大の項なので安くはないが、
音の素性が変わるので受け入れた。

## ステレオ

当初は左右のチャンネルにまったく同じマスター処理を2回かけていた。残響まで
同一だったので、L/R の相関は 0.98 — 耳には1点から鳴っているのと変わらなかった。

- 残響は左右をまとめた信号を1つの部屋へ送り、返りだけ遅延時間を 2.1% ずらす。
  反射の並びが食い違って空間として広がる
- リミッターは大きいほうのチャンネルからゲインを1つ決めて両方に掛ける。
  別々に抑えると、片方だけ小さくなった瞬間に音像が横へ動く
- 位相をいじる widening は使わない。モノラルにまとめたとき打ち消しが出る
- 低音とドラムは中央のまま。上物だけ左右に振って場所を空ける

  L/R 相関   sports_anthem 0.983 -> 0.956 / night 0.990 -> 0.834

**「モノラルにまとめたときの音量差は ±0.4dB 以内」と書いていたのは誤り。**
2曲だけを見て書いていた。全11曲想で測り直すと最大 1.65dB(sports_anthem)
あった。ただし原因はステレオ化ではない。

  ラウドネス目標(-15 LUFS)に届いている曲   差 0.00〜0.34dB
  ピーク天井で頭打ちになっている曲          差 0.58〜1.65dB

天井に当たっている曲は、正規化がラウドネスではなくピークで決まる。
パンを振るとピークの立つ位置が変わるので、モノラル版とステレオ版で
頭打ちになる量が違ってくる。ステレオ化の前後で測っても同じ数字なので、
以前からあった性質を見落としていただけだった。

## MIDI 書き出し

`compose()` が「どの音をいつ鳴らすか」を持っているので、そのまま標準 MIDI
ファイルにできる。合成音では物足りないとき、同じ曲を DAW の音源で鳴らしたり
人の手で編集したりできる。

パートごとに1トラック、ドラムは GM の打楽器チャンネル(10ch)。音色は
楽器名から GM の音色番号へ寄せてある(brass → French Horn、pluck → 
Acoustic Guitar など)。GM に大太鼓がないのでティンパニは Low Floor Tom で代用。

テンポの上書きは受け付けない。音符の時刻は秒で持っているため、譜面と違う
テンポを宣言すると小節線とずれる。テンポを変えたいときは `--bpm` で
作曲からやり直す。

テストでは書き出したバイト列を自前で解析し直して、音符の数と高さが譜面と
一致すること、ノートオン/オフが釣り合うこと、小節線がテンポどおりの位置に
来ることを確かめている。

## サッカーの音楽から取ってきたもの

実際に使われている曲を聴き直して、共通してやっていることを4つに絞り、
機構として入れた。実在の旋律を写したものは1つもない。写しても使えないし、
真似したいのは旋律そのものではなく「なぜそう作られているか」のほうだった。

### 1. メジャーのまま ♭VII を借りる

中継やハイライトの曲がほぼ必ず通る和音。C メジャーで音階どおりに VII を
積むと B・D・F の減三和音になり、緊張して主和音へ帰りたがる。半音下げて
B♭・D・F にすると長三和音になり、緊張しないまま外へ広がる。
明るいのに解決を急がない、あの感じはこれ。

ローマ数字の頭に `b` / `#` を書けるようにした(`I-bVII-IV-I`)。
`parse_progression` は度数に半音移動を持たせた `Degree` を返す。
``int`` を継承しているので、度数として使っている既存のコードはそのまま動く。

メロディ側にも手当てがいった。♭VII の小節で音階どおり B を弾くと、和音の
根音 B♭ と半音でぶつかる。「和音が下げた度数は旋律も下げる」という規則を
入れてある(実質、その小節だけミクソリディアンになる)。

    ♭VII の小節のメロディ 508音中、構成音の半音上を弾くもの  2 -> 0

はじめ「根音と半音差」で数えて 9.4% という数字を出したが、これは誤り。
半音**下**は導音であって普通に使う音で、C メジャーの A は B♭ の長7度、
ぶつかる音ではない。耳に痛いのは構成音の半音**上**のほうなので、
そちらだけを、しかも近い音域にあるときだけ数え直した。

### 2. チャント型の旋律

客席の歌は、旋律としての出来ではなく「訓練していない大群が歌えるか」で
形が決まっている。実際に歌われているものに共通するのは4点だった。

1. 音域が狭い(5〜6度)。上も下も外さずに出せる範囲
2. 同じ音の連打が多い。次に何を歌うか迷わない
3. 音は拍の頭に来る。シンコペーションは大勢では揃わない
4. 途中で休まない。息継ぎは句の切れ目だけ

ふつうの旋律生成とは前提が違うので、作り方ごと分けた(`lead_chant`)。
1小節ぶんのモチーフ40通りの実測:

    曲想             音域   同音連打  拍頭   休符
    terrace_chant   2.6度   43.2%   72.9%   0.0%
    adventure       4.2度    4.6%   50.1%  17.0%

もう一つ、チャントは**展開しない**。A/A/B/A' で変えていくのは聴かせる
音楽の作りで、覚えて一緒に歌わせたい曲は同じ句を押し通す。
`lead_development=("A",)` で型ごと差し替えられるようにした。

厚みは和音ではなくオクターブで作る(`lead_double`)。大勢が同じ旋律を歌うと
声域がばらけてオクターブに散る。三度で重ねると合唱団になってしまい、
客席には聞こえない。

### 3. ペダル(動かない低音)

入場曲が長い助走で期待を溜めるときの手。上で和音が動くのに低音が主音に
居座ると、解決していない感じが持続する。`bass_pedal` で、和音に関係なく
ベースを主音に固定する。実測でも `stadium_anthem` のベースは C2 だけになる。

### 4. 減らしてから戻す

全部鳴らし続けるより、いったん打楽器だけにしてから全部戻すほうが大きく
聞こえる。`anthem` 構成は 助走 → 合唱 → 打楽器だけの切れ目 → 転調して総力戦。
既存の区間の仕組み(`drop` と `transpose`)だけで書けたので、新しい機構は
足していない。

リズムは 4つ打ちの足踏みに2・4拍の手拍子(`terrace` パターン)。大勢で
叩けるのは表拍だけなので裏は入れない。裏拍を入れると客席ではなく
バンドの音になる。

### 見つけたが直していないこと

計測中に、`night` のように長い音符しか使わない曲想でメロディが主音の
連打になってしまうのを見つけた。`_next_degree` が強拍でコードトーンへ
寄せるとき、同点の候補を `abs(value)` で選んでいて主音に偏るため。
サッカーの話とは別件で、直すと全曲想の出力が変わるので手を付けていない。

## ループの継ぎ目

残響がループ長を超えたぶんは先頭へ折り返している(`wrap_tail`)。それでも
放送用の煽りループを実測すると、末尾と先頭で 0.028 の段差が残っていた。
繰り返すたびにプチッと鳴る大きさ。

段ごとに追うと、犯人は残響ではなくマスター EQ だった。

    ミックス直後      段差 0.005
    wrap_tail 後      段差 0.003
    EQ 後             段差 0.044   <- ここ
    リミッター後      段差 0.038

フィルタは状態を持つ。素直に通すと先頭は状態ゼロから始まるのに、末尾は
溜まった状態で終わる。ループの継ぎ目でその差がそのまま段差になる。

直し方は単純で、末尾 0.25 秒を前置きしてから通し、その分を捨てる
(`effects.circular`)。両端の状態がそろう。0.25 秒は一番低いカットオフ
30Hz の時定数 5.3ms の 47倍で、状態はほぼ収束している。
2周ぶん通した2周目と一致することをテストで確かめている。

全11曲想 x 種4つ(44曲)をピーク比で集計:

    継ぎ目の段差 / ピーク   中央 0.029 -> 0.009   最大 0.279 -> 0.152
    先頭50msのずれ / ピーク  最大 0.221(これが消える)

44曲のうち15曲は段差だけ見ると悪化した。EQ の立ち上がりが偶然もとの段差を
打ち消していた曲があるため。ただし先頭にフィルタの過渡が乗るのは
どちらにせよ誤りなので、分布が良くなる側を採った。

テストの合否は絶対値では決めない。音量が違えば段差の絶対値も変わるからで、
プチッと聞こえるのは「曲中では起きない大きさの段差」のほう。曲自身の
隣り合うサンプルの差(99パーセンタイル)と比べる。実測で最大 0.44倍、
つまり継ぎ目は曲中の普通の波形の動きより小さい。

生成時間は +1.2%(同一プロセス内で交互に2回ずつ測った)。

締める曲(`--ending`)とテンポを緩める曲は折り返さず鳴らしきるので、
この処理は通さない。

## 効かなかったこと

リミッターに先読みを入れれば、飛び出す一発を先に抑えて曲間の音量が
そろうはず — と考えて試した。ゲイン包絡を 2ms / 5ms ぶん前へずらす。

    news_bed_loop   0ms -17.53 / 2ms -17.53 / 5ms -17.53 LUFS
    sports_anthem   0ms -15.42 / 2ms -15.34 / 5ms -15.24 LUFS

最大 0.18dB。効かない理由を調べたら、`news_bed_loop` のピークは一発の
立ち上がりではなかった。0.1秒ごとのピークを見ると中央値 0.346 に対して
195窓中30窓が 0.6 を超えている。単に振れ幅の大きい曲で、先読みで削る
ような山ではない。原稿読みの下に敷く曲としてはそのほうが良いので、
そのままにした。入れていない。

## 入力の検証

おかしな設定を渡したときの挙動を一通り試したところ、次のように壊れていた。

| 入力 | 以前 | 現在 |
|---|---|---|
| `bpm=0` | `ZeroDivisionError` | `bpm must be between 20 and 400 (指定: 0)` |
| `bpm=-40` | 0サンプルの無音を返す | 同上 |
| `sr=0` | `ZeroDivisionError` | `sample rate must be >= 4000Hz (指定: 0)` |
| `final_tempo=0` | `ZeroDivisionError` | `final_tempo must be between 0.2 and 2.0 (指定: 0.0)` |
| `final_tempo=-1` | `math domain error` | 同上 |
| `key="H"` | `KeyError: 'H'` | `invalid key: 'H' (例: C, F#, Bb, A3)` |
| `parts=("kazoo",)` | 無音のトラック | `unknown parts: kazoo (使えるのは chords, arp, bass, lead, drums)` |
| `sfx.generate(pitch=0)` | 無音を返す | `pitch must be > 0 (指定: 0.0)` |

例外の型ではなく中身が問題だった。`ZeroDivisionError` はどの値が悪いのか
教えてくれないし、無音が返るのは最悪で、書き出した WAV を再生するまで
気づけない。`bgm.validate(config)` を `compose()` の先頭で呼び、値の名前・
許容範囲・渡された値を必ずメッセージに入れている。

小節数の上限は設けていない。`bars=100000` は正しく動くが数十分かかる。
時間がかかること自体は誤りではないので、止めずに通す。

## 検証結果

すべて 32kHz での実測。

- テスト 800 件がパス(`pytest`、1分46秒)
- 効果音 27種: 最大 |DC| 0.00025、最大ピーク 0.920、先頭・末尾の値 0.0000
- 曲想 11種(8小節): 最大 |DC| 0.00099、最大ピーク 0.860、
  ラウドネス -17.72〜-15.00(幅 2.72dB)
- 狙ったキーの音が鳴っているか。曲全体を 16384 点の窓(ハン窓、50%重ね)で
  変換し、60〜4000Hz を12の音名へ畳んで平均した強さを比べる:

    calm       C major   音階内 / 音階外 = 7.6倍
    night      A minor                    10.0倍
    news_open  C dorian                    1.9倍

  news_open が低いのはドラムのノイズが12音すべてに散るため。音程のある
  パートだけを見れば他と変わらない。以前 `bgm_calm` を「11倍」と書いていたが、
  1区間だけを切り出した値だった。曲全体で測ると 7.6倍になる
- 8小節の BGM 1曲の生成に約3秒。11曲想ぶんで 36秒

## 性能の勘どころ

自分で入れた劣化を2回踏んだので先に書いておく。

- ステレオ対応でリミッターを複数チャンネル対応にしたとき、1サンプルごとに
  `max(ジェネレータ)` を呼ぶ形にしてしまった。モノラルでも通る経路なので
  全体が重くなる。チャンネル数で分岐し、2本のときも展開して書き直したら
  同じ結果のまま 3〜4.5倍速くなった
- ベンチの絶対値だけを見て「遅くなった」と判断しかけたが、同時に測った
  未変更のリバーブも 40% 遅くなっていた。実行環境の負荷であって、
  コードの変化ではなかった。比較は同一プロセス内で取り直すこと



純 Python なので、素朴に書くと1サンプルあたりの処理がそのまま効いてくる。
効いた順に:

1. **同じ音の使い回し** — 同じ音程・長さの音は1度だけ作る。和音もベースも
   小節をまたいで繰り返し出てくるので効果が大きい。ドラムの音色を1打ごとに
   作り直していたバグ(dict 内包表記が重複キーでも値を評価する)を直した際は、
   8小節の生成が 3.2s → 2.4s になった
2. **固定係数の巻き上げ** — カットオフが一定のフィルタは係数を1度だけ計算する
3. **ループを C 側に落とす** — スライス代入 + `zip` の内包表記、WAV 書き出しの
   `array('h')` 化。素朴なインデックスループより速い
4. **条件分岐をループの外へ** — リバーブとディレイは遅延線が埋まるまでの区間を
   ループから外した
