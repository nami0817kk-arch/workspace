# 読みの点検（音声を作る前）

2026-10-10 に作った。歴史の地層（rekishi-chiso）の10/12〜13 の4本で、聞いて分かる誤読が約50か所あった
（万石→マンゼキ・織田家→オダカ・小谷の方→ホウ・表→ヒョウ・披露→ツユ・斉→ヒトシ・都へ→ト・お米→オベイ・戦は→タタカワ・死の床→ユカ）。
人が全行のカナを目で追うだけでは漏れたので、機械で拾える所を拾い、残りを人が見る。

- 点検の中身：共有ライブラリ `libs/yomi`（workspace。README に使い方・拾えない型・関門の作り方）
- チャンネルの側：読み替え辞書・チャンネルだけの一覧（yaml）・check・関門・既知の誤読のテスト

## 手順（どのチャンネルでも）

1. **kana を出す**：台本の全行（ショートの頭の問いなど、声で読むもの全部）を、読み替え辞書で置き換えてからエンジンに渡し、
   audio_query のカナを1行ずつ出す（rekishi-chiso は `python -m chiso.cli kana scripts/x.yaml`）
2. **libs/yomi で点検**（rekishi-chiso は `check` の「読み：」に出る）
   - `×` 型に当たって読み違えている所（名字＋家・数字＋石・名前＋の方・表＋の/に/と、チャンネルの型）と、読み替え辞書の巻き込み
     （キーが長い語の一部に当たって読みが変わる。「露: つゆ」が「披露」に）。**全部直す**：読み替え辞書に長い語で足す
   - `!` 辞書（fugashi）との食い違い：1件ずつ kana を聞いて、誤読なら辞書に足す。誤りでなければチャンネルの一覧の `alike` に足す
   - `・` 読みが割れる語の一覧・人名地名：少ない読みの行と、人名・地名の読みを確かめる
   - エンジンが動いていないと型の所は確かめられず止まる。エンジンを起動してから回す
3. **全行を目で突き合わせる**：機械が拾えない型があるので、kana を台本と1行ずつ見比べる
   - 両方の辞書が同じ間違いをした所（UniDic も「織田家＝オダカ」と読む）
   - 数字と数え方（「1尺＝ヒトシャク」）・区切りの崩れ（「勝家」が「〜とか／ついえ」）・ひらがなで渡した語が前とくっつく所
   - 書名・人名・寺の名など、辞書に無い読み（調べて確かめる。確かめられないものは「要確認」と書き残す）
4. **誤読を辞書とテストに足す**
   - 読み替え辞書には**長い語で**足す（1字のキーは他の語を巻き込む。「家: け」は入れない、「織田家: おだけ」のように）。
     ひらがなで渡すと前の語とくっついて区切りが崩れることがある（勝家→カタカナで渡した）。足したら kana で直ったか見る
   - チャンネルのテストに「この文は、置き換えるとこう・エンジンはこう読む」を1件足す（`yomi.Case`。CI は置き換えだけ、
     エンジンのカナは `@pytest.mark.voicevox` で手元だけ。rekishi-chiso は `tests/test_reading.py` の MISREADS）
   - 新しい型・割れる語は、チャンネルの一覧（yaml）に足し、過去の台本に全部流して正しく読めている所を止めないか確かめる
5. **関門の控え**：全行を確かめ、× が0になったら `reading-ok`（台本と読み替え辞書のハッシュを控える）。
   台本の承認（approve）はこの控えが無いか合わないと止まる。読み替え辞書を変えたら全台本の控えが外れる（それでよい）
   - **予約・公開済みの回は直さない・作り直さない**（2026-10-10 ユーザー「過去は修正不要」）。過去の回に流すのは誤検知を調べるためだけ

## 新しいチャンネルに入れるとき

1. `pip install -e ../../libs/yomi`（requirements.txt に `-e ../../libs/yomi`。CI の workflow の `paths:` に `libs/yomi/**` を足す）
2. 読み替え辞書（yaml、`画面の文字: 読む文字`）を1つ持ち、声を作る所で長い語から順に置き換える（`yomi.apply_readings`）
3. チャンネルだけの一覧 `yomi.yaml`（形は `libs/yomi/src/yomi/data/base.yaml`。`ambiguous`・`rules`・`alike`）。
   題材に多い割れる語（歴史なら 斉・都・明）を足す
4. check に `yomi.review(items, readings, kana, yomi.Lexicon.load("yomi.yaml"), strip)` を入れ、`Report.lines()` を並べる。
   kana は `yomi.VoicevoxKana(url, speaker, cache="work/kana_cache.json")`（同じ文は控えから。エンジンの URL は引数）
5. 関門：`reading-ok` で `approvals/<台本>.reading.json` に台本と辞書のハッシュ（改行は LF にそろえる）を書き、
   次の工程の前で確かめる。公開済みの回は対象外。テストで「控えが無い・台本が変わった・辞書が変わった」で止まることを見る
   （写し元：rekishi-chiso の `chiso/cli.py` の `reading_ok_problem`・`cmd_reading_ok`・`cmd_approve`、`tests/test_reading.py`）
6. そのチャンネルの過去の台本に全部流し、`!` の数と中身を見る。誤りでない食い違いは `alike` へ（誤検知が多いと使われない）

## 目安（rekishi-chiso、10-10 に流した数）

今の4本（始皇帝・秀長・お市・秀吉）で「読み：」の `!` は 0・1・1・9件、`×` はお市の『朝倉家記』1件（読みは要確認）。
過去の回を含む14本で `!` は計26件（多くは実際の読み違い：怒り→オコリ・申年→サルネン・瓜→フリ・港町→ミナトチョウ）、
`×` は計8件（全部が実際の読み違い）。readings.yaml を直す前の版で流すと、4本の 万石・織田家・今川家・表・都へ・小谷の方・披露 は全部 × で止まった。
