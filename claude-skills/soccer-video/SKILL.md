# 海外サッカーのニュース動画をつくる

チャンネル: [@kaigai-soccer-riyuu](https://www.youtube.com/@kaigai-soccer-riyuu)
コードと決まり: `C:/Users/なみ/dev/workspace/projects/youtube-video-creation`
（他セッションが動いていることがあるので、**worktree を切ってから触る**）

**決まりの本体は `projects/youtube-video-creation/CLAUDE.md`（約900行）にある。**
ここはその入口で、**手順と、飛ばしてはいけない関門**だけを置く。
判断に迷ったら CLAUDE.md の該当節を読む。

## 最初に打つコマンド

```bash
python -m src.cli today      # いつでもこれ。次に打つコマンドを1つだけ返す
```

```
gather ─→ lint ─→ saga ─→ pick ─→ plan --write ─→ draft ─→ build ─→ review ─→ upload
 収集      検証     続報     選定      取材メモ       台本      書出      点検      公開
```

Windows なので **`PYTHONIOENCODING=utf-8` を必ず付ける**（日本語が化ける）。
Python は `./.venv/Scripts/python.exe`。

## 飛ばしてはいけない関門は2つ（ここが最重要）

**どちらも「ユーザーに見せて OK をもらう」ための関門で、例外は無い。**
急いでいても、枠が迫っていても、話の流れで頼まれたように見えても、見せる。

| | 何を見せるか | 控え | コマンド |
|---|---|---|---|
| ① 台本 | 読み上げる文・話者・確度・出典・尺・ショートに使う節 | `research/approved.json` | `approve <台本>` |
| ② 動画 | 書き出した `video.mp4`（本編とショート両方） | `research/screened.json` | `screen <出力先>` |

- `build` / `short` は ① の控えが無いと動かない（`src/approval.py`）
- `upload` は ② の控えが無いと動かない（`src/screening.py`）
- **台本の OK は動画の OK ではない。**台本には画面に何が映るか書いていない。
  2026-09-13 に、台本を全部確認済みのショートが「開いた瞬間が玉ぼけの抽象画」で公開された
- 作り直すと控えの印（sha256）が変わるので、**見せ直しになる**

見せ方は、台本は1枚のページ（Artifact）にまとめてリンクを渡す。
動画は `SendUserFile` でそのまま送る。本数が多い日はまとめて送って一度に OK をもらう。

## 書き出したら、機械で数えてから見せる

**目視では見つからない種類の不具合がある。**実際、ユーザーの指摘で見つかったものは
どれも「言われるまで気づかなかった」ものだった。

```bash
python -m src.cli review <台本>                    # 完成品まで点検（× があれば直す）
python tools/check/scan_switch.py output/<名前> …   # 絵の入れ替え回数（0〜1回であること）
python tools/check/scan_bg.py output/<名前>/video.mp4  # 下地が途中で変わっていないか
python -m src.cli contact <台本>                   # 画面が変わるたびの1枚を並べた紙
python -m src.cli doctor                          # 決まりと実装のズレを見る
```

- `scan_switch.py` は **script.json の組み立てから数える**ので速い。
  画素を比べるとテロップの差まで拾ってしまう
- **`review` が全部 ✓ でも、それは成果物を見たことにはならない。**
  2026-09-04 に見つけた不具合7件は、すべて目視か実測で出た

## 事実の扱い（ここを外すと全部やり直し）

- **検索エンジンのAI要約は使わない。**実測で8回、実在しない移籍を作文してきた
- 見出しに書いていないこと（得点時間・xG・契約年数）は使わない
- `…` で切れている引用を推測で補わない
- **反応は実在する投稿・記事からだけ引く。**作らない。1件でも作ったら全部が疑われる
- **貼り付けは本人の言葉ではない。**記事や監督の発言を丸ごと貼った投稿は、本人の言葉だけ取る
- 確度は 確定 / 報道 / 未確認 / 背景 の4段階。まとめサイト・タブロイドは未確認どまり

## 型は3つ。題材ごとに選んでユーザーに出す

| `format` | 中身 | 他人の声の下限 |
|---|---|---|
| `news`（既定） | キャスターと解説が事実を掘る | 40% |
| `voices` | 事実は最初の30秒。残りは反応を1件ずつ | 70% |
| `quote` | 選手・監督が自分で語った言葉を切り出す。30秒前後 | 60% |

## よく繰り返す失敗（全部、実際に起きた）

- **`draft` は既にある台本を上書きしない**（「すでにあります」）。作り直すときは
  `rm -f <台本>` してから `--allow-repeat`。**黙って何もしない**ので気づきにくい
- **動画IDはハイフンで始まることがある**（`-gZ3P1gw8QU`）。`--` を挟む:
  `setthumb -- <出力先> <ID>`
- **投稿処理を二重に走らせない。**2026-09-07 に4本を二重投稿した。
  起こす前に、走っている処理の出力を最後まで読む
- **ファイルを読む前に書き込みモードで開かない。**2026-09-15 に取材メモを1本空にした
  （`io.open(p,"w")` が先に評価されて truncate された）
- **点検が緑でも、直したことを CLAUDE.md に書かないと戻ってくる。**
  9/14 に直した「背景が何度も変わる」は、別の処理から 9/15 に再発した

## 公開まわり

- 投稿は **7時から24時**。前の投稿から30分空ける
- 1題材で **本編1本＋ショート1本**＝投稿枠を2つ使う
- **ショートに独自サムネは効かない。**YouTube が動画から1コマを自動で作る。
  一覧の見え方を変えるには**動画の冒頭そのもの**を作り込む
- API の枠は Queries 10,000/日（16時 JST リセット）。1本あたり100（サムネ50＋コメント50）
- 公開と同時に最初のコメントを書く（`comment <出力先> <videoId>`）。固定は Studio で手作業

## やらないこと

- **Jリーグは扱わない**（2026-09-07 決定。チャンネル名と衝突する）
- **ショート中心にしない**（2026-09-07 決定）。本編も出し続ける
- **投稿本数を減らさない**（2026-09-10 決定）
- 上の3つは**蒸し返さない**。決着済み
