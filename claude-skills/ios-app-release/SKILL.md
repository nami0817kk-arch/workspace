## A. ユーザーの作業（1クリック単位で案内する）

### A-1. App ID【実地・公式】
https://developer.apple.com/account/resources/identifiers/list → 「Identifiers」横の **青い ＋** → **App IDs** → Continue →
**App** → Continue → Description、Bundle ID は **Explicit** で `com.namiki.<appName>` → Capabilities は触らない（課金は既定で使える）→ Continue → **Register**

### A-2. プロファイル【実地・公式】
https://developer.apple.com/account/resources/profiles/list → **青い ＋** → Distribution の **App Store Connect** → Continue →
App ID を選ぶ → Continue → 証明書は**サカマネと同じもの（一覧に1つ）** → Continue → 名前 `<App> AppStore` → **Generate** → **Download**（ダウンロードフォルダに入る）

### A-3. App Store Connect にアプリ【実地・公式】
https://appstoreconnect.apple.com/apps → 「アプリ」横の **青い ＋** → **新規App** → iOS、名前、プライマリ言語 **日本語**、
バンドルID（A-1 から数分たたないと出ないことがある）、SKU、**フルアクセス** → 作成

### A-4. 課金アイテム【実地・公式】
アプリ → 左「収益化」→ **App内課金** → **＋** → 種類（非消耗型など）、参照名、**製品ID（コードと1文字も違えない。英数字・ハイフン・ピリオド・下線だけ）** → 作成。次を埋めて保存:
- **価格**: 価格スケジュールの「価格を追加」→ 基準の国（日本）→ 価格 → 次へ → 確定
- **配信状況**: 「配信状況を設定」→ アプリと同じ国 → 完了（公式に必須とは書かれていないが設定しておく）
- **App Store のローカリゼーション**（最低1言語。日英とも入れる）: 表示名は2〜30文字、説明は45文字まで
- **審査に関する情報**（ページのいちばん下）:
  - スクリーンショット（**必須**）: 値段のボタンが写った画面。**掲載画像と同じ寸法の仕様**に合わせる（iPhone 6.9インチなら 1290×2796）。上げた後は差し替えしかできない。生成器で作る
  - 審査メモ（**任意**。4000文字まで）: 英語で「ボタンの場所と、買うと何が変わるか」
- **1024×1024 の画像は「App Store のプロモーション」用**。課金アイテムをストアで宣伝するとき・再獲得オファーを使うときだけ要る（任意）。審査用の欄と取り違えやすい
- 参照名・製品IDは利用者に見えない（英語でよい）。利用者に見えるのは表示名

### A-5. AdMob【実地・公式】
https://apps.admob.com → 左 **アプリ** → **アプリを追加** → iOS →「ストアに掲載されていますか」**いいえ** → 名前 → 追加 →
**広告ユニットを追加**（リワード／インタースティシャル）。作成画面の答え:
- **「別のメディエーション プラットフォーム（AdMob 以外）でのリアルタイム入札に使用」はオフ**（オンにすると AdMob の広告が出ない）
- リワードの報酬: 量 `1`、アイテム名は何でもよい（アプリは見終えたかだけ見る）
- 広告の種類は全部オン、サーバーサイドの検証オフ、フリークエンシー キャップ無効
- eCPM 下限: **Google による最適化 →「すべての価格」**（広告が来ないとヒントが出ない作りなので、出せることを優先）
- 「アプリの設定」でアプリID（`~` 区切り）、各ユニットID（`/` 区切り）を控える。「ブロックのコントロール」で広告の上限を G
- ユーザーが貼ってきた ID は、形（`ca-app-pub-16桁~10桁` / `ca-app-pub-16桁/10桁`）と発行元の16桁がそろっているかを確かめて返す
- 未公開のアプリは広告の配信が絞られる（公開後に H で解く）

### A-6. Secrets【実地】
https://github.com/nami0817kk-arch/workspace/settings/secrets/actions → **New repository secret**。
- 登録後は `gh secret list --repo nami0817kk-arch/workspace | grep <APP>` で名前がそろったか確かめる（中身は見えない）
- **プロファイルの Base64 は Git Bash で作る**: `base64 -w0 "$USERPROFILE/Downloads/<file>.mobileprovision" | gh secret set NAME --repo nami0817kk-arch/workspace`
  - **PowerShell のパイプで渡すと末尾に CRLF が付き、Mac の `base64 -D` で落ちる**（2026-09-28 に1回落ちた）
  - ユーザーが PowerShell にコマンドプロンプト用の書き方を貼って構文エラーになった。こちらで実行するか、クリップボードに入れる
  - Name 欄にクリップボードの長い文字列を貼る事故があった。名前を先に入れてから中身をクリップボードへ

## B. 法務ページと app-ads.txt（私。公開の OK が要る）

- `projects/<app>/legal/{privacy,terms,support}.html`（日英1ページ）、`site/index.html`、`site/app-ads.txt`、**`site/robots.txt`、`site/404.html`**
- **robots.txt と 404.html は必ず実体として置く**。無いと Cloudflare Pages は無いパスにトップページの HTML を返し、`/robots.txt` が「200 で中身が HTML」になる。
  AdMob のクローラは robots.txt を読めず、**app-ads.txt の確認が止まる**（サカマネ・護送ボートの両方で踏んだ。docs/app-pitfalls.md 項目8）。
  robots.txt は `User-agent: *` / `Allow: /` に加え、AdMob のヘルプの指示どおり `User-agent: Google-adstxt` / `Disallow:` を入れる
- 置いたら `curl -s -o /dev/null -w '%{content_type}' https://<host>/robots.txt` が text/plain か、無いパスが 404 かを確かめる（200 だけでは足りない）
- `.github/workflows/<app>-site.yml` で Cloudflare Pages `<app>` プロジェクトへ（goso-boat-site.yml を写す）。最後に curl で開けるか確かめる
- **app-ads.txt はストアの「マーケティング URL」のホスト直下**に置く（`https://<ホスト>/app-ads.txt`）。AdMob はそこを読みに来る【公式】
- privacy には: AdMob が集める情報（IP・端末ID・広告の表示と操作・性能とクラッシュ）、ATT を使わず IDFA を渡さない、
  My Ad Center、13歳未満向けではない、返金で広告が戻る、Google が同等の保護・削除方法。support に「不適切な広告の報告」
- アプリの設定画面からプライバシーポリシーとサポート（広告の報告）を開けること（Apple 5.1.1・2.5.18）

## C. ビルドして TestFlight【実地】

```bash
gh workflow run <app>-ios-release.yml --repo nami0817kk-arch/workspace --ref master -f upload_to_testflight=true
```
- リリースの CI は Secrets の有無・テスト用IDでない・形・発行元の一致・Info.plist の置換・法務ページが開けるかを確かめてから作る
- 成功は `UPLOAD SUCCEEDED with no errors` で確かめる。ビルド番号は `pubspec.yaml` の `+N`（同じ番号は二度上げられない）
- Info.plist に `ITSAppUsesNonExemptEncryption=false` を入れておく（暗号化の質問が毎回出なくなる。入っていないと TestFlight のビルド横に「管理」が出て答えを求められる）【公式】

## F. ユーザーに決めてもらうこと（おすすめ付きで1つずつ）

- **年齢区分**: 質問票に「広告」の項目があり、広告があっても 4+ のままにできる。暴力の描写が無ければ 4+【公式】
- **配信国**: サカマネ・護送ボートは **EU 27か国と中国本土を外した**
  - EU はデジタルサービス法の「トレーダー」だと連絡先（住所など）の公開が要る。**トレーダーでない区分なら EU にも出せる**（その場合、EU の利用者には消費者保護の権利が適用されない旨が表示される）【公式】。外すかは都度ユーザーに確かめる
  - 中国本土はゲームの許可番号が要る
  - 英国・スイス・ノルウェー・アイスランド・リヒテンシュタイン: 護送ボートでは**ユーザーが外した**（2026-09-30「英国はやめた」。UMP の同意画面が要る国。残しても違反ではなく広告が絞られるだけ）。次のアプリでも外すかを確かめる
  - 配信国は公開後に `curl "https://itunes.apple.com/lookup?id=<AppID>&country=<国>"` の resultCount で外から確かめられる
- **ATT** は出さない（サカマネと同じ）
- **App のプライバシーの答え**: 下の G-3。Google の公式の開示と食い違うので、次のアプリでは都度確かめる

## G. App Store Connect を埋めて提出

欄ごとにコードブロックで出す。

1. **App 情報**【実地・公式】
   - 名前・サブタイトル（日本語と、右上の言語から「言語を追加」で英語）、カテゴリ、年齢制限（「広告」は「はい」）
   - **コンテンツ配信権: 「はい、サードパーティ製のコンテンツを含み、必要な権利を保有」**（広告と OFL フォントがあるため）
   - **EULA: 触らない**（初めから Apple の標準が全地域に当たる）。聞かれたら「標準を全地域に適用」
   - **暗号化の書類: 何も出さない**（Info.plist のキーで済んでいる。聞かれたら「なし」）
2. **価格および配信状況**: 無料、配信可否の「編集」で外す国のチェックを外す → 保存
3. **App のプライバシー**【実地・公式】
   - プライバシーポリシー URL（**必須**）。**「ユーザーのプライバシー選択 URL」は任意で空でよい**【公式】
   - データの収集: サカマネ・護送ボートは **「デバイス ID → サードパーティ広告／関連付けなし／追跡なし」の1行** で出した（サカマネは審査を通った）
   - ただし **Google の公式の開示**（developers.google.com/admob/ios/privacy/data-disclosure）は AdMob が集めるものとして
     IP（おおよその位置）・クラッシュ・性能・デバイス ID・広告データ・製品の操作を挙げていて、1行の答えと食い違う。次のアプリではユーザーに確かめる
   - 最後に右上の **公開** → 確認でもう一度 **公開**
4. **iOS App 1.0（バージョンのページ）**【実地・公式】
   - スクショ（iPhone と iPad のタブ、日英）、プロモーションテキスト、概要（説明、4000文字まで、プレーンテキスト）、
     キーワード（100バイトまで）、サポート URL、マーケティング URL（app-ads.txt の置き場所なので空にしない）、ビルド
   - **著作権**（**必須**）: ページ下の欄（枠の名前は「一般情報」と出ていた）。`2026 Tsuruhashi-sha`。**© は自動で付くので入れない**。本名を入れない
   - App Review に関する情報: サインイン不要のチェックを外す、連絡先（電話は `+81` と国番号付き。名前はローマ字が安全）、メモは英文
   - バージョンのリリース: **自動でリリース**（2026-10-01 ユーザー決定。承認後にボタンを押さなくて済む）。**提出ごとに選べる**ので、日付を合わせたい回だけ手動にする
5. **提出**【実地・公式】
   - **最初の課金アイテムは、アプリの新しいバージョンと同じ提出物で出す（種類ごとの1件目は必須）**
   - **課金アイテムはバージョンのページに添付欄が無い**。課金アイテムのページ右上の **審査用に追加** → 提出物の下書き（無ければ新規作成）→ プラットフォーム iOS と版を選ぶ
   - アプリもバージョンのページ右上の **審査用に追加** で同じ下書きへ
   - 画面右下の **「提出物の下書き」** で両方が並んだのを確かめて **審査へ提出**
   - **広告識別子（IDFA）の質問が出たら**: はい →「App内で広告を配信する」だけ（サカマネの記録。**今の公式ヘルプには記載なし**。出たときだけ答える）

### 「このフィールドには1つ以上の無効な文字が含まれています」【実地】

使えない文字の一覧は公式に無い【公式に記載なし】。実際に弾かれたもの:
- **★ でプロモーションテキストが弾かれた**。説明文も弾かれ、■ … ―― • — を外して通した
- 日本語の見出しは【】、英語は [ ]、箇条書きは「・」と「-」、区切りは「：」。絵文字は使わない
- **markdown の `*` を貼り込まない**（2026-10-01、選手キャリアで直した）。弾かれはしないが強調にならず、アスタリスクがそのまま説明文に出る
- どの欄かを聞いてから直す。名前は漢字を弾くことがある（ローマ字）、電話は `+81` の後に数字だけ
- 保存ボタンに赤い「!」が出て赤い欄が見えないときは、言語を英語に切り替えて英語側の欄を見る。保存を押して出る文を読む

## H. 審査のあと

### 審査に通ったら【公式】
- **自動リリースにしてあれば、承認がそのまま公開になる**（2026-10-01 以降の既定）。店頭に出るまで最大24時間
- 手動を選んだ回だけ、状態が「デベロッパによるリリース待ち」（配信準備完了）になる。バージョンのページ右上の **このバージョンをリリース** → ダイアログで **確認**。**押すまで公開されない**
- 公開後の数字は `curl "https://itunes.apple.com/lookup?id=<AppID>&country=jp"` で外から確かめる

### 「Guideline 2.1 - Information Needed - New App Submission」が来たら【実地 2026-09-29】

審査の実績が少ないアカウントに来る**情報の提出依頼**。却下ではない（護送ボートの初回提出の翌日に来た）。求められるもの:
1. **実機の画面録画**（最新の iOS。**アプリの起動から始める**。普段の遊び方と、課金など有料の機能に入る所を写す）
2. アプリの目的と対象、3. 使い方（ログインの要否）、4. 使っている外部サービス、5. 地域による違い、
6. 規制業種・第三者の保護された素材の有無、7. 課金で買えるものと、そこへの行き方
→ **App Store Connect で返信**し、**同じ内容を「App Review に関する情報」のメモ欄にも入れる**（次回以降のため）

対応:
- 録画: iPhone のコントロールセンターの「画面収録」→ ホーム画面から起動 → 面を遊ぶ・クリア・失敗・ヒント・面の一覧・設定（購入を復元・プライバシーポリシー・広告の報告）→ 止める → PC へ送って返信に添付
- **TestFlight で課金を買った端末では購入ボタンが出ない**（入れ直しても自動で広告なしに戻る）。購入済みの状態を写し、返信で「未購入なら ○○ にボタンが出て標準の購入画面が開く」と説明した
- 返信の英文（2〜7 の答え）は、護送ボートのときの会話に全文がある。要点: 目的と対象／ログイン不要の遊び方／外部は AdMob・StoreKit・端末内の通知だけで自前のサーバー無し／地域差なし（日本語か英語、EU と中国本土は配信なし）／規制なし・素材は自前・フォントは OFL／課金は非消耗型1つとその場所／公開前は広告が届かない旨
- 2.1 の情報依頼は返信で審査が再開する（サカマネの記録）。ただし画面に「再提出」が出ていたら押す

### 却下されたら【公式】
1. 届いた文面をユーザーからもらう（アプリの「App Reviewの問題およびメッセージを表示」で見られる）
2. 直す。返信は「App Review に返信」→「返信」だが、**返信だけでは再審査に入らない**
3. 「解決」→ 却下された項目の「編集」→ 直して **審査用に追加** → **App Reviewに再提出** まで押す
   （画面によっては「審査内容を更新」と出ていた。記憶 app-review-resubmit）
4. メタデータだけの却下なら、同じビルドのまま出し直せる

### 公開後の AdMob（これをしないと広告の制限が外れない）【公式】
1. 公開の **24〜48時間後**（長いと1週間）、AdMob の **アプリ** → **すべてのアプリを表示** → ストアの列の **ストアを追加**
   （またはアプリの設定 →「アプリストア」→「ストアを追加」）→ アプリを検索 → **追加** → **続行**
   - **名前で出なくても、ストアの URL（`https://apps.apple.com/jp/app/id<AppID>`）を検索欄に貼ると出る**【公式・実地 2026-10-02】。護送ボートは公開2日目に名前では出ず、URL で出た
2. **アプリを確認（Verify app）**: アプリの設定 →「アプリを確認」→「更新を確認」。app-ads.txt で本人のアプリかを確かめる
   - **「app-ads.txt ファイルが設定されている可能性がありますが、お客様の詳細情報が AdMob アカウントの情報と一致しません」と出たら、まず `/robots.txt` が HTML を返していないかを見る**（2026-10-02 実地。原因はこれだった）。
     私は「*.pages.dev だから pages.dev を読みに行く」と見立てたが**外れ**（サカマネも同じ見立てで外していた）。*.pages.dev でも robots.txt を直せば通る。
     直したあと、AdMob が読み直すまで最大24時間【公式】。翌日に「アップデートを確認」を押し直す
   - 確かめ方: `curl -s https://<ホスト>/app-ads.txt | od -c`（余計な文字が無いか）と、iTunes lookup の `sellerUrl` がそのホストか
   （**2025年1月から新しいアプリは必須**。確認が済むまで広告は十分に出ない）
3. 確認が通ると「アプリの準備状況」の審査が自動で始まる（たいてい2〜3日）。状態は「準備中」→「審査が必要」→「**準備完了**」。準備完了で配信の制限が外れる
4. app-ads.txt は `https://<マーケティング URL のホスト>/app-ads.txt`。サブドメインは1段上まで探しに行く。`www.` と `m.` は探す対象から外れる
