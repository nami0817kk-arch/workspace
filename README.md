# [PJT003] ai-side-business

## 概要

AI で成果物を自動生成して納品する副業のための、**実行エンジン + 経営管理ツール**。

このツールは2層でできている。

| 層 | やること | 主なコマンド |
|---|---|---|
| **自動化エンジン** | 案件を受けて、成果物の生成・検品・納品ファイル出力までを人手なしで実行する | `service` `job` `auto` `cost` |
| **経営レイヤー** | 何を売るか決め、計画し、売上と原価を数字で管理する | `ideas` `research` `plan` `status` `price` |

自動化エンジンが実際の作業をやり、経営レイヤーが「儲かっているか」を見る。
文章の生成は Claude が担当し、**適合スコア・見積もり・原価・粗利率は自前の計算式**で出すので、
「なぜこの順位なのか」「なぜこの金額なのか」「1件あたりいくら残るのか」を数字で説明できる。

### メディア運営の流れ（本命）

```
ジャンル選定      media genre     ← ここで9割決まる
       ↓
収益設計          media plan      目標月収 → 必要PV → 必要記事数を逆算
                  media simulate  月ごとの収益と累積損益（赤字期間を可視化）
       ↓
キーワード設計    media keywords  収益記事と集客記事を設計し、期待収益順に並べる
                  media keywords --import volumes.csv  実際の検索数を取り込む
       ↓
記事生成          media write     AI が執筆 → 検品 → 修正（ステマ規制のPR表記も検査）
       ↓
公開・計測        media publish / media stats   PV・順位・収益を記録
       ↓
改善              media rewrite   直したときに一番増える記事から順に出す
                  media check     実測とモデルのズレを見てパラメータを補正
```

### 受託自動化の流れ（つなぎ）

```
依頼を登録        python main.py job add minutes --input meeting.txt --price 6000
       ↓
  auto を実行     python main.py auto
       ↓
  ① 生成         Claude が成果物を作る
  ② 検品         機械チェック（文字数・必須項目・景表法NG語・AIの前置き残り）
                 ＋ AI検品（依頼を満たしているかを100点満点で採点）
  ③ 修正         80点未満なら指摘を渡して自動で書き直す（既定1回まで）
  ④ 納品         deliverables/ にファイル出力・送付文も生成
  ⑤ 記録         検品を通ったものだけ売上に計上し、API原価を差し引いて粗利を出す
       ↓
  人が見るのは「要確認」になった案件だけ
```

**人手が要るのは、検品を通らなかった案件の確認だけ。**
それ以外は `auto` 一発で納品ファイルまで出る。Windows タスクスケジューラに
`run-auto.ps1` を登録すれば、案件を溜めておくだけで自動処理される。

## できること

### メディア運営（アフィリエイト・広告）

| コマンド | 内容 |
|---|---|
| `media genre` | ジャンル候補を出し、**目標到達までの月数**で比較する |
| `media plan` | 目標月収から必要PV・必要記事数を逆算し、順位・単価別の感度も出す |
| `media simulate` | 月ごとの収益・原価・累積損益。黒字化月と最大赤字額が分かる |
| `media keywords` | 収益記事と集客記事を設計し、**期待月間収益の順**に並べる |
| `media write` | キーワードから記事を生成（内部リンク・広告表記込み） |
| `media publish` / `media stats` | 公開日・PV・順位・収益を記録する |
| `media rewrite` | 直したときに一番増える記事から順に出す |
| `media check` | 実測とモデルのズレを見て、前提の補正を促す |
| `media params` | 収益モデルのパラメータ（CVR・単価・RPM等）を実測に合わせる |

### 受託の自動化

| コマンド | 内容 |
|---|---|
| `service` | 自動化できるサービス（議事録・ブログ・LP・FAQ など9種）の一覧と詳細 |
| `job add` | 依頼を案件として登録する |
| `auto` | 未処理の案件をまとめて生成・検品・納品ファイル出力する |
| `job show` | 納品物と品質スコア・原価・粗利を確認する |
| `job delivered` | 納品完了にして売上を計上する |
| `cost` | API原価と粗利率のレポート（`--estimate` で実行前の概算） |

### 経営レイヤー

| コマンド | 内容 |
|---|---|
| `init` | スキル・稼働時間・目標月収などのプロフィール登録 |
| `ideas` | プロフィールに合う副業アイデアを提案し、適合スコア順に並べる |
| `research` | 選んだアイデアの需要・競合・価格・撤退基準を調査する |
| `plan` | 90日ロードマップを作り、そのままタスクに登録する |
| `task` | タスクの確認・追加・完了 |
| `revenue` | 売上の記録と、実質時給の算出 |
| `status` | 今月の売上・目標達成率・進捗のダッシュボード |
| `price` | 手取りで希望時給が残る見積もり金額を逆算する |
| `proposal` | 応募文・DM・プロフィール文などをそのまま送れる形で作る |
| `review` | 週次レビュー。詰まっている一点を指摘し、来週のタスクを出す |
| `ask` | 現在の数字を踏まえた個別相談 |
| `report` | ここまでの内容を Markdown レポートに出力する |

## 使い方（メディア運営）

### 1. ジャンルを決める

ここで結果の大半が決まる。逆算すると分かるが、**記事数より単価と順位のほうが効く**。

```powershell
python main.py media genre --detail
```

```
  [1] 業務効率化ツール  単価高  競合3/5
      中小企業向け
      収益: 両方  想定 8位 → 必要 289記事 / 4,329PV
      目標到達まで 約41ヶ月
      適性: 生産管理の経験が活きる

  [2] 転職エージェント  単価特に高い  競合5/5  [競合強]
      収益: アフィリ主体  想定 15位 → 必要 889記事 / 2,222PV
      目標到達まで 約116ヶ月
```

単価が高くても競合が強ければ順位が取れず、結果として遠くなる。
その両方を掛け合わせて **到達月数** で並べる。

案件の報酬額は AI に推定させず「低/中/高/特に高い」の段階でしか扱わない。
実額は必ず ASP で確認すること。

### 2. 目標から逆算する

```powershell
python main.py media plan
```

```
  必要な月間PV          19,608 PV
  必要な記事数             654 本

  【順位が変わると必要記事数はこう変わる】
      3位    11.0%          110PV        179本
      8位     3.0%           30PV        654本
     10位     2.2%           22PV        892本

  【案件単価が変わると必要量はこう変わる】
      1,000円      47,619PV      1,588本
     30,000円       2,193PV         74本
  → 単価の高いジャンルを選ぶだけで必要量が桁で変わる。ジャンル選定が最重要
```

計算式はすべて明示してある。

```
月間PV  = 検索ボリューム × 順位別CTR
アフィリ = PV × 遷移率 × CVR × 単価 × 承認率
広告    = PV ÷ 1000 × RPM
```

### 3. 赤字期間を先に見ておく

```powershell
python main.py media simulate --months 24 --per-month 10
```

```
    月    記事数      月間PV         収益       原価         損益          累積
    1      8         0         0円   1,860円    -1,860円     -1,860円
    5     40       600     1,530円   1,860円      -330円     -6,240円
   10     80     1,800     4,590円   1,860円     2,730円      1,290円  ← 累積黒字化

  最大赤字額（一番苦しい時点の累積）: -6,240円
  累積黒字化: 10ヶ月目
```

**最初の数ヶ月は収益ゼロ**が構造上の前提。ここを知らずに始めて、
3ヶ月目に「稼げない」と判断してやめるのが最も多い失敗。

### 4. キーワードを設計する

```powershell
python main.py media keywords --theme "業務効率化ツール" --detail
```

収益記事（購入・申込につながる）と集客記事（人を集めて収益記事へ送る）を
両方設計し、**期待月間収益の順**に並べる。

```
    # 役割   キーワード                意図    難度  収益性     検索数   想定    月収益
    1 収益   在庫管理 ツール おすすめ      購入検討    3    5      500?   8位    112円
    2 集客   在庫管理 エクセル 限界       知りたい    2    3      500?   5位     91円
```

期待収益は「難易度 → 現実的に取れる順位 → 順位別CTR → PV → 収益」の順で計算する。
難易度5のキーワードは15位想定になるので、いくら単価が高くても上位には来ない。

**検索ボリュームは AI に推測させない。** 末尾の `?` は推測値の印。
ラッコキーワードやキーワードプランナーの CSV を取り込むと実データに置き換わる。

```powershell
python main.py media keywords --import volumes.csv
```

### 5. 記事を書く

```powershell
python main.py media write --limit 5           # 未執筆から5本
python main.py media write 1 3 7               # 番号指定
python main.py media write --options "です・ます調。専門用語には注釈"
```

記事タイプ（レビュー / 比較 / 解説 / 手順 / まとめ）ごとに構成が変わり、
収益記事には**ステマ規制の広告表記**が必須項目として検査される。
表記が無ければ検品を通らず、`要確認` として止まる。

集客記事には収益記事への内部リンクが、収益記事には集客記事へのリンクが入る。

### 6. 公開して計測する

```powershell
python main.py media publish 1                              # 公開日を記録
python main.py media stats 1 --pv 420 --rank 9 --revenue 0  # 実績を記録
python main.py media stats                                  # 一覧
```

### 7. どれを直すか決める

```powershell
python main.py media rewrite
```

```
  [1] 在庫管理 エクセル 限界  <収益化>
      現状: 9位 / 420PV / 0円
      3位まで上げられれば 月 +5,783円
      → 読まれているのに稼げていない。導線か案件を見直す
```

記事は PV・順位・収益の組み合わせで4つの状態に分かれ、打ち手が変わる。

| 状態 | 判定 | 打ち手 |
|---|---|---|
| PV高・収益あり | 横展開 | 関連キーワードを増やして面を取る |
| PV高・収益なし | 収益化 | 導線か案件を見直す |
| PV低・順位低 | リライト | 内容を厚くして上位を狙う |
| PV低・順位高 | 統合・撤退 | 検索需要が無いキーワードだった |

優先順位は**「3位まで上げたときに増える見込み額」**で決める。
実PVと順位別CTRから逆算した実質検索数を使うので、実測に基づいた見積もりになる。

### 8. 前提を実測で補正する

```powershell
python main.py media check
```

```
  1PVあたり収益   想定 2.55円  →  実測 0.8円  （想定の 31%）
  平均順位        想定 8位  →  実測 11.5位

  実測が想定を大きく下回っています。パラメータを実測に合わせてください。
    例) python main.py media params --set cvr=0.01
```

最初の想定は業界一般値にすぎない。実測が出たら必ず自分の数字に置き換える。
そうしないと逆算もシミュレーションも意味を持たない。

```powershell
python main.py media params                              # 現在値
python main.py media params --set cvr=0.01 unit_price=10000
```

### 何を自動化できるか見る

```powershell
python main.py service                    # 一覧
python main.py service show minutes       # 詳細（必要な入力・品質基準・検品観点）
```

### 実行前に原価を確認する

```powershell
python main.py cost --estimate
```

```
  サービス                想定原価                想定単価       粗利率      目標必要件数
  議事録作成                25円      3,000〜8,000円     99.2%        17 件/月
  ブログ記事執筆              43円      5,000〜15,000円     99.1%        11 件/月
  LPコピー作成              53円     20,000〜50,000円     99.7%         3 件/月
```

API 利用料は 1 件あたり数十円。**単価の 1% 未満**なので、粗利率は 99% 前後になる。
「目標必要件数」は、プロフィールの目標月収を最低単価で達成するのに要する件数。

### 依頼を登録する

```powershell

python main.py job add minutes --input meeting.txt --client "株式会社A" --price 6000 --title "8月定例"

# 直接指定
python main.py job add blog --text "テーマ: 40代からの副業の始め方 / 読者: 会社員" --price 8000

# 追加の指定を渡す
python main.py job add sns --input theme.txt --options "トーンは丁寧め。絵文字なし" --price 5000
```

### 自動処理する

```powershell
python main.py auto              # 未処理をすべて処理
python main.py auto --limit 3    # 3件だけ
python main.py auto --no-qa      # AI検品を省く（機械チェックのみ・原価を約4割削減）
```

実行するとこう出る。

```
[1] 8月定例  <議事録作成>  株式会社A
  [1/3] 議事録を生成中...
  [2/3] 検品中...（2,140文字）
  [3/3] 指摘 2 件を修正中...（1回目）
  完了: 2,380文字 / 47.2秒 / 原価 31.4円
  売価 6,000円 → 粗利 5,969円（粗利率 99.5%）
```

検品を通らなかった案件は `要確認` として残り、**売上には計上されない**。

```powershell
python main.py job list                # 案件の一覧と粗利率
python main.py job show 1              # 納品物の中身と品質スコア
python main.py job delivered 1         # 納品完了 → ここで売上を計上
```



### 定期実行で完全自動にする

`run-auto.ps1` をタスクスケジューラに登録すると、案件を溜めておくだけで自動処理される。

```powershell
# 毎日 6:00 に実行する（PowerShell を管理者で開いて実行）
$action  = New-ScheduledTaskAction -Execute "powershell.exe" `
           -Argument "-NoProfile -ExecutionPolicy Bypass -File `"$PWD\run-auto.ps1`""
$trigger = New-ScheduledTaskTrigger -Daily -At 6:00
Register-ScheduledTask -TaskName "AI副業-自動処理" -Action $action -Trigger $trigger
```

実行ログは `logs/auto-YYYY-MM-DD.log` に残る。

### 品質はどう担保しているか

自動化の弱点は「誰も見ないまま納品されること」なので、二段で止めている。

| 段 | 内容 | 特徴 |
|---|---|---|
| 機械チェック | 文字数・必須項目の有無・景表法NG語・AIの前置きやプレースホルダの残り | 確実に検出。**AIが何点を付けようとここで引っかかれば不合格** |
| AI検品 | サービスごとの観点で100点満点採点し、指摘を出す | 依頼を満たしているかを見る |

80点未満または「高」深刻度の指摘があれば、指摘を渡して自動で書き直す（既定1回）。
それでも通らなければ `要確認` として人に上げる。**設計上、人が見るのはここだけ。**

以降のすべての提案がこの内容を土台にするので、ここは正直に入れる。

`--detail` を付けるとスコアの内訳まで表示される。

## データの扱い

- プロフィール・タスク・売上・案件は `data/` 配下の JSON に保存される
- **`deliverables/`（納品物）と `logs/` は顧客の情報が入るため `.gitignore` 済み**
- `data/*.json` と `data/reports/` も `.gitignore` 済み（個人情報を push しない）
- API キーは `.env` にのみ置く

### モデルと原価

既定は `claude-opus-5`（入力 $5 / 出力 $25 per 1M トークン）。
費用を抑えたい場合は `.env` の `CLAUDE_MODEL` で変更できる。

```
CLAUDE_MODEL=claude-sonnet-5     # 入力 $2 / 出力 $10 — 原価が約6割になる
```

円換算レートは `.env` の `USD_JPY`（既定 155）で調整する。
同じサービスを連続処理する際はプロンプトキャッシュが効くため、実測原価は概算より下がる。

## 注意

### アフィリエイト・広告収入について

- **収益は保証できない。** シミュレーションは前提を置いた計算にすぎず、
  検索アルゴリズムの変動ひとつで前提は崩れる。**「◯ヶ月で◯円」は約束ではない**
- **AI生成記事がそのまま上位表示される保証はない。** 検索エンジンは独自性と
  一次情報を評価する。実体験・実測データを自分で足すことが前提
- **ステマ規制（2023年10月施行）** により、広告を含む記事には広告である旨の
  表示が義務。本ツールは機械チェックで検査するが、最終的な責任は運営者にある
- **YMYL領域**（医療・健康・金融・法律）は個人サイトの評価が上がりにくく、
  誤った情報は実害を生む。このジャンルは避けるか、専門家の監修を入れる
- ASP の報酬額・提携条件は必ず公式で確認する。本ツールは段階評価しか扱わない

### 共通

- **納品前・公開前に必ず自分で目を通す。** 検品は二段で入れているが、事実関係の正しさまでは保証できない。
  特に固有名詞・数値・日付は原文と突き合わせる
- 顧客から預かった情報を AI に渡すことになるため、**守秘義務契約の内容を事前に確認する**。
  機密性の高い案件は受けない判断も必要
- AI 生成物であることの開示が必要かは、取引先の規約による。事前に確認する
- このツールは意思決定を支援するもので、**収益を保証するものではない**
- 本業の就業規則（副業規定）は事前に確認する
- 年間の副業所得が 20 万円を超える場合は確定申告が必要
