# [PJT004] ai-side-business

## 概要

AI で成果物を自動生成して納品する副業のための、**実行エンジン + 経営管理ツール**。

このツールは2層でできている。

| 層 | やること | 主なコマンド |
|---|---|---|
| **自動化エンジン** | 案件を受けて、成果物の生成・検品・納品ファイル出力までを人手なしで実行する | `service` `job` `auto` `cost` |
| **経営レイヤー** | 何を売るか決め、計画し、売上と原価を数字で管理する | `ideas` `research` `plan` `status` `price` |

自動化エンジンが実際の作業をやり、経営レイヤーが「儲かっているか」を見る。
文章の生成は Claude が担当し、**適合スコア・見積もり・原価・粗利率は自前の計算式**で出すので、
「なぜこの順位なのか」「なぜこの金額なのか」「1件あたりいくら残るのか」を数字で説明できる。

### 複数プロジェクトを回す流れ

```
プロジェクト登録    pjt add "サッカーゲームアプリ" --type app --status 開発中
                    pjt add "株式ランキング" --type media --status 運用
       ↓
見通しを立てる      pjt forecast 1     種別に応じた収益モデルで逆算・シミュレーション
       ↓
実績を記録         pjt record 2 --revenue 4100 --cost 1500 --hours 12
       ↓
横断で比較         pjt                今どれが稼いでいるか
                    pjt allocate       週の時間をどこに割くか
                    pjt review         伸ばす / てこ入れ / 撤退検討
```

判定は記事のリライト判定と同じ考え方で、**実績から状態を分類して打ち手を出す**。

| 判定 | 条件 | 打ち手 |
|---|---|---|
| 伸ばす | 収益あり・直近で+20%以上 | ここに時間を寄せる |
| 維持 | 収益あり・横ばい | 手を入れる余地を探す |
| 様子見 | 公開4ヶ月未満・収益ゼロ | 判断はまだ早い |
| てこ入れ | 公開4〜9ヶ月・収益ゼロ | 原因を特定する |
| 撤退検討 | 公開9ヶ月超・収益ゼロ | 残すか畳むか決める |
| 公開優先 | 開発6ヶ月超で未公開 | まず世に出して反応を見る |

### メディア運営の流れ

```
ジャンル選定      media genre     ← ここで9割決まる
       ↓
収益設計          media plan      目標月収 → 必要PV → 必要記事数を逆算
                  media simulate  月ごとの収益と累積損益（赤字期間を可視化）
       ↓
キーワード設計    media keywords  収益記事と集客記事を設計し、期待収益順に並べる
                  media keywords --import volumes.csv  実際の検索数を取り込む
       ↓
記事生成          media write     AI が執筆 → 検品 → 修正（ステマ規制のPR表記も検査）
       ↓
公開・計測        media publish / media stats   PV・順位・収益を記録
       ↓
改善              media rewrite   直したときに一番増える記事から順に出す
                  media check     実測とモデルのズレを見てパラメータを補正
```

### 受託自動化の流れ（つなぎ）

```
依頼を登録        python main.py job add minutes --input meeting.txt --price 6000
       ↓
  auto を実行     python main.py auto
       ↓
  ① 生成         Claude が成果物を作る
  ② 検品         機械チェック（文字数・必須項目・景表法NG語・AIの前置き残り）
                 ＋ AI検品（依頼を満たしているかを100点満点で採点）
  ③ 修正         80点未満なら指摘を渡して自動で書き直す（既定1回まで）
  ④ 納品         deliverables/ にファイル出力・送付文も生成
  ⑤ 記録         検品を通ったものだけ売上に計上し、API原価を差し引いて粗利を出す
       ↓
  人が見るのは「要確認」になった案件だけ
```

**人手が要るのは、検品を通らなかった案件の確認だけ。**
それ以外は `auto` 一発で納品ファイルまで出る。Windows タスクスケジューラに
`run-auto.ps1` を登録すれば、案件を溜めておくだけで自動処理される。

## できること

### ダッシュボード画面

```powershell
python main.py screen --open
```

`dashboard.html` を生成してブラウザで開く。ライブラリも通信も使わない単一ファイルなので、
**オフラインで開き、収益データが外に出ることはない**。

**収益がまだ無い時期と、出はじめた後で、画面の主役が変わる。**

立ち上げ期に「目標達成率 0%」だけを見せても何の判断材料にもならないため、
収益がゼロのあいだは投資額と回収ラインを主役にする。

| | 投資フェーズ（収益ゼロ） | 成長フェーズ（収益あり） |
|---|---|---|
| 主役の数字 | まだ回収していない額 | 今月の収益 |
| メーター | まず支出と同額を目指す線 | 目標月収の達成率 |
| KPI | 毎月の支出・累計投資額・投資期間 | 累計損益・実績時給・今月の稼働 |
| 専用パネル | 最初の1円までの距離 | — |

共通して載っているもの:

- 月次の収支と累積損益（収益を上・支出を下に出し、累積を線で重ねる）
- プロジェクト一覧（判定バッジ・今月・累計・実績時給・推移スパークライン）
- 経費の内訳（項目別の月額と累計）
- 今週の時間配分の目安
- 期限超過タスク / 改善対象の記事 / 滞留している受託案件

ダークモード対応（OSの設定に追従、右上のボタンで切替）。

## 使い方（ダッシュボード）

### まず課金形態と支出を登録する

**AIの課金が定額（サブスク）か従量（API）かで、原価の考え方が根本から変わる。**

```powershell
python main.py profile --set cost_mode=定額 monthly_fee=3000
python main.py expense add 3000 --item "Claude利用料" --from 2026-05
python main.py expense                                    # 一覧
```

| | 定額（サブスク） | 従量（API） |
|---|---|---|
| 1件あたりの追加費用 | **0円** | トークン数に応じて発生 |
| 作る量を絞る理由 | 費用面には無い | 増やすほど原価が増える |
| 回収すべき額 | 月額のみ | 月々の従量課金の合計 |

既定は定額。`cost`・`media simulate`・ダッシュボードはこの設定に従って計算を変える。
従量課金なら `profile --set cost_mode=従量` としてください。

```powershell
python main.py cost --estimate         # 定額なら「月額を回収するのに何件必要か」
python main.py cost --estimate --api   # 従量だった場合の試算も見られる
```

### 画面を開く

```powershell
python main.py screen --open
```

実行するたびに `dashboard.html` が最新の記録で作り直される。
ブックマークしておけば、ファイルを開くだけで現状が確認できる。

### 画面の設計について

グラフは検証済みのカラーパレットを使っている（色覚特性のある方でも系列を
区別できることを、スクリプトで検証済み）。加えて次を守っている。

- 系列は必ず凡例と併記する。色だけで識別させない
- 判定バッジは色と文字ラベルを必ずセットにする
- 数値はテーブルにも出す（色が見分けにくい環境でも読めるように）
- 目標ラインを引き、実績との距離が一目で分かるようにする


種別に応じて適切な収益モデルに自動で振り分ける。

## 使い方（アプリ収益）

### 構造

```
収益   = DAU × ARPDAU × 30
DAU    = 日次インストール × 継続率の総和
ARPDAU = 広告表示回数 × eCPM ÷ 1000  +  課金率 × ARPPU ÷ 30
```

継続率は D1 / D7 / D30 の実測3点から冪関数で近似する。
ストアの分析画面で取れる数字を入れれば、以降の計算が全部つながる。

```powershell
python main.py app params --set d1=0.42 d30=0.08 ecpm=800 paying_rate=0.02
```

### 逆算

```powershell
python main.py app plan
```

```
  必要なDAU                  383 人
  必要な日次インストール          30 件/日
  （1インストールが平均 12.9 日分の DAU を生むため）

  現在のオーガニック獲得は 5 件/日の想定
  → 25 件/日 足りない
  → 広告で埋めるなら 月 112,500円 の出稿費が必要
  ⚠ LTV 56円 < CPI 150円 なので、広告を打つほど赤字が増える
     先に継続率か ARPDAU を上げること

  【継続率が変わると必要インストール数はこう変わる】
      D1    D30     DAU寄与        必要インストール
     20%     2%      4.7日           83件/日
     35%     6%     12.9日           30件/日  ← 現在
     50%    12%     26.9日           15件/日
     60%    20%     48.6日            8件/日
  → 継続率を上げるほうが、インストールを増やすより効く
```

**LTV < CPI なら広告出稿は赤字**。この判定を必ず先に見ること。
継続率が低いまま広告を打つのが、個人開発で最も金を失うパターン。

```
      目標到達まで 約116ヶ月
```

単価が高くても競合が強ければ順位が取れず、結果として遠くなる。
その両方を掛け合わせて **到達月数** で並べる。

案件の報酬額は AI に推定させず「低/中/高/特に高い」の段階でしか扱わない。
実額は必ず ASP で確認すること。

### 定期実行で完全自動にする

`run-auto.ps1` をタスクスケジューラに登録すると、案件を溜めておくだけで自動処理される。

```powershell
# 毎日 6:00 に実行する（PowerShell を管理者で開いて実行）
$action  = New-ScheduledTaskAction -Execute "powershell.exe" `
           -Argument "-NoProfile -ExecutionPolicy Bypass -File `"$PWD\run-auto.ps1`""
$trigger = New-ScheduledTaskTrigger -Daily -At 6:00
Register-ScheduledTask -TaskName "AI副業-自動処理" -Action $action -Trigger $trigger
```

実行ログは `logs/auto-YYYY-MM-DD.log` に残る。

### 品質はどう担保しているか

自動化の弱点は「誰も見ないまま納品されること」なので、二段で止めている。

| 段 | 内容 | 特徴 |
|---|---|---|
| 機械チェック | 文字数・必須項目の有無・景表法NG語・AIの前置きやプレースホルダの残り | 確実に検出。**AIが何点を付けようとここで引っかかれば不合格** |
| AI検品 | サービスごとの観点で100点満点採点し、指摘を出す | 依頼を満たしているかを見る |

80点未満または「高」深刻度の指摘があれば、指摘を渡して自動で書き直す（既定1回）。
それでも通らなければ `要確認` として人に上げる。**設計上、人が見るのはここだけ。**

## データの扱い

- プロフィール・タスク・売上・案件は `data/` 配下の JSON に保存される
- メディアの固定費（`media params` の `fixed_monthly`）は既定でドメイン・サーバー代
  1,500円/月を仮定している。使っていなければ `media params --set fixed_monthly=0` で外すこと
- **`deliverables/`（納品物）・`articles/`（記事）・`logs/`・`dashboard.html` は
  顧客情報や収益実績が入るため `.gitignore` 済み**
- `data/*.json` と `data/reports/` も `.gitignore` 済み（個人情報を push しない）
- API キーは `.env` にのみ置く

### モデルと原価

**定額（サブスク）で使っている場合、以下のトークン単価は原価に影響しない。**
1件作るごとの追加費用は発生せず、回収すべきは月額のみ。
`profile --set cost_mode=定額 monthly_fee=<月額>` を設定しておくこと。

以下は従量課金（API）の場合の話。既定モデルは `claude-opus-5`
（入力 $5 / 出力 $25 per 1M トークン）。
費用を抑えたい場合は `.env` の `CLAUDE_MODEL` で変更できる。

```
CLAUDE_MODEL=claude-sonnet-5     # 入力 $2 / 出力 $10 — 原価が約6割になる
```

円換算レートは `.env` の `USD_JPY`（既定 155）で調整する。
同じサービスを連続処理する際はプロンプトキャッシュが効くため、実測原価は概算より下がる。

## 注意

### アフィリエイト・広告収入について

- **収益は保証できない。** シミュレーションは前提を置いた計算にすぎず、
  検索アルゴリズムの変動ひとつで前提は崩れる。**「◯ヶ月で◯円」は約束ではない**
- **AI生成記事がそのまま上位表示される保証はない。** 検索エンジンは独自性と
  一次情報を評価する。実体験・実測データを自分で足すことが前提
- **ステマ規制（2023年10月施行）** により、広告を含む記事には広告である旨の
  表示が義務。本ツールは機械チェックで検査するが、最終的な責任は運営者にある
- **YMYL領域**（医療・健康・金融・法律）は個人サイトの評価が上がりにくく、
  誤った情報は実害を生む。このジャンルは避けるか、専門家の監修を入れる
- ASP の報酬額・提携条件は必ず公式で確認する。本ツールは段階評価しか扱わない

### アプリについて

- **個人開発アプリのオーガニック獲得は極めて難しい。** ストア内検索で埋もれるのが通常で、
  `app plan` の「オーガニック 5件/日」という既定値ですら、実際には楽観的な場合がある
- **LTV < CPI の状態で広告を打たない。** 打つほど赤字が増える。`app plan` が警告を出す
- 継続率・eCPM・課金率はジャンルと国で大きく変わる。既定値は目安にすぎないので、
  ストアの実測が出たら必ず置き換える

### 共通

- **納品前・公開前に必ず自分で目を通す。** 検品は二段で入れているが、事実関係の正しさまでは保証できない。
  特に固有名詞・数値・日付は原文と突き合わせる
- 顧客から預かった情報を AI に渡すことになるため、**守秘義務契約の内容を事前に確認する**。
  機密性の高い案件は受けない判断も必要
- AI 生成物であることの開示が必要かは、取引先の規約による。事前に確認する
- このツールは意思決定を支援するもので、**収益を保証するものではない**
- 本業の就業規則（副業規定）は事前に確認する
- 年間の副業所得が 20 万円を超える場合は確定申告が必要
