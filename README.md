# [PJT006] price-tracker — 楽天 値下がりウォッチ

楽天市場の価格を毎日記録し、その履歴から値下がりと最安値圏を機械的に判定して
公開する静的サイト。収益は楽天アフィリエイト。

## 考え方

APIが返すのは「今日の価格」だけで、履歴は返さない。
**毎日それを保存し続けることが、そのまま他にない資産になる**（後から買えない）。
このサイトの価値は文章ではなく蓄積にあるので、記事は書かない。

**実行時に生成AIを使わない。** 理由は2つ。

1. 費用。判定を計算式に限れば、定額のサブスク以外に従量課金が発生しない
2. 品質。実体験のない生成文はどのみち評価されない。事実の提示なら書き手の経験を要さない

判定はすべて `src/analyze.py` の四則演算で、根拠を後から説明できる。

## 構成

| ファイル | 役割 |
|---|---|
| `fetch.py` | 毎日1回、楽天から価格を取得して記録する（Actions から実行） |
| `explore.py` | 対象ジャンルを勘ではなくデータで決めるための調査 |
| `build.py` | 記録済みデータから静的サイトを生成する（**通信しない**） |
| `src/rakuten.py` | API クライアント。1秒1回の制限を守る |
| `src/store.py` | 価格の記録。同日に二度動かしても壊れない |
| `src/analyze.py` | 値下がり・最安値の判定 |
| `src/theme.py` `src/pages.py` `src/style.css` | ページ生成 |
| `data/` | **成果物ではなく資産。** 履歴なのでリポジトリに commit する |

## 必要な設定

GitHub のリポジトリ設定 → Secrets and variables → Actions に登録する。
アプリIDはリクエストURLに乗る準公開の識別子だが、それでもリポジトリには置かない。

| 名前 | 取得先 |
|---|---|
| `RAKUTEN_APP_ID` | 楽天ウェブサービスでアプリを登録して発行 |
| `RAKUTEN_AFFILIATE_ID` | 楽天アフィリエイト（楽天会員なら審査なし） |

`RAKUTEN_AFFILIATE_ID` が未設定でも動くが、リンクが通常URLになり**収益は発生しない**
（`fetch.py` が警告を出す）。

## 手順

```bash
# 1. 対象ジャンルを決める（Actions で mode=explore を手動実行）
#    価格が数千〜数万円、レビュー数が多いジャンルを config.json の genres に書く

# 2. 毎日 06:00 JST に自動で記録される（手動実行も可）

# 3. サイトの生成（記録済みデータのみを使う。ローカルで確認できる）
python build.py
python -m http.server -d dist 8000
```

## 収益の構造

変動費がない（実行時にAIを使わず、GitHub Actions と Pages は無料枠で足りる）ため、
費用は Claude のサブスク 15,000円/月だけの固定費になる。
したがって **利益率は目標に置く数字ではなく、売上で自動的に決まる**。

    利益率 = 1 − 15,000 / 月商

月商15,000円で0%、30,000円で50%、100,000円で85%。目標に置くべきは月商のほう。

報酬規則には設計を左右する上限が2つある（`src/revenue.py`）。

- **1商品1個につき1,000円が上限。** 料率2%なら50,000円を超えた分は報酬にならない
- 同一ユーザーからの月間報酬は3,000円が上限

つまり高額なジャンルほど得ではない。**上限に当たる手前（料率2%なら3〜5万円）が最も効率が良い。**
`explore.py` はこの計算でジャンルを並べる。

なお報酬は楽天キャッシュで支払われる。3か月連続で3,001円以上を得ると銀行振込に切替できる。

## 制約として意識していること

- **「最安値」は当サイトが記録した期間内の最安値**であり、市場全体の最安値ではない。
  全ページのフッターに明示している
- 記録が7日に満たない商品には最安値の判定を行わない（初日は全商品が最安値になるため）
- 今日取得できなかった商品はページに出さない（古い価格を今日の価格として見せないため）
- アフィリエイトリンクには `rel="sponsored nofollow noopener"` を付ける
- 全ページに広告表記を出す（ステマ規制）

これらはテストで担保している（`tests/test_build.py`）。

## テスト

```bash
python -m unittest discover -s tests   # 41件
```

この開発環境からは楽天へ到達できない（ネットワークポリシーで遮断）。
通信部分は Actions 上でのみ動作し、ローカルでは疑似データと `--dry-run` で確認する。
