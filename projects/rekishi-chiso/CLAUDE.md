# 歴史の地層（日本史・世界史を聞き流し）

YouTube チャンネル「歴史の地層｜日本史・世界史を聞き流し」（@rekishi-no-chiso、運営：つるはし社）の動画を作る。
目的は収益化（2027-02 からの新基準＝長尺 8,000 時間を前提に、長尺で視聴時間を積む）。

この文書は3つに分けてある（10-08 に整理）：**1. 決まり（なぜ）**／**2. 台本の書き方（どう）**／**3. 作り方とコマンド**。
書き方の細部は `scripts/_template.yaml`（ひな形）・`scripts/_showcase.yaml`（全部の道具を使った見本）と各モジュールの頭の説明にある。
制作の手順はユーザーレベルのスキル `rekishi-video`（`~/.claude/skills/rekishi-video/SKILL.md`、バックアップは workspace/claude-skills）。

### 2人のキャラと会話の流れ（10-04 にユーザーと決めた。変えるときは聞く）

|  | 剣崎雌雄（語り） | 春日部つむぎ（聞き） |
|---|---|---|
| 役 | 掘る案内人。事実と記録を出す | 視聴者と同じ側。予想し、今に置き換え、言い直す |
| 口調 | 落ち着いた丁寧語 | **中間**：ふだん軽い話し言葉（でしょ？／じゃん／の？）、驚くと素が出る |
| 一人称 | 僕（ほとんど言わない） | あーし（**節に1回くらい**） |
| 呼び方 | つむぎさん | 剣崎さん（公式のあだ名「めすおちゃん」「べっつー」は使わない） |
| 素性 | **語らない**（付喪神・3600歳は出さない） | 公式の「埼玉のギャル」を口調ににじませる程度 |

- **進行役はいつも剣崎**（10-04 に固定）。最初の行と締めの「今日の地層は、ここまでです」は剣崎
- **締め**：剣崎「今日の地層は、ここまでです」→ つむぎが次回の題材を一言 → コメントへの誘い → **二人**「また一緒に、掘りましょう！」
- **つむぎを受け身にしない**（10-04、101行の約半分が驚き・おうむ返し・「……」だった）：驚くだけの返しは1節2回まで、「……」の感想は2回続けない。
  予想して外す・今に置き換える・節の終わりで自分の言葉で言い直す
- **1節の流れ**：年と出来事 → つむぎの予想か疑い → 意外な答え → 反応は1回 → 次の問い → 層を分ける（記録／言い伝え）→ 事実で引く
- **まとめ**：要点を番号で、要点ごとにつむぎが置き換えるか言いかける。最後につむぎが自分の言葉でその人を言い直す
- **掛け合いの配分**（10-07）：5本とも剣崎の字数が72〜79%で講義に近かった。**70%まで**。つむぎにも事実・予想を言わせる
- **伸びている歴史の長尺18本の調べ**（research/benchmark_long.md）：冒頭15秒でいちばん重い事実を1文、60秒以内に最初の掘った事実／
  各節に小さな具体的な逸話を1つ／最後の節に人柄の場面（家族・手紙・最期の言葉）、締めは余韻の一文＋次回の人物名（「いかがでしたか」は使わない）／
  分からない所は「分かっていない」と言い、出典を1回は読み上げる／25〜40分なら7〜8節・1節3〜5分／嫌われるもの：AIらしい日本語、元気すぎる声、期待した人物が出ないこと
- **文体**（10-08）：同じ文末が4文続く・同じ言い回しが1本に4回・書き言葉（である・とされる…）・つむぎの頭が「え」「へえ」で1節3回・読点の多い長い文。check が「文体：」で知らせる（止めない）

### 抑揚（ユーザーが一番気にしている）

- **2人とも抑えめ**（10-04「女の子の声がおかしい」「かなり抑えて」「男性側は、抑揚はかなり控えめ」）：つむぎは素の抑揚1.0・調子の効き4割・上限1.3／1.08倍、
  剣崎は素の抑揚1.0・効き3割・上限1.15。「強めて」と言われても、上限（抑揚2.0・速さ1.2倍）に張りつかせない（check が知らせる）
- **《》の強調も話者ごとに効きを変える**（config の `emphasis`）。剣崎は0.3（10-05、1.0 だと色文字の語が裏返ったように聞こえた）。つむぎは1.0
- VOICEVOX は「〜んですか」の「ン」を最高音にする。「ン」で始まる区切りは自動でつなげる（chiso/voice.py）
- 読み違いは `readings.yaml` に足す。**音を出す前に kana で読みを確かめる**（「いちばん上」を「イチバンジョウ」と読んだ）

### 画面（10-04 に固め、10-07・10-08 に足した）

- **画面**：背景の絵画／右上に肖像（二重の金の額、名前＋誰の絵か）／左に「掘り出したメモ」（その節の札が新しい順に3枚）／節の進み具合の点／
  地層の年表／2人のあいだの下に字幕（2行・高さ固定、話し手の名前、《》の語は朱色。10-04「字幕もだしたい」）。話す側は明るく、聞く側は暗く
- **背景の絵は動かさない**（10-06「背景を微妙に動かさないで」。config の video.bg_motion: false）。動きは：話し始めに跳ねる／絵が替わると溶け合う／
  年表の印が動く／新しいメモが滑り込む／冒頭2行は題名の問いを大きく／節の頭に「第N節 題名」
- **画面の真ん中を空けない**（10-06）：肖像が無いときは背景と同じ絵を真ん中の額に出す
- **強調語の飛び出しは使わない**（10-04「不要」）。**BGM は入れない**。効果音は節の切り替え・図・お金の札・聞き手の驚き（20秒に1回まで）の4つだけ（合成音、出典不要）
- **次回予告**：最後に12秒。右側は YouTube の終了画面のために空ける
- **画面の替わり方**（10-07。信長の回で同じ絵が2分前後動かない区間が6か所あった）：**同じ背景は40秒まで**（1本30〜40枚）・**20秒に1回は新しいもの**
  （絵・札・図・挿絵・肖像・絵の一部・赤ペン）。絵が少ない回は detail・mark で同じ絵から新しいものを作る
- **図は1本に3つ以上**（10-04）。地図は Natural Earth（パブリックドメイン）
- **お金**：「1リーヴル＝何円」は資料で300〜2,000円と割れるので使わない。**当時の日当を今の1万円とし**、前提を basis に書いて語りでも「目安」と言う
  （10-04 に「年収300万円」で作ってずれたので直した）
- **人物の言葉**（10-04「マリーアントワネットのセリフとかの声はどうなっている？」）：記録に残る本人の言葉だけを、config の roles の別の声で読む。前置きは語りで
- **用語の札・場所の小さな地図・この時○歳**：自動（terms.yaml・places.yaml・台本の people:）。説明は40字まで・事実だけ。生没は百科事典で確かめる
- **挿絵**（10-04、画面の替わる間隔が中央値18秒で人気の動画の5〜10秒より長かったので足した）
- **つむぎの寄り**は1本2回まで（毎回使うと安くなる）。ショートには出さない
- **紙の質感・ここまでの地層**（10-07）：新しい回から台本の一番上に `texture: true`・`recap: true`（前の回の見た目を変えないため既定は切）
- **節の終わりの引き**（10-04）：導入とまとめ以外の節は、終わり2行に次が気になる事実の一言（`hook: true`）。答えを先に言わない
- **冒頭とショートの出だし**（10-07）：最初の4行（約100字）に数字・年・人名／ショートの1行目に名前か数字、つなぎの言葉（そして・しかも…）で始めない
- **章の題**（10-08）：節の題＝概要欄の目次。年・人名・地名・場面の語を入れる（places.yaml に無い地名は拾えないので、知らせが出ても地名なら気にしない）

### サムネイル（10-04・10-07・10-08）

- 絵を全面・下に赤い名前札＋その人を一言で（lead 白＋main 特大の黄）・右下に剣崎（後ろ）と驚き顔のつむぎ（手前）。シリーズ名・チャンネル名の札は入れない。
  目印は下端の細い地層。`out/*_thumbnail_preview.png` で一覧の大きさでも読めるか見る
- **構図は回ごとに選ぶ**（10-07「量産型に見せない」）：**そろえるのは目印だけ**（地層の帯・字体・黄白赤）。face／scene／versus／number／map／classic。
  選び方：良い肖像→face、合戦・行列の名画→scene、2人の関係→versus、1つの数字→number、旅・遠征→map。**同じ構図が3回続くと check が知らせる**
- **作り込み**（10-07「もう少し作り込んだサムネにしたい」）：layout を書いたときだけ、構図ごとの光・縁取り・質感・人物の切り抜き（rembg、任意。CI には入れない）。
  classic・3案の b・c は画素まで同じ。見本 `dev/output/rekishi-chiso/research/thumb_layouts2/`
- **引きの要素**（10-08「サムネにもう少し人を惹きつける要素を入れたい！」、調べ research/thumb_hooks.md）：reactor・hide・contrast・flip・flash。
  **1枚に1つか2つまで**。**台本で答えが出ることだけ**（合わないと YouTube の「誤解を招く」決まりに当たる）。
  **和服（左前＝死者の着方になる）・文字・紋の入った絵は反転しない**。見本 `research/thumb_hooks/`
- **3案**（10-07、`thumb --variants`）：YouTube Studio の「テストと比較」用。a＝今の形／b＝顔に寄せる／c＝上に大きな数字。b は元の絵が粗いとぼやける（吉良の古写真）ので crop を書く

### 関門・投稿（チャンネル共通の決まり）

- **台本のユーザー確認は不要**（10-05「今後台本確認は不要です」）。代わりに Claude が自分で何回も確かめてから approve する：
  事実（前半・後半を資料で）・流れとキャラ（初めて聞く人の耳で）・読み（kana を1行ずつ）→ 直す → 直した所の確認 → 最後の通し確認で
  「公開してよい水準」と出るまで回す（マリーの回は3回）。`check` の × も0に。`build` / `shorts` は `approve` の控え（台本のハッシュ）が要る
- **投稿の前に本番の動画を見せる**。`upload` は承認（台本）と `screen`（動画のハッシュ）の両方が無いと動かない
- Google Cloud は**サッカーと別のプロジェクト「rekishi-chiso」**（API の枠を分ける。10-04）。鍵と許可は `dev/output/rekishi-chiso/secrets/`。`whoami` でチャンネルを確かめる。控えは `posted.json`
- **本編は1日2本、12時と19時**（10-08。それまでは1日1本・19時）。**ショートは本編の翌日の11・12・13・14・16・17・18・19・20・21時に10本**（10-06。15時は空ける）。1日2本からは**1題材5本ずつ**（ショートは1日10本までしか配られないため）
- **再生リストと英語の題名**（10-08。固定コメントはやらない）：台本の `playlists:`（省けば series:）・`shorts_playlists:`・`en: {title, description, chapters}`。
  英語の説明は日本語の概要欄の要点を短く・**事実は台本にあることだけ**（VOICEVOX のクレジット・絵の出典は日本語の概要欄から自動で写す。案は research/en_titles.md）。API の枠は1日 10,000（playlists.insert・playlistItems.insert・videos.update は各50、投稿 1,600・字幕 400）。投稿の日は `--budget` で抑え、残りは翌日。
  投稿済みは `playlists --sync`・`localize`
- **許可**：書き込みには `youtube.force-ssl` が要る（10-08 の token は持っていた）。足りないときコマンドは**ブラウザを開かずに止まる**。取り直しは**ユーザーが** `reauth`：
  「歴史の地層」の Google アカウント → チャンネル一覧で**「歴史の地層」**（「海外サッカーの理由」を選ばない）→「確認していません」は「続行」→ **チェックを全部入れて**続行。
  古い token は `secrets/token.<日時>.json.old` に写す（消さない）

## 2. 台本の書き方（どう）

- **行で話していることと、そのとき映っているものを合わせる**（10-08 ユーザー指摘「会話している内容と画面の内容が合ってない」）。
  「1582年、京都の本能寺」と話す行には本能寺の絵、「1568年、堺に」なら堺の絵。話題が節の場面から離れたら、節を分けるか絵を替える
  （detail で寄せてもよい）。次の節の出来事を年つきで先に言う引きは、いまの絵と食い違う。
  check の「話と画面：」が、年＋場所・出来事で場面を言い出した行を、節の題・背景の出典・絵の一覧（research/*_assets.md）・
  札・図・名札と照らして知らせる（chiso/match.py。draft・build の最後にもう一度並ぶ）。次回予告の行の地名には地図を出さない
- **新しい回は `scripts/_template.yaml` を写す**。上から順に埋めれば、texture・recap・サムネの layout・ショートの hook など全部の道具が正しい既定で入る
- **全部の道具を使った見本は `scripts/_showcase.yaml`**（信長。投稿しない）。道具を足す・描き方を変えたら、これで check → draft → qc → shorts --draft を通してコマを見る
- 道具ごとの書き方の場所：

| 道具 | 台本 | 説明のある所 |
|---|---|---|
| 調子・間・強調 | `tone:`・`pause:`・《語》 | chiso/voice.py |
| 札・年表・肖像・人物の言葉 | `card:`・`year:`・`portrait:`・`- 人物:`＋`who:` | chiso/script.py の頭 |
| 図（map・pie・bars・people・compare・money・stats・calc・numberline・line・versus）と `upto:` | `figure:` | chiso/figures.py の頭 |
| 絵の一部・赤ペン | `detail:`・`mark:` | chiso/pen.py の頭 |
| 吹き出し・挿絵 | `bubble:`・`icon:` | chiso/extras.py の頭 |
| つむぎの寄り | `reaction:` | chiso/reaction.py の頭 |
| サムネイル | `thumbnail:` | chiso/thumb.py・thumbfx.py・hooks.py の頭 |
| ショート | `shorts:`・`short:` | chiso/shorts.py の頭 |

- **道具の重なり**（10-08、見本の通し確認）：画面は 寄り → 絵の一部 → 図 → 肖像・挿絵・額 の順に1つを優先する。
  `detail` を書いた行で図は終わる（続けるなら detail のあとの行に同じ figure）。図の出ている行の挿絵、寄りの行の吹き出し・挿絵・絵の一部は出ない（check が知らせる）。
  `upto` で増えた行の赤ペンは、図が伸びきってから描く
- **点検の目安の数字**（背景40秒・新しいもの20秒・剣崎70%・寄り2回…）は `chiso/check.py` の頭に1か所でまとめてある

## 3. 作り方とコマンド

手順（スキル rekishi-video）：下調べ → 台本 → kana → check → draft → qc → 自分の確認3回 → approve → build → qc → shorts → thumb --variants → describe --keywords → 見せる → screen → upload

```
python -m chiso.cli check    scripts/x.yaml     # 作る前の点検。止める(×)→直すと効く(!)→参考(・)の順、同じ種類は1件にまとめる
python -m chiso.cli kana     scripts/x.yaml     # 全行の読みをカタカナで
python -m chiso.cli voice    scripts/x.yaml     # 音声だけ（抑揚の確認）
python -m chiso.cli draft    scripts/x.yaml [--lines 40]   # 確認用の動画（右上に「確認用」）。最後に段ごとの時間が出る
python -m chiso.cli qc       scripts/x.yaml [--video out/x_draft.mp4]   # 出来上がった動画の点検（20秒ごとの一覧・画面の替わり方・音・無音）
python -m chiso.cli approve  scripts/x.yaml     # 自分の確認を回しきったあとだけ
python -m chiso.cli build    scripts/x.yaml     # 本番
python -m chiso.cli shorts   scripts/x.yaml [--draft] [--only s1,s3]
python -m chiso.cli thumb    scripts/x.yaml [--variants] [--out dir]
python -m chiso.cli describe scripts/x.yaml [--keywords]   # 概要欄
python -m chiso.cli keywords "織田信長" [--all] # YouTube の検索候補によく続く語・題名・タグの下書き
python -m chiso.cli assign   scripts/x.yaml --assets research/x_assets.md   # 絵の割り当ての下書き
python -m chiso.cli screen   scripts/x.yaml     # 本番の動画を見てもらった控え（OK のあとだけ）
python -m chiso.cli upload   scripts/x.yaml --at "2026-10-05 19:00"
python -m chiso.cli screen-shorts / upload-shorts scripts/x.yaml --start "2026-10-06 11:00"
python -m chiso.cli whoami | playlists [--sync] | localize scripts/x.yaml [--dry-run] | reauth（ユーザーが打つ）
python -m chiso.cli prepare-characters --tsumugi <png> --kenzaki <png> --tsumugi-psd <psd>
```

- VOICEVOX エンジン（127.0.0.1:50021）を起動しておく。抱えたメモリが6GBを超えると音声のあとに立ち上げ直す
- **速さ**（10-08）：背景は動かさないので、背景の動画は作らず「絵ごとの1枚＋替わり目の18コマ」の並びを重ねるときに読む（前は本編1本で背景に約50分）。
  前景の下の層は口パク・字幕ごとに描き直さず控える。かかった時間は draft・build の最後に段ごとに出る。測った結果は `dev/output/rekishi-chiso/research/optimize/`
- **config.yaml の値を変えると本編のコマが全部描き直しになる**（コマの控えの名前に設定全体が入るため）。台本の一番上の texture・recap も同じ
- テストは CI（rekishi-chiso-tests.yml）。手元では `PYTHONIOENCODING=utf-8 python -m pytest -q tests`
