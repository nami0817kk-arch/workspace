# 日本のなぜ

YouTube チャンネル（名前は未決）の動画を作る。**「歴史の地層」の対**として、
過去を縦に掘るのではなく、**いまの世の中を横に切る**。

## コンセプト（2026-10-06 にユーザーと決めた）

- **切る**：毎回ニュースを1つ選び、**表面**（報じられたこと）→ **切る** → **断面**（制度・歴史・数字）
  → **見立て**（なぜそうなったか）の順で見せる
- **画面の主役は自作の断面図**。他人の写真も発言も使わない。権利の心配を構造的に持たない
  （サッカーのチャンネルが抱えている審査の危うさを、こちらは最初から持たない設計にする）
- **題材は固定しない**。その日いちばん多くの人が気にしていることから選ぶ。
  「住宅のチャンネル」「都市のチャンネル」のように題材で縛ると、幅が狭く題材も尽きる

## 「なぜが立つ」の3条件（題材を選ぶ物差し）

1. **結果は報じられたが、理由が説明されていない**（「ガソリンがまた上がった」→ なぜ？）
2. **多くの人が誤解している**（「金利が上がる」→ どの金利？）
3. **日本だけ、あるいは1国だけが異質**（中古住宅が築20〜25年で価値ゼロになるのは日本だけ）

どれにも当たらないものは、どれだけ大きいニュースでも扱わない。

## 扱わないもの

- **政治的な是非**（どちらが正しいか）。数字が何と言っているかまでに留める
- **医療・健康の助言**。審査が厳しく、誤りの責任が重い
- **事件・事故の被害者、死亡記事、芸能の私生活**
- **投資助言**。事実の提示まで

## 素材

| | |
|---|---|
| 図・グラフ・断面図 | **自作**（このチャンネルの主役） |
| 地図 | Natural Earth（パブリックドメイン）／OpenStreetMap（出典表示） |
| 写真・映像 | Pexels・Pixabay（無料・商用可）／Wikimedia Commons |
| 衛星写真 | NASA（パブリックドメイン） |

**Google マップは使わない**。動画で使うには画面に出典を出し続ける必要があり、
ストリートビューは事前申請が要る。毎日出すチャンネルで守り続けるのは事故のもと。

## 数字と出典

- 画面の下に**出典を出し続ける**（「国土交通省『○○』p.12」まで）。これが他の解説チャンネルとの差
- **価格や料金には「2026年10月時点」と必ず添える**。1年後に嘘つきにならないため
- 原典に当たる手順は `primary-source-research` スキルに従う。記事の言い換えを根拠にしない

## 題材を拾う

```bash
python scripts/gather.py --out research/candidates/<日付>.json
```

ニュースと検索トレンドの RSS を読み、「なぜが立つ芽」を含む見出しだけを拾う。
扱わないもの（事件・死亡・芸能）はここで落とす。**○× はユーザーが付ける**（番号だけ振って出す）。

## 関門（2026-10-08 に決めた）

**台本確認は不要**（ユーザー決定）。歴史の地層と同じ扱い。
代わりに**自分で確かめてから進める**。確かめるのは3つ。

| | どうやって |
|---|---|
| **数字と出典** | 原典に当たる（`primary-source-research` スキル）。記事の言い換えを根拠にしない |
| **台本の偏り** | `python scripts/audit_script.py 台本.yaml`（語尾・相づち・専門語・画面の偏り・1行の長さ） |

**動画を見せる関門は残る。** `scripts/post.py upload` は `screen` の控えが無いと動かない。

### 性格（2026-10-09 に決めた）

| | 岬 透 | 小倉 知夏 |
|---|---|---|
| **基本** | **淡々と事実を積む。** 驚かない。「これが数字です」と置く。感情を足さない | **よく喋る。** 予想して外す・自分の暮らしに置き換える・ときどき食い下がる |

### 口調（2026-10-09 に決めた）

| | 岬 透 | 小倉 知夏 |
|---|---|---|
| 一人称 | **使わない** | **私** |
| 文体 | です・ます | です・ます |
| 相手の呼び方 | 小倉さん | 岬さん |

**岬は普段、一人称を使わない。** 「調べたことを置く」姿勢がそれで出る。
**見立ての節だけ「私は、こう見ています」と言う。** そこだけ主観だと分かって際立つ。
「私はこう思います」を全編で使うと、どこが事実でどこが見立てか、見る人が分けられない。

### たまに（**1本に2〜3回まで**）

語り手が**答えを言う前に問いを返し**、聞き手が**声に出して考えて、途中で間違える**。

```yaml
- 語り: この税金、1台あたり年にいくら払っていると思いますか。
- 聞き: えっと……月に二回入れるとして、一回五千円だから……年に十二万円?
- 語り: 四万円です。
```

**山場の数字を出す前に置く。** 1本に2〜3回まで（2026-10-09 ユーザー指示）。
それ以上やると問いの往復が多すぎて、30分で話が進まない。
9つの節のうち、数字がいちばん効く節に散らして置く。

### ショートの作り方（2026-10-09 に決めた）

**本編から切り出す。** ショート専用の台本は書かない。

| 切る場所 | ショートの中身 | 終わり方 |
|---|---|---|
| **冒頭の数字** | いちばん強い数字を、理由を言わずに出す | 「なぜこうなったのか」で切る |
| **よくある誤解** | 広まっている説を1つ潰す | 「では、本当は何なのか」で切る |

| **世界と比べる** | 日本だけが違うことを示す | なぜ日本だけなのかは言わない |

**リンクは貼らない。** 関連動画のリンクは 2026-10-03 に見送っている。

## 台本の型（1本 **30分**・9つの節）

| 節 | 名前 | 長さの目安 | 中身 | 図 |
|---|---|---|---|---|
| 00 | **表面** | 2分 | 報じられたことをそのまま出す。聞き役が素朴に反応する | 見出しの板 |
| 01 | **問い** | 30秒 | 「なぜ？」を立てる。**これが題名になる** | なし |
| 02 | **一の断面** | 4分 | いちばん分かりやすい切り口。数字を出す | 積み上げ |
| 03 | **二の断面** | 5分 | いつ、誰が、なぜそう決めたか | 年表 |
| 04 | **三の断面** | 5分 | 誰が払い、誰が受け取っているか | 流れ図 |
| 05 | **四の断面** | 4分 | **世界と比べる**。日本だけなのか | 比べる図 |
| 06 | **よくある誤解** | 4分 | 広まっている説を1つだけ潰す。人ではなく説を扱う | 比較の図 |
| 07 | **見立て** | 4分 | なぜそうなったかを**番号で**出す | まとめの板 |
| 08 | **締め** | 1分30秒 | 次回の問いを聞き役が一言で振る | なし |

2026-10-06 にユーザーが「1作30分」と決めた（18〜22分から変更）。
伸ばすために話を薄めるのではなく、**「世界と比べる」節を足して中身を増やす**。
収益化の新基準（2027-02 から長尺 8,000 時間）でも長尺のほうが効く。

### 決まり

- **節ごとに図を1つ**（05 と 07 を除く）。図が作れない節は、その節を作らない
- **出典は画面の下に出し続ける**。数字を言う行では、必ず出典を画面に出す
- **価格・料金には「2026年10月時点」を添える**
- **聞き役を受け身にしない**。驚くだけの返しは1節に2回まで。
  代わりに**予想して外す・誤解の側から疑う・自分の暮らしに置き換える・節の終わりで言い直す**
- **締めは必ず聞き役**が次回の問いを振る（「〜って、なんでなんでしょうね？」）
- **1本に1つの問いだけ**。2つ立てたくなったら、2本に割る

### 台本の書き方

`scripts/_template.yaml` を写して使う。節番号のキーは `id`（`no` は YAML で「偽」になるので使わない）。行の話者に括弧で強さを付けられる（`語り(強)`）。

## 題材の決め方（2026-10-06 に固めた）

### 手順

```bash
python scripts/gather.py --out research/candidates/<日付>.json   # 集める・選り分ける
```

### 点の付け方（23点満点）

| 物差し | 満点 | 測り方 | なぜ見るか |
|---|---|---|---|
| **検索の広さ** | 5 | YouTube の補完が何件出るか | 関心が広いほど、届く人が多い |
| **問いの濃さ** | 5 | 補完のうち「なぜ・いつ・とは・どうなる」が占める割合 | 知りたがられている＝説明する価値がある |
| **原典の堅さ** | 5 | 当たるべき原典が公的機関（省庁・法令・統計）か | 出典を出せない題材は作らない |

| **新しさ** | 2 | 今日のニュース・はてブ由来なら加点 | 今日見る理由になる |
| **いまの勢い** | 3 | **Google の急上昇ワード**に当たるか（1000件以上で3点・500で2点・100で1点） | 実際にいま検索されているか |

**「いまの勢い」は 2026-10-09 に足した。** それまで「新しさ」は**由来だけ**で決めていて
（ニュース由来なら3点）、**ニュースに出たが誰も検索していない題材**にも点が付いていた。

**旧 URL（`/trends/trendingsearches/daily/rss`）は 404。** 今は `/trending/rss`。

**照合は急上昇ワードの側を分ける。** 丸ごと一致を見ると「ホワイトソックス 監督」が

## 画面の作り（2026-10-06 に固めた）

参考にした「大人の学び直しTV」の画面を実際に見て分解し、寄せた。
**差は配置ではなく、要素の質と種類にあった。**

### 画面の決まり

| | |
|---|---|
| **背景** | 実写の写真か動画を**暗く落として**（明るさ0.33）敷く。上下に暗い被せを入れる |
| **書体** | **Noto Sans JP の可変フォント**（Windows 標準の `NotoSansJP-VF.ttf`）。見出しと字幕は 900 |
| **字幕** | 画面の5分の1を占める大きさ（74px）。**黒の太い縁（17px）だけ**。数字は明るい金（255,206,72）、ほかは白 |
| **図** | 白い板に載せ、**金の細線**と落ち影をつける |
| **立ち絵** | 左下に岬、右下に小倉（**おなかまで**・高さ 420。10-10 に胸から上／おなか／腰を見比べて選んだ）。話していない方を少し暗く。**縁の光はやめた**（2026-10-10「白い線は何で？」→「外して」） |
| **ロゴ** | 左上。チャンネル名と一言を添える |
| **出典** | 画面のいちばん下に出し続ける |

**字幕の縁は、縁を全部描いてから本体を描く**（1文字ずつ重ねると、次の字の縁が前の字を潰す）。

**数字に金の縁を重ねない**（2026-10-07）。金の文字の上にさらに金の縁を描いていたため、
輪郭がぼやけ、黒の縁もその分細くなって読みにくかった。黒い太い縁だけにして、
金そのものを明るくする（板の中の金より明るい 255,206,72）。

**写真の選び方で守ること。**

- **国や地域を指す画面には、その国の写真を使う**（「ドイツ」の面に日本の住宅を敷かない）。
  無ければ写真を敷かず、濃紺の地のままにする
- **実在の店や企業の看板が大きく写る写真は、その企業が題材のときだけ**。
  そうでないと「この会社の話」と誤解される
- **左右に並べる画面は、2枚の明るさを揃える**（`versus` は平均の明るさを測って自動で揃える）

3つを順に当てる。**立ち絵を足したら、この道具を通してから使う。**

## 節の中で画面がどう切り替わるか（2026-10-07 に固めた）

**図を1枚作って4分出しっぱなしにすると、どれだけ作り込んでも間が持たない。**
ニュース番組は10〜20秒で画面が変わる。ただし毎回ぜんぶ差し替えるのではなく、
**同じ図の上に1つずつ増えていく**。語りが「ここが」と言う所で赤が付く。

### 増やし方は2つ（`danmen/sequence.py`）

| | |
|---|---|
| `grow(fn, fig)` | **項目が1つずつ増える。** レシートの行、箇条書き、年表、アイコンの並び |
| `reveal(im, marks)` | **書き込みが1つずつ増える。** 蛍光ペン → 丸 → 矢印 の順に足していく |

**`grow` は最終的な項目数を図に渡す（`slots`）。** これが無いと、増えるたびに
既に出ている項目が動いて、映像で跳ねて見える。図の側は `slots` を見て、
列の幅と板の高さを最初から最後の形にしておく。

### 節ごとの画面の数（`sequence.PATTERNS`）

| 節 | 長さ | 画面 | 1枚あたり |
|---|---|---|---|
| `surface` | 120秒 | 8枚 | 15秒 |
| `question` | 30秒 | 2枚 | 15秒 |
| `cut1` | 240秒 | 17枚 | 14秒 |
| `cut2` | 300秒 | 21枚 | 14秒 |
| `cut3` | 300秒 | 20枚 | 15秒 |
| `world` | 240秒 | 15枚 | 16秒 |
| `myth` | 240秒 | 14枚 | 17秒 |
| `reading` | 240秒 | 15枚 | 16秒 |
| `close` | 90秒 | 7枚 | 13秒 |

**1本ぶんで 119 枚。** 作ってみるまで「図が41種あれば足りる」と思っていたが、
実際には**1本で100枚以上の画面を組む**ことになる。だから型が要る。

### 決まり

- **1枚あたり6〜22秒。** 22秒を超えたら画面が足りない（`sequence.check()` が言う）
- **最初から全部出さない。** 1行だけ出して、話しながら増やす。
  全部出すと、見る人の目が語りより先に行ってしまう
- **書き込みは1つの画面に2つまで**（前出の決まりのとおり）
- **`+` で始まるものは前の画面に重ねる**（別の図を作らない）

```bash
python -c "from danmen import sequence; print(sequence.report())"   # 全節の点検
```

### 台本に画面を書く

```yaml
sections:
```

### 画面は台本から作る（2026-10-09 に作った）

`make_screens.py` は試作30秒ぶんを手で組んだものだった。1本ぶん（120〜130枚）を
台本から組めるようにした。

```bash
python scripts/build_screens.py 台本.yaml          # 画面を作る（--only 02 で1節だけ）
python scripts/assign_screens.py 台本.yaml         # 台本の行に screen: と cast: を割り当てる
python scripts/assign_screens.py 台本.yaml --clear # 割り当てを消す（何度でも掛け直せる）
```

**節ごとに図は1つでは足りない。** 4分の節に図1つだと1枚40秒で、間が持たない。
台本の節に `more:` で図を足す。節ごとの画面は **中扉1枚＋各図の項目数**。

```yaml
  - id: "02"
    lead: 払う額は、申請の順番で決まる   # 中扉に出る「この節で何を見るか」
    figure: { kind: compare, from: 9社の内訳, ... }
    more:
      - { kind: hero,  from: 0円です。,     ... }
      - { kind: table, from: 全額免除です。, ... }
```

**冒頭の10秒は台本の `hook:` に書く。** ここを書かないと、いきなり 00 の中扉から始まる。

```yaml
hook:
  value: 0円                    # fullscreen.number で全画面に。**size を上げないと小さい**（既定230→380）
  size: 380
  title: 同じカルテルをした9社のうち
  lead: 1社だけが、これだった
  question:                     # screens.title。1行を [["0円","#FFCE48"],["なのか","white"]] にすると色を変えられる
    - なぜカルテルは
    - 「最初に自白した1社」だけ
    - [["0円", "#FFCE48"], ["なのか", "white"]]
```

**この2枚に当てる台詞を、00 の先頭に2行置く。** `assign_screens.py` が1行に1枚ずつ当て、
**全画面なので立ち絵は出さない**（`cast: なし` を入れ、3行目から `cast: auto`）。

**`from:` を書かないと、画面と話がずれる。** 2026-10-09 に実際に起きた
（割増の表が出ているのに、台詞はごま油の話をしていた）。`from:` はその図を出し始める
**台詞の一部**でよい。書かなかった図は、前後の `from:` のあいだを枚数の比で分ける。

**図の並びは、台詞の順と同じにする。** 違うと、後ろの図が前に押し出されて画面が出ない。

#### 2つの物差し（どちらも外すと作り直しになる）

| | 見るもの | 外したときに起きること |
|---|---|---|
| **1枚あたり6〜22秒** | `build_screens.py` が節ごとに出す | 長いと間が持たない。短いと目が追えない |
| **1枚あたり台詞4行まで** | 図の枚数と、その話をしている台詞の行数 | 図の増え方が語りに追いつかない。**社名を8つ読み終わったのに、表には2社しか出ていなかった** |

画面の数より台詞の行が少ないと、**その画面は出ない**（1行に1枚しか置けない）。
そのときは図の項目を減らすか、**台詞を足す**。

### 画面と図で踏んだ穴（2026-10-09）

| | |
|---|---|
| **板の周りに黒い枠** | `texture.finish(panel.convert("RGB"), "panel")` と書くと、落ち影の半透明が黒くつぶれる。**質感を掛けたあとアルファを戻す**（`build_screens.finish_panel`） |
| **添えが右端で黙って切れる** | `_note` は折り返さない。入らないときは警告が出るので、**添えを短くする**（28px が下限で、縮めても足りない） |
| **表の値が隣の列に重なる** | 列の幅を超えた値は自動で小さくなるが、見出しの列が広すぎると値が 28px まで潰れる |
| **立ち絵が1人も出ない** | 台本に `cast:` が無いと `movie.py` は重ねない。`assign_screens.py` が節の頭に `cast: auto` を入れる |
| **`compare` の添えが切れる** | 棒の右に空ける幅を 300px 固定で見積もっていた。実際の添えの幅から出すよう直した |

### 文字の大きさ（2026-10-07 に決めた。いちばん効いた直し）

### 日本語の組版（2026-10-07 に直した）

折り返しは **`typo.wrap` に一本化**した。文字数だけで切ると**行頭に「、」が来る**。
実際に試作の字幕で起きた。守るのは5つ。

- 行頭に「、」「。」「）」などを置かない（前の行にぶら下げる）
- 折り返す位置から**2文字以内に読点があれば、そこまで入れる**
  （「…始まりました／が、半世紀…」のような切れ方を防ぐ）
- 行末に「（」「「」を置かない（次の行へ送る）
- **数字の途中で切らない**（「17」と「5円」に分かれない）
- 切れるなら**読点・句点のあと**で切る（2行目が1語だけになるのを防ぐ）

### 立ち絵（2026-10-07）

**口パクはやらない。** 画像処理で口を開ける方法を3通り試したが、どれも
線画＋淡い彩色の絵のなかで口だけが浮いた。

1. 楕円をベタ塗り … 口だけ色が濃く浮く
2. 唇の形を描く … 輪郭線を入れても、のっぺりして浮く
3. 口の線より下を切り出して下げる … 四角い帯が出て、あごが切れる

口の形・唇の色・線の太さが、人物と表情ごとに違う。描き足す方法では追いつかない。
**違和感のある口パクは、無いより悪い。**

代わりに、**しゃべっている人は縁をうっすら光らせる**。
誰がしゃべっているかはこれで分かる。

**2026-10-08 に Gemini で作り直そうとして、5通り試して全部だめだった。**
ユーザーの判断で**口パクも瞬きもやらない**。**再提案しない。**

| 試した方法 | どうなったか |
|---|---|
| Gemini の口を楕円のぼかしで移植 | **元の口とシワが薄く透ける**（半透明のマスクの縁） |
| マスクの芯を不透明に固定 | 今度は貼った四角の縁が段差として見えた |
| 元の口を肌で消してから口の形だけ貼る | 口の位置がずれ、顎の輪郭線まで一緒に貼り付いた |
| 口をコードで描く（元の上唇は残す） | 半月形の「穴」になり、人の口に見えない |
| 顔ごと差し替える | コマごとに顔が跳ね、切り抜きの外が白く欠ける |

**根っこの原因は1つ。生成AIは「同じ顔で一部だけ違う絵」を画素単位で揃えて出せない。**
4枚組を1枚で頼めば絵柄はそろうが、顔の大きさ・位置・角度は1枚ずつ違う。
だからどの方法でも、最後はズレの処理に行き着く。

**分かったこと（次に誰かが挑むときのために）**

- 唇は**色で見つかる**（肌より赤い・横長）。目や眼鏡を基準にすると髪を拾って外す
- 倍率は**顔の幅**（肌色の帯の幅）で合う
- 切り出す位置は**必ず「口を閉じた絵」で測る**。開いた絵は唇の重心が下にずれる
- **開き具合を不透明度で表してはいけない**。薄く重ねると元の口が透けて二重になる
- 元の立ち絵19枚も、**表情ごとに顔の大きさが違う**（幅 753〜836px）。
  同じキャラでも1枚ずつ別に生成されているため

**2人とも常に出す。人は切り替えない**（2026-10-08 ユーザー指示）。

最初は `cast:` を書いた行だけ出していて、34秒のうち7秒しか人が写らなかった。
次にしゃべっている人だけを出したが、**話者が変わるたびに画面の人が入れ替わり**、
そちらに目が行って落ち着かなかった。

置き方は**2つ**。どちらも2人とも出す。しゃべっている人は明るく、
**聞いている人は少し暗く小さくなる**（0.72倍・0.90倍）。表情は行の強さから自動で決まる。

| 書き方 | 置き方 | いつ |
|---|---|---|
| `cast: auto` | **左右の下**に2人 | 板に載る図の画面（下 326px が空いている） |
| `cast: wipe 右上` | **箱**に2人（`studio.flip` のワイプと同じ形） | 全画面の様式 |
| `cast: なし` | 出さない | 画面じたいが2人を出すとき（`talk.talk` / `talk.reaction`） |

**ワイプの場所は画面を見て決める**（`右上` `左上` `右下` `左下`）。
全画面の様式は画面いっぱいに描くので、空いている場所が画面ごとに違う。
下に立ち絵を置くと中身と重なる（2026-10-08）。

**全画面の様式は、ワイプのために右上か左上を空ける。**
速報の帯のチャンネル名は左上へ、おさらいの板は左に寄せて幅を 1450 までにした。

| 強さ | 語り手 | 聞き手 |
|---|---|---|
| ふつう | `setsumei`（説明の顔） | 素の顔 |
| 強 | `shinken`（真剣） | `odoroki`（驚き） |
| 特強 | `shinken` | `odoroki` |
| 抑 | 素の顔 | `nattoku`（納得） |

**語り手の「強」は力をこめて話すこと、聞き手の「強」は驚くこと。**
同じ「強」でも意味が違うので、表情の表を人ごとに分けてある。

**板は画面の上半分に、中央に置く。幅は 1740 まで。**
立ち絵が左右の下に2人とも出るので、**下 326px は字幕と立ち絵のために空ける**。

**この 326 は板の縮み方で決めた**（2026-10-08 に実測）。
420 を空けていたときは、高さ 778 の板が 630 にしか置けず **0.81倍に縮み**、
本文 48px が画面上で **38.9px** になっていた。立ち絵を 400 → **320px** に
小さくして 0.93倍まで戻し、本文は 44.7px になった。
3割小さく（280px・ほぼ等倍）も作ったが、誰が話しているか分かりにくく見送り。

**字幕は、3行目を捨てずに字を小さくして2行に収める。**
2人の立ち絵で字幕の幅が狭まったとき、文末が切れていた（74px → 最小 52px まで縮む）。

### 表情（2026-10-10 に作り直した）

- **岬はほとんど変えない**（ユーザー「男の表情はほとんど変わらずだよ」）。台本に `face:` を書いた所だけ。
  1本に2〜3か所まで（カルテルの回は「断っておきます」の真剣と、締めのにっこり）
- **小倉は台詞の中身で決める**（`movie.speak_face`）。強→驚き／「ずるい」「納得いかない」→不満／
  「……」「えっと」「正直」→困る／「〜んですね」→感心（「〜ないんですね」は困る）
- **聞いている小倉も反応する**（`movie.listen_face`）。相手の台詞の**後半 45%** だけ顔を変える。
  次に自分が驚く行なら驚き、金額・人数・件数・倍を聞いたら「お」の口（続く数字は最初の1回だけ）、
  短い否定（「違います。」）には「え？」。**日付や年数では反応しない**（ずっと口が開いて見えた）
- 台本で上書きできる。`face:` は話す人、`react:` は聞いている人（日本語で書く: 驚き・にっこり・感心・
  不満・困る・くやしい・すぼめる・え・お・しょんぼり・真剣・大笑い）
- **表情の顔のまま口パクする**（表情の目＋ふつうの口）。瞬きはふつうの顔のときだけ
- 前は「行の強さ」だけで決めていて、作った絵の大半が一度も出なかった

### 背景（2026-10-10）

**節ごとに写真を変える**（台本の節に `photo:`）。1本を同じ写真で通すと30分変化が無い。
国を指す節で、その国の写真が無ければ `photo: なし`（濃紺）。

### 字幕の割り方（2026-10-10）

立ち絵を 420 にすると、字幕に使える幅は 812px（1行に11字ほど）しかない。

- **字は捨てない。** 前は2行で切っていて、台詞の後ろが消えた
- **長い台詞は何枚かに分け、話している途中で送る**（`split_caption`。時間は文字数で割る）。
  区切るのは句読点を先に、無ければ文節の頭
- **2行に割るのは文節の頭だけ**（`_breaks`。fugashi で単語に分ける）。名詞が続く所
  （「受け取り｜手」）・「〜こと」「〜てある」「〜という」の手前・かぎかっこの中では割らない。
  文字数で割ると「ライバルどう｜し」「「カ｜ルテル」」になった
- 言葉の切れ目で2行に入らないときだけ、字を 74 → 66 まで小さくする

### 字幕が読める速さ

日本語の字幕は **1秒あたり 4〜6文字**が目安。これを超えると、
聞けても読めない（読み終わる前に次の画面へ行く）。

`python -m danmen.movie` が**行ごとに字／秒を出し、6.5 を超えた行を挙げる**。
挙がったら、台本を短くするか、2行に割って画面を1枚足す。

### 音と動き（2026-10-08 に入れた）

**BGM は入れない。**「歴史の地層」が 2026-10-04 に同じ判断をしている。
代わりに、場面の切り替えにだけ短い音を**声よりずっと小さく**置く（`danmen/sfx.py`）。
音は合成するので、素材のライセンスも課金も要らない。

| いつ | 音 | 大きさ |
|---|---|---|
| 画面が変わる | 紙が滑る「シュッ」 | 0.15 |
| 節の頭 | 低い「ゴゴッ」 | 0.20 |
| 聞き手が驚く | 小さな「ポン」 | 0.07 |

**気づかれるほど鳴らすと、うるさい動画になる。**
画面が速く変わるときに鳴らしすぎないよう、3秒の間を空ける。
驚きの「ポン」は20秒の間を空ける。

**画面の切り替えには 0.1 秒の重なりを挟む**（`FADE_FRAMES = 3`）。
パッと切り替わると、静止画を並べただけに見える。
中間のコマを3枚だけ作るので、手間はほとんど増えない。

**声の間は一律にしない**（`gap_after`）。

| 行 | 間 |
|---|---|
| 問いで終わる（「〜ですか。」「〜でしょうか。」） | +0.26 秒。受け手が考える間 |
| 次が聞き手の驚き | −0.14 秒。かぶせ気味のほうが自然 |
| 短い言い切り（12字以内） | +0.10 秒 |
| そのほか | 0.28 秒 |

### 数字の読み（2026-10-08 に直した）

**読み上げるときだけ、数字を漢数字に直す。字幕は算用数字のまま。**（`danmen/reading.py`）

AivisSpeech は「175円」を単独なら正しく読むが、**単位のあとに数字が続くと
桁として読めなくなる**。

| 書き方 | 読み |
|---|---|
| `1リットル175円` | イチリットル**イチナナゴ**エン ← 誤り |
| `1リットル、175円` | イチリットル・ヒャクナナジュウゴエン |
| `1リットル百七十五円` | イチリットル・ヒャクナナジュウゴエン ← **これを使う** |

読点を入れると間が増えて不自然になるので、**漢数字に直す**。
小数点も「点」にする（`25.1` はそのままだと「ニジュウ**ゴオ**テン…」と伸びる）。

```
175      → 百七十五          ヒャクナナジュウゴ
25.1     → 二十五点一        ニジュウゴテンイチ
1974     → 千九百七十四      センキュウヒャクナナジュウヨ
1.5兆    → 一点五兆          イッテンゴチョオ
4万      → 四万              ヨンマン
```

動画を作るときに**読み用のテキストが出る**ので、目で確かめられる。

### 冒頭の10秒（2026-10-08）

**ここで離脱が決まる。** 型の先頭に「冒頭」を足した。

1. **いちばん強い数字を、理由を言わずに出す**（`fullscreen.number`）
2. **その数字から問いを立てる**（`screens.title`）。これが題名になる

冒頭だけは1枚5秒でよい（掴みなので、ゆっくり出さない）。
点検の下限（6秒）も冒頭には当てない。

### 台本と通しの点検

```bash
python scripts/audit_script.py 台本.yaml
```

119枚を人が目で見るのは無理なので、機械で見る。

- 同じ語尾が3回続いていないか（「〜です。」が並ぶと耳に付く）
- 聞き手の相づちが単調でないか
- **専門の言葉が、説明なしで出ていないか**（「暫定税率」「一般財源」など。
  近くに「とは」「つまり」があれば説明しているとみなす）

- ひとつの画面が全体の34%を超えていないか

  左右が大きく空いて小さく見えた。レシートは 1240 幅に直した
- **板の下 280px は空ける**（字幕の場所）
- ffmpeg は `imageio_ffmpeg` 同梱のものを使う。別に入れなくてよい
- 30秒で 1.6MB。30分なら 100MB 前後の見込み

## 投稿する（2026-10-08 に作った）

```bash

python scripts/post.py screen 台本.yaml                    # 動画を見せた控え（**関門**）

```

**歴史の地層（`chiso/upload.py`）から写した。** 向こうで踏んで直したことが全部入っている。

- **関門を外さない。** `upload` は、動画をユーザーに見せて OK をもらい `screen` を打った
  控え（`approvals/<台本>.screened.json`）が無いと動かない。動画を作り直すと
  sha256 が変わるので確認もやり直し

### 素材の置き場（リポジトリには入れない）

`output/yononaka-danmen/assets/` の下に置く。workspace は public なので。

| 置き場 | 中身 | 出どころ |
|---|---|---|
| `icons/` | 3Dアイコン **41点** | **Gemini で自作**（Chrome 経由）。`danmen/icons.py` から名前で呼ぶ |
| `photos/` | 実写 24点 | Pexels（商用可）。`sources.json` に出典 |
| `wikimedia/` | 資料写真 | Wikimedia。`CREDITS.md` が自動で付く |
| `videos/` | 実写動画 6本 | Pexels。背景に敷く |
| `characters/` | 立ち絵 2人・19枚 | Gemini。`danmen/cast.py` から表情の名前で呼ぶ |
| `brand/` | ロゴ | Gemini。40pxまで縮めても形が分かる |
| `geo/` | 世界地図のデータ | **Natural Earth**（パブリックドメイン） |
| `fonts/` | （予備） | 本番は Windows 標準の Noto Sans JP を使う |

**素材を足すときは出典を必ず控える。** Pexels と Pixabay は商用可・クレジット不要だが、
Wikimedia は個別に確認する。

**アイコンを足したら、絵の中の文字を必ず目で見る。** ただし**全部だめなのではない**。

| | 例 | どうする |
|---|---|---|
| **崩れた文字・関係ない名前** | smartphone に「ヘルメット」、toolbox と worker に崩れた漢字 | **外す。** 文字の帯を切り落とすか `AVOID` へ |
| **そのものを表す正しい名称** | 年金手帳の PENSION HANDBOOK、銀行の BANK、定期券の Train Commuter Pass | **使ってよい**（2026-10-09 ユーザー判断「別に言葉入っていてもいいのでは？」） |

絵としてそれらしさを出している文字は、むしろ何のアイコンか分かりやすくする。
外すのは「間違っている文字」だけ。元は `icons/raw/` に置く。
