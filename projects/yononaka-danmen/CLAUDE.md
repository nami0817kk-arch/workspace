# 世の中の断面図

YouTube チャンネル（名前は未決）の動画を作る。**「歴史の地層」の対**として、
過去を縦に掘るのではなく、**いまの世の中を横に切る**。

## コンセプト（2026-10-06 にユーザーと決めた）

- **切る**：毎回ニュースを1つ選び、**表面**（報じられたこと）→ **切る** → **断面**（制度・歴史・数字）
  → **見立て**（なぜそうなったか）の順で見せる
- **画面の主役は自作の断面図**。他人の写真も発言も使わない。権利の心配を構造的に持たない
  （サッカーのチャンネルが抱えている審査の危うさを、こちらは最初から持たない設計にする）
- **題材は固定しない**。その日いちばん多くの人が気にしていることから選ぶ。
  「住宅のチャンネル」「都市のチャンネル」のように題材で縛ると、幅が狭く題材も尽きる

## 「なぜが立つ」の3条件（題材を選ぶ物差し）

1. **結果は報じられたが、理由が説明されていない**（「ガソリンがまた上がった」→ なぜ？）
2. **多くの人が誤解している**（「金利が上がる」→ どの金利？）
3. **日本だけ、あるいは1国だけが異質**（中古住宅が築20〜25年で価値ゼロになるのは日本だけ）

どれにも当たらないものは、どれだけ大きいニュースでも扱わない。

## 扱わないもの

- **政治的な是非**（どちらが正しいか）。数字が何と言っているかまでに留める
- **医療・健康の助言**。審査が厳しく、誤りの責任が重い
- **事件・事故の被害者、死亡記事、芸能の私生活**
- **投資助言**。事実の提示まで

## 素材

| | |
|---|---|
| 図・グラフ・断面図 | **自作**（このチャンネルの主役） |
| 地図 | Natural Earth（パブリックドメイン）／OpenStreetMap（出典表示） |
| 写真・映像 | Pexels・Pixabay（無料・商用可）／Wikimedia Commons |
| 衛星写真 | NASA（パブリックドメイン） |

**Google マップは使わない**。動画で使うには画面に出典を出し続ける必要があり、
ストリートビューは事前申請が要る。毎日出すチャンネルで守り続けるのは事故のもと。

## 数字と出典

- 画面の下に**出典を出し続ける**（「国土交通省『○○』p.12」まで）。これが他の解説チャンネルとの差
- **価格や料金には「2026年10月時点」と必ず添える**。1年後に嘘つきにならないため
- 原典に当たる手順は `primary-source-research` スキルに従う。記事の言い換えを根拠にしない

## 題材を拾う

```bash
python scripts/gather.py --out research/candidates/<日付>.json
```

ニュースと検索トレンドの RSS を読み、「なぜが立つ芽」を含む見出しだけを拾う。
扱わないもの（事件・死亡・芸能）はここで落とす。**○× はユーザーが付ける**（番号だけ振って出す）。

## まだ決まっていないこと（ユーザーと決める。勝手に決めない）

- チャンネルの正式名と運営名
- 語り手（「歴史の地層」のような掛け合いにするか、1人か。声は誰か）
- 1本の尺と1日の本数（目安は20〜30分・1日1本）
- 台本の型、画面の作り、サムネイルの型
- 台本確認・動画確認の関門の入れ方（他の2チャンネルと同じく**必ず入れる**）

## チャンネル名（2026-10-06 に決めた）

**世の中の断面図｜ニュースを数字で切る**（運営：のこぎり社）

「歴史の地層（つるはし社）」が**掘る**のに対し、こちらは**切る**。道具の名前で運営名を揃える。

## 台本の型（1本 **30分**・9つの節）

| 節 | 名前 | 長さの目安 | 中身 | 図 |
|---|---|---|---|---|
| 00 | **表面** | 2分 | 報じられたことをそのまま出す。聞き役が素朴に反応する | 見出しの板 |
| 01 | **問い** | 30秒 | 「なぜ？」を立てる。**これが題名になる** | なし |
| 02 | **一の断面** | 4分 | いちばん分かりやすい切り口。数字を出す | 積み上げ |
| 03 | **二の断面** | 5分 | いつ、誰が、なぜそう決めたか | 年表 |
| 04 | **三の断面** | 5分 | 誰が払い、誰が受け取っているか | 流れ図 |
| 05 | **四の断面** | 4分 | **世界と比べる**。日本だけなのか | 比べる図 |
| 06 | **よくある誤解** | 4分 | 広まっている説を1つだけ潰す。人ではなく説を扱う | 比較の図 |
| 07 | **見立て** | 4分 | なぜそうなったかを**番号で**出す | まとめの板 |
| 08 | **締め** | 1分30秒 | 次回の問いを聞き役が一言で振る | なし |

2026-10-06 にユーザーが「1作30分」と決めた（18〜22分から変更）。
伸ばすために話を薄めるのではなく、**「世界と比べる」節を足して中身を増やす**。
収益化の新基準（2027-02 から長尺 8,000 時間）でも長尺のほうが効く。

### 決まり

- **節ごとに図を1つ**（05 と 07 を除く）。図が作れない節は、その節を作らない
- **出典は画面の下に出し続ける**。数字を言う行では、必ず出典を画面に出す
- **価格・料金には「2026年10月時点」を添える**
- **聞き役を受け身にしない**。驚くだけの返しは1節に2回まで。
  代わりに**予想して外す・誤解の側から疑う・自分の暮らしに置き換える・節の終わりで言い直す**
- **締めは必ず聞き役**が次回の問いを振る（「〜って、なんでなんでしょうね？」）
- **1本に1つの問いだけ**。2つ立てたくなったら、2本に割る

### 台本の書き方

`scripts/_template.yaml` を写して使う。節番号のキーは `id`（`no` は YAML で「偽」になるので使わない）。行の話者に括弧で強さを付けられる（`語り(強)`）。

## 題材の決め方（2026-10-06 に固めた）

勘で選ばない。**測れるもので点を付けて並べる**。

### 手順

```bash
python scripts/gather.py --out research/candidates/<日付>.json   # 集める・選り分ける
python scripts/pick.py research/candidates/<日付>.json            # 点を付けて並べる
python scripts/demand.py <言葉> --deep                            # 気になったものを深く見る
```

### 点の付け方（23点満点）

| 物差し | 満点 | 測り方 | なぜ見るか |
|---|---|---|---|
| **検索の広さ** | 5 | YouTube の補完が何件出るか | 関心が広いほど、届く人が多い |
| **問いの濃さ** | 5 | 補完のうち「なぜ・いつ・とは・どうなる」が占める割合 | 知りたがられている＝説明する価値がある |
| **原典の堅さ** | 5 | 当たるべき原典が公的機関（省庁・法令・統計）か | 出典を出せない題材は作らない |
| **30分もつか** | 5 | 断面が4つ立つか（見出しを出させて数える） | 1つしか立たないなら尺がもたない |
| **新しさ** | 3 | 今日のニュース・はてブ由来なら加点 | 今日見る理由になる |

### 見ないもの

- **他人の動画の再生数**（2026-10-06 ユーザー指摘）。
  再生数を基準にすると**既にある動画の後追い**になる。再生数が多い＝すでに誰かが答えている。
  見るのは「人が何を知りたがっているか」だけ

### 検索語の決め方

judge が候補ごとに**短い検索語を3つ**出す（1〜2語、長くても8文字）。
それぞれで補完を引き、**いちばん反応があったもの**を採る。
人は長く打たないので、語が長いと補完が出ず、関心が無いように見えてしまう。

### 最後はユーザーが決める

点は**並べ替えのため**であって、決めるのはユーザー。番号を振って出し、○× を付けてもらう。

### 週の決め方（2026-10-06 ユーザー決定「毎週土曜日に一週間の題材を決める」）

毎日選ばない。**土曜に7本まとめて決める。**

```bash
# 土曜。候補を集めて点を付け、上位20件を番号付きで出す
python scripts/weekly.py

# ユーザーが7つ選んだら
python scripts/weekly.py --fix 3,7,1,12,5,9,14
```

決めた予定は `research/plan/<年>-W<週>.json` に入る。月〜日の7日ぶん。

**曜日の割り当てには理由がある。**

| 置く場所 | 題材 | なぜ |
|---|---|---|
| **週の前半**（月・火…） | ニュース・はてブ由来の**時事** | 1週間で古くなる。早く出す |
| **週の後半**（…土・日） | 検索の補完から来た**常在の疑問** | いつ出しても効く。急がない |

候補の一覧では `[時事]` `[常在]` の札を付けて出す。

**時事を「新しさ」の点で優遇しすぎない。** 置く曜日で解決するので、点は3点のままにしてある。

## 画面の作り（2026-10-06 に固めた）

参考にした「大人の学び直しTV」の画面を実際に見て分解し、寄せた。
**差は配置ではなく、要素の質と種類にあった。**

### 画面の決まり

| | |
|---|---|
| **背景** | 実写の写真か動画を**暗く落として**（明るさ0.33）敷く。上下に暗い被せを入れる |
| **書体** | **Noto Sans JP の可変フォント**（Windows 標準の `NotoSansJP-VF.ttf`）。見出しと字幕は 900 |
| **字幕** | 画面の5分の1を占める大きさ（74px）。**黒の太い縁（17px）だけ**。数字は明るい金（255,206,72）、ほかは白 |
| **図** | 白い板に載せ、**金の細線**と落ち影をつける |
| **立ち絵** | 右下に小さく（胸から上）。縁をうっすら光らせて背景から浮かせる |
| **ロゴ** | 左上。チャンネル名と一言を添える |
| **出典** | 画面のいちばん下に出し続ける |

**字幕の縁は、縁を全部描いてから本体を描く**（1文字ずつ重ねると、次の字の縁が前の字を潰す）。

**数字に金の縁を重ねない**（2026-10-07）。金の文字の上にさらに金の縁を描いていたため、
輪郭がぼやけ、黒の縁もその分細くなって読みにくかった。黒い太い縁だけにして、
金そのものを明るくする（板の中の金より明るい 255,206,72）。

**写真の選び方で守ること。**

- **国や地域を指す画面には、その国の写真を使う**（「ドイツ」の面に日本の住宅を敷かない）。
  無ければ写真を敷かず、濃紺の地のままにする
- **実在の店や企業の看板が大きく写る写真は、その企業が題材のときだけ**。
  そうでないと「この会社の話」と誤解される
- **左右に並べる画面は、2枚の明るさを揃える**（`versus` は平均の明るさを測って自動で揃える）

### 使える部品（全 62 種）

**どれを使うかは「何を見せたいか」から引く。** モジュールの名前
（`charts2` `charts4` …）からは中身が分からない。

```bash
python scripts/which.py           # 全部を用途ごとに
python scripts/which.py 内訳      # その言葉に当たるものだけ
python scripts/which.py --check   # 索引と実物がずれていないか
```

|---|---|---|---|

| **比べる（2つ）** | `news4.versus` | 日本と1国を強く対比する | icon_compare／before／convert |
| **比べる（3つ以上）** | `news.ranking` | 各国・各項目を並べる | verdict／numberline／table／compare |
| **ひとつの数字を強く** | `news.big_number` | 節の山場で数字を出す | number／reaction／hero |
| **時間** | `figures.timeline` | いつ決まったかを見せる | schedule／line／change |
| **流れ・関係** | `charts6.icon_flow` | お金が誰から誰へ動くか | relation／flow |
| **並べる・まとめる** | `charts6.icon_list` | 見立ての節で理由を並べる | points／board／bars／icon_stats／stats |
| **判定・条件** | `charts5.flowchart` | 「あなたは当てはまるか」を辿らせる | checklist／matrix／calc／gauge／thermometer |

| **節の区切り** | `screens.chapter` | 何節目で何を見るか | recap／talk／qa |

**同じことができるものが複数あるときは、「まず使う」を使う。**
ほかのものは、それが合わないときの控え。索引の実体は `danmen/catalog.py`。

**図や画面を足したら、索引にも足す。** `--check` がずれを見つける。

#### 仕上げに掛けるもの

| | | |
|---|---|---|
| `texture.finish(im, 'panel')` | 紙の目・わずかな暖色 | 板に載せる図に |
| `texture.finish(im, 'screen')` | 粒子・四隅の落ち・暖色 | 全画面に |
| `annotate.apply(im, marks)` | 手で書き込んだ強調9種 | 質感のあと、1画面に2つまで |
| `sequence.grow(fn, fig)` | 項目が1つずつ増える列 | 語りに合わせて出す |
| `sequence.reveal(im, marks)` | 書き込みが1つずつ増える列 | 同上 |

**掛ける順は「質感 → 書き込み」。** `finish` は1回だけ（二度掛けると汚れる）。

#### 立ち絵の決まり

- 読み込みは `danmen/cast.py`。`katari`（語り手）と `kikite`（聞き手）の2人。
  表情は名前で呼ぶ（`odoroki` `nattoku` `setsumei` …）。絵が無い表情は近いものに自動で寄る
- **`aside` の吹き出しは立ち絵の真上に出る。** 横に出すと図の上に乗るため。
  だから図は画面のどこに置いてもよい
- **`reaction` は1本に2回まで。** 毎回使うと安く見える
- 画面に出す高さは `talk` と `reaction` が腰から上、`aside` が胸から上。
  背の違いを作らないよう、2人とも同じ高さにしてある

**立ち絵の白い縁を抜く。** Gemini で作った絵は背景を抜いてあるが、抜ききれていない。
アルファが2値で、**輪郭の外と髪の束のあいだに白が残る**。暗い画面に置くと人の周りが白く浮く
（2026-10-08 にユーザーが指摘）。

```bash
python scripts/fix_cast_white.py          # どう変わるか見るだけ
python scripts/fix_cast_white.py --write  # 書き換える（元は characters/raw_white/ へ）
```

3つを順に当てる。**立ち絵を足したら、この道具を通してから使う。**

| | 何をするか | 値を外すと |
|---|---|---|
| 外の白を抜く | 画像の縁から、白と透明を辿って透明にする | — |
| 髪の白を埋める | **周りが暗い**白（明るさ230以上・周り175未満）を、周りの色で塗る | 周りの閾値を上げると顔にまだらが出る。白の閾値を下げると髪のつやが消える |
| 縁を2px削る | 輪郭の外に絵として描かれたグラデーションを隠す | 4px 以上だと髪が痩せる |

**上から何％という範囲で区切る方法は失敗した。** シャツの位置が人によって違い、
白いシャツに縞が出た。「周りが暗いか」で見るほうが確実。

**残りを追いかけるときは、実際に使う大きさで見る**（2026-10-08）。
元の絵は高さ 1246px だが、動画では 400px（左右の下）か 190px（ワイプ）。
4倍に拡大すると髪の束の内側に白黒の縞が見えるが、**使う大きさでは見えない**。
これを消そうとして9通り試し、どれも顔かシャツが壊れた。

| 試した方法 | どうなったか |
|---|---|
| かたまりの大きさで分ける | 顔とシャツが壊滅。白いかたまりが783個あり、肌のハイライトも拾う |
| かたまりの太さで分ける | 変わらない。縞とシャツが細い通路でつながって1つのかたまり（16,733画素） |
| 周りが髪である割合で見る | 境界線だけ選ばれ、縞は外れる |
| 髪の塊の穴を埋めて内側を消す | 24,325画素。顔も髪に囲まれているので顔まで入る |
| 塗る元を髪色だけにする | 顔にまだらが出た |
| 輪郭の帯で白いほど透明に | 効果なし（白は帯の外） |
| 髪のそばの無彩色を消す | シャツの縁がギザギザに |
| 髪に接する輪郭だけ深く削る | 外周の白は消えるが、髪の内側の縞は残る |

**縞の正体は、毛先と背景が1pxおきに交互に並んだところ**（画素を測って確認）。
アルファが2値なので、半透明であるべき毛先が白黒の縞として描かれている。
画像処理で分けられる種類のものではない。

**立ち絵を足したら、ファイル名と中身が合っているか目で見る。**
`katari_nattoku` は中身が聞き手だった（`characters/raw/` に退避済み）。

## 節の中で画面がどう切り替わるか（2026-10-07 に固めた）

**図を1枚作って4分出しっぱなしにすると、どれだけ作り込んでも間が持たない。**
ニュース番組は10〜20秒で画面が変わる。ただし毎回ぜんぶ差し替えるのではなく、
**同じ図の上に1つずつ増えていく**。語りが「ここが」と言う所で赤が付く。

### 増やし方は2つ（`danmen/sequence.py`）

| | |
|---|---|
| `grow(fn, fig)` | **項目が1つずつ増える。** レシートの行、箇条書き、年表、アイコンの並び |
| `reveal(im, marks)` | **書き込みが1つずつ増える。** 蛍光ペン → 丸 → 矢印 の順に足していく |

**`grow` は最終的な項目数を図に渡す（`slots`）。** これが無いと、増えるたびに
既に出ている項目が動いて、映像で跳ねて見える。図の側は `slots` を見て、
列の幅と板の高さを最初から最後の形にしておく。

### 節ごとの画面の数（`sequence.PATTERNS`）

| 節 | 長さ | 画面 | 1枚あたり |
|---|---|---|---|
| `surface` | 120秒 | 8枚 | 15秒 |
| `question` | 30秒 | 2枚 | 15秒 |
| `cut1` | 240秒 | 17枚 | 14秒 |
| `cut2` | 300秒 | 21枚 | 14秒 |
| `cut3` | 300秒 | 20枚 | 15秒 |
| `world` | 240秒 | 15枚 | 16秒 |
| `myth` | 240秒 | 14枚 | 17秒 |
| `reading` | 240秒 | 15枚 | 16秒 |
| `close` | 90秒 | 7枚 | 13秒 |

**1本ぶんで 119 枚。** 作ってみるまで「図が41種あれば足りる」と思っていたが、
実際には**1本で100枚以上の画面を組む**ことになる。だから型が要る。

### 決まり

- **1枚あたり6〜22秒。** 22秒を超えたら画面が足りない（`sequence.check()` が言う）
- **最初から全部出さない。** 1行だけ出して、話しながら増やす。

### 日本語の組版（2026-10-07 に直した）

折り返しは **`typo.wrap` に一本化**した。文字数だけで切ると**行頭に「、」が来る**。

### 立ち絵（2026-10-07）

**口パクはやらない。** 画像処理で口を開ける方法を3通り試したが、どれも
線画＋淡い彩色の絵のなかで口だけが浮いた。

1. 楕円をベタ塗り … 口だけ色が濃く浮く
2. 唇の形を描く … 輪郭線を入れても、のっぺりして浮く
3. 口の線より下を切り出して下げる … 四角い帯が出て、あごが切れる

口の形・唇の色・線の太さが、人物と表情ごとに違う。描き足す方法では追いつかない。
**違和感のある口パクは、無いより悪い。**

代わりに、**しゃべっている人は縁をうっすら光らせる**。
誰がしゃべっているかはこれで分かる。

**2人とも常に出す。人は切り替えない**（2026-10-08 ユーザー指示）。

最初は `cast:` を書いた行だけ出していて、34秒のうち7秒しか人が写らなかった。
次にしゃべっている人だけを出したが、**話者が変わるたびに画面の人が入れ替わり**、
そちらに目が行って落ち着かなかった。

置き方は**2つ**。どちらも2人とも出す。しゃべっている人は明るく、
**聞いている人は少し暗く小さくなる**（0.72倍・0.90倍）。表情は行の強さから自動で決まる。

| 書き方 | 置き方 | いつ |
|---|---|---|
| `cast: auto` | **左右の下**に2人 | 板に載る図の画面（下 326px が空いている） |
| `cast: wipe 右上` | **箱**に2人（`studio.flip` のワイプと同じ形） | 全画面の様式 |
| `cast: なし` | 出さない | 画面じたいが2人を出すとき（`talk.talk` / `talk.reaction`） |

**ワイプの場所は画面を見て決める**（`右上` `左上` `右下` `左下`）。
全画面の様式は画面いっぱいに描くので、空いている場所が画面ごとに違う。
下に立ち絵を置くと中身と重なる（2026-10-08）。

**全画面の様式は、ワイプのために右上か左上を空ける。**
速報の帯のチャンネル名は左上へ、おさらいの板は左に寄せて幅を 1450 までにした。

| 強さ | 語り手 | 聞き手 |
|---|---|---|
| ふつう | `setsumei`（説明の顔） | 素の顔 |
| 強 | `shinken`（真剣） | `odoroki`（驚き） |
| 特強 | `shinken` | `odoroki` |
| 抑 | 素の顔 | `nattoku`（納得） |

**語り手の「強」は力をこめて話すこと、聞き手の「強」は驚くこと。**
同じ「強」でも意味が違うので、表情の表を人ごとに分けてある。

**板は画面の上半分に、中央に置く。幅は 1740 まで。**
立ち絵が左右の下に2人とも出るので、**下 326px は字幕と立ち絵のために空ける**。

**この 326 は板の縮み方で決めた**（2026-10-08 に実測）。
420 を空けていたときは、高さ 778 の板が 630 にしか置けず **0.81倍に縮み**、
本文 48px が画面上で **38.9px** になっていた。立ち絵を 400 → **320px** に
小さくして 0.93倍まで戻し、本文は 44.7px になった。
3割小さく（280px・ほぼ等倍）も作ったが、誰が話しているか分かりにくく見送り。

**字幕は、3行目を捨てずに字を小さくして2行に収める。**
2人の立ち絵で字幕の幅が狭まったとき、文末が切れていた（74px → 最小 52px まで縮む）。

### 音と動き（2026-10-08 に入れた）

**BGM は入れない。**「歴史の地層」が 2026-10-04 に同じ判断をしている。
代わりに、場面の切り替えにだけ短い音を**声よりずっと小さく**置く（`danmen/sfx.py`）。
音は合成するので、素材のライセンスも課金も要らない。

| いつ | 音 | 大きさ |
|---|---|---|
| 画面が変わる | 紙が滑る「シュッ」 | 0.15 |
| 節の頭 | 低い「ゴゴッ」 | 0.20 |
| 聞き手が驚く | 小さな「ポン」 | 0.07 |

**気づかれるほど鳴らすと、うるさい動画になる。**
画面が速く変わるときに鳴らしすぎないよう、3秒の間を空ける。
驚きの「ポン」は20秒の間を空ける。

**画面の切り替えには 0.1 秒の重なりを挟む**（`FADE_FRAMES = 3`）。
パッと切り替わると、静止画を並べただけに見える。
中間のコマを3枚だけ作るので、手間はほとんど増えない。

**声の間は一律にしない**（`gap_after`）。

| 行 | 間 |
|---|---|
| 問いで終わる（「〜ですか。」「〜でしょうか。」） | +0.26 秒。受け手が考える間 |
| 次が聞き手の驚き | −0.14 秒。かぶせ気味のほうが自然 |
| 短い言い切り（12字以内） | +0.10 秒 |
| そのほか | 0.28 秒 |

### 数字の読み（2026-10-08 に直した）

**読み上げるときだけ、数字を漢数字に直す。字幕は算用数字のまま。**（`danmen/reading.py`）

AivisSpeech は「175円」を単独なら正しく読むが、**単位のあとに数字が続くと
桁として読めなくなる**。

| 書き方 | 読み |
|---|---|
| `1リットル175円` | イチリットル**イチナナゴ**エン ← 誤り |
| `1リットル、175円` | イチリットル・ヒャクナナジュウゴエン |
| `1リットル百七十五円` | イチリットル・ヒャクナナジュウゴエン ← **これを使う** |

読点を入れると間が増えて不自然になるので、**漢数字に直す**。
小数点も「点」にする（`25.1` はそのままだと「ニジュウ**ゴオ**テン…」と伸びる）。

```
175      → 百七十五          ヒャクナナジュウゴ
25.1     → 二十五点一        ニジュウゴテンイチ
1974     → 千九百七十四      センキュウヒャクナナジュウヨ
1.5兆    → 一点五兆          イッテンゴチョオ
4万      → 四万              ヨンマン
```

動画を作るときに**読み用のテキストが出る**ので、目で確かめられる。
