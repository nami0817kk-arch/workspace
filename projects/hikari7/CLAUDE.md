# ひかりの指名（hikari7）

2026-10-04 に題名を「ひかりの七席」から「ひかりの指名」に変えた（デビューは5〜8人で7に限らないため）。App Store の名前は「ひかりの指名：オーディション育成ゲーム」。「アイドル」は使わない（アーティストとして扱う）。フォルダ名・Bundle ID・保存の名前（hikari7_*）は変えない

オーディション番組のプロデューサーになり、練習生の中からデビューメンバーを自分で選ぶ1人用ゲーム（仮題）。
本番は **iOS アプリ**（無料＋広告＋広告を消す買い切り、護送ボートと同じ形）。

**作り（2026-10-02 ユーザー選択「試作を中に組み込む」）**: アプリの外側（広告・課金・保存・ストア対応）は Flutter、
ゲーム本体は `prototype/game.html` をそのまま WebView で動かす。Web のテスト版とアプリは同じ1つのゲーム本体を使うので、
**ゲームの直しは game.html だけ**で両方に効く。アプリとゲームのやりとりは `app/lib/game/bridge.dart`（JS 側は `HStore`・`withAd`・`appPost`）。

## 仕組みの整理とつり合い（2026-10-04 指示「全体的な仕組みを整理して、諸々のバランスも」）

`ABL=talk,event,trait,awaken,bond,combo,crit,feat,center,tone,mission node tool/sim.js` で仕組みを1つずつ切って、最終評価への効き目を測れる。sim は最終評価の内訳（曲／まとまり／ファン／視聴率）も出す。
- 整理前に分かったこと：ファンは遊び方で動かず（naive 71・good 69）、人気を動かせるのはセンターだけ。大きく映すは sim が使っておらず、使っても効き目が小さかった。講評の「厳しく言う」に代償が無い。センターの約束が、ひとりずつ披露する審査で必ず破れる不具合。人気の子を落とすと視聴率が上がる逆向きの得。ふつうのレッスンが何もしない伸びと同じくらい
- 直したこと：約束の不具合と逆向きの得を外す／ふつうのレッスン .3→.5／講評「厳しく」に疲れ＋8、伸びを少し下げる／依頼 3→2点／報われた物語 まとまり・ファン＋3／デビュー組の自信の平均をまとまりに（(自信−50)×.12）／ファンの上限を緩める（230→300）・大きく映す 人気＋5→＋8・センターの人気＋6→＋5／MV は2回目から半分／シーズンを重ねた制作費の上乗せ 最大50→20／魅力を「華」としてプロフィールに出す
- **まとめた（同日、ユーザー指示「二つともまとめて」）**：関わる時間を「話す・出かける・ふたりと話す」の3つに（個別指導は特訓と重なるので外した。差し入れは出かけるの中の1枚）。関係（幼なじみ・ライバルなど）は絆の始まりの値と札だけにし、チームの点・まとまりは絆の深さ（`bondLink`：25で0.5・50で1・75で1.5、`linksIn`）で数える
- **B の2〜7（同日）**：結果に「評価の内訳」（4項目×重み・依頼・難しさ・合計と、コンビ・物語・絆・自信・リーダー・宣伝費・デビュー後の足し分）。デビュー準備で「名前・色・曲名は見た目だけ」と明記。センターは制作会議だけで決める（出来事「センター争い」と相談は次の会議で「志願」の印を付けるだけ。志願の子を選ぶと信頼＋4、選ばないと信頼−6）。特性の効き目を強めた（本番に強い1.07・センターの華1.08・表現の魔術師1.05・緊張しい.92・金1.07）。気質に合う語りかけの得を大きく。目標「最終審査に立ちたい」は記号 final のまま「苦手なことを克服したい」（4能力すべて55以上）に。明るい見た目も確認
- **裏で閉じられたとき**：`hikariPause` が「続きから戻る」印（`hikari7_resume`）を付け、次の起動でタイトルを飛ばす。裏では BGM と声の再生器を手放す
- 結果（ふつう・男女各200）：naive 59・random 70・good 81（整理前 64・70・80）。何もしないと弱く、考える差が広がった。きびしいで random 66・good 76
- 効き目（good から切ったときの下がり方）：大きく映す 約−6、講評・関わる時間 約−4、センター 約−2、特性・気質 ほぼ0（味付け）

## 仕組みのメモ（v12）

- **特性**（`TRAITS`）：パワプロの特殊能力にあたる。良い特性9つ・悪い特性3つ（緊張しい・ケガしやすい・気分屋）。
  最初に良35%・悪30%で持つ。本音を打ち明ける・難しい出来事の成功（25%）・目標達成（50%）で良いものが増え、
  緊張しいはセンター成功か自信85以上のステージで、気分屋・緊張しいは本音で克服する
- **いまデビューしたら**：制作会議で、実力上位6人で今日デビューした場合の評価と、いちばん足りない項目を出す。
  残りの成長は入れない（予想ではない）ので、名前を「予想」にしない
- **相性と絆**：ふたりごとに相性（◎○△、生まれつき・ふたりと話すか同じチームで分かる）と絆（0〜100）。
  絆はふたりと話す（12）・同じチーム（8、勝てば12）・ペア（8）・同室（毎審査6）・ふたりの出来事（5）・仲間割れ（話し合い＋10／放送−12）で動き、◎は1.4倍・△は0.6倍。
  チーム課題では、コンビ＋3・◎で絆40以上＋1・△で絆60未満−1.5 がチームの点に入る
- **ふたりの物語**（`EV.bond`）：絆25・50・75で1場面ずつ進む（通常の出来事とは別枠、1審査に1つ、進みかけのふたりを優先）。
  合う声かけは気質・相性・絆で決まる（相性△で絆50未満は寄り添う、相性◎で絆60以上かつ繊細がいなければ任せる、繊細がいれば寄り添う、負けず嫌い同士かライバルなら厳しく、ほかは任せる）。
  3場面で2回以上合えばコンビ結成（10種、`COMBO`）：ふたりとも急成長し、3回とも合えば特性も付く。ステージ×1.02、ペアで組むと×1.05、デビュー組のコンビ1組ごとにまとまり＋4（3組まで）・ファン＋2
- **覚醒**：ひとりの物語を3場面とも正しく進める（本音で1点足してもよい）と、得意＋10・ほか＋3・金色の特性（ステージ×1.05）
- **図鑑**：覚醒した物語20種・コンビ10種をシーズンをまたいで記録。実績は20個
- **エンドロール**（`makeFuture`・`vEnding`）：デビュー後1か月の結果の前に、グループの10年の年表（評価・まとまり・コンビで分岐）、
  メンバーのその後（覚醒・物語の結末・コンビ・リーダー）、スタッフロール（出演・ともに戦った練習生）を流す。
  年表は結果に入った時点で1回だけ作り `S.future` に残す。結果の画面からもう一度見られる。動きを減らす設定の端末では流さずに並べる
- **さくさく**：タイトルの「進み方」。ステージの演出と一人ずつの合格発表を飛ばす。講評や合否など選ぶところは飛ばさない。エンドロールも飛ばす（結果の画面のボタンからは見られる）

## やり込みとアプリ品質（2026-10-03、50フェーズ）

- **心得**（`PERKS`）：得たポイントで7種の強化。使っても肩書きは下がらない（`c.spent` に記録）。振り直し可
- **チャレンジ**（`CHALS`）：縛り6種。A以上で達成、初回+3ポイント
- **今日のオーディション**：日付と男女から種を作り（`seedRng`）、応募者だけ同じにする。乱数はシーズンの作成後に戻す
- **名鑑・特性の図鑑・通算の記録・実績30・肩書き・殿堂の詳細・これまでの曲**：すべてプロデューサー歴（`hikari7_career`）に入る
- **先輩の再登場**：名鑑の先輩が第2審査以降に1度、特別講師として来る（`EV.alumni`）
- **難易度「伝説」**：実績「きびしい局の満点」で解放
- **めずらしい応募者**（`RARES`）：約2割で1人。「注目」の札
- **設定**（`hikari7_set`）：文字の大きさ（body の zoom）・進み方・ステージの見方・効果音（WebAudio で合成）・振動（アプリは HapticFeedback）・明るさ・動きを減らす・記録の消去
- **落ちない作り**：描画は `render()` が `render0()` を包み、失敗したら復帰の画面。場面が変わるたびに一つ前の保存を `hikari7_bak` に残し、壊れたセーブは予備から戻せる。1シーズン1回「この審査を最初からやり直す」（`hikari7_snap`）
- **アプリ側**：起動画面（題字）、上の帯の色をゲームの明るさに合わせる（`theme`）、裏に回る直前に保存（`hikariPause`）、A以上を2シーズン取った人に1度だけレビューのお願い（`in_app_review`、出すかどうかは iOS が決める）

## BGM と台詞の声（2026-10-03 ユーザー選択「BGMは audiogen で作って同梱・セリフは事前に録って同梱」）

- **BGM**：title（タイトル・準備・デビュー後）／practice（会議・レッスン・会話）／night（出来事・夜）／stage（本番）／judge（合否・発表）／ending（エンドロール）。
  場面との対応は game.html の `BGM_OF`。音量は設定の「BGM」（切る・小・中・大）
- **声**：「」の中が固定の台詞だけ（名前が入る台詞は録れない）。台詞のキーは FNV-1a（`voiceKey` と `make_voice.key_of` が同じ値を出す）。
  練習生ごとに、同じ男女の4つの声から1つ（`t.vo`）。会話の結果・話を聞いた一言・出来事の結果・合格のひと言は自動で読み、面談・講評・別れ・応募のひと言は🔊を押すと読む。
  **台詞を足したり変えたりしたら `python tool/make_voice.py` を回す**（無い声は鳴らないだけで、壊れはしない）
- **使っている声と規約**（2026-10-03 に各規約を確認。どれも申請不要、クレジットが必須）

  | キー | 話者 | 気をつけること |
  |---|---|---|
  | f1 | 春日部つむぎ | ゲーム・別キャラの声での利用は FAQ で明記して可 |
  | f2 | 冥鳴ひまり | 別キャラの声も可 |
  | f3 | 雨晴はう | 別キャラの声も可。再生時に高さ・速さを変えない（合成のときに決める） |
  | f4 | 九州そら | クレジットを書かないと商用は有料契約。必ず書く |
  | m1 | 白上虎太郎 | VirVox 規約。クレジットを外さない |
  | m2 | 玄野武宏 | 同上 |
  | m3 | 剣崎雌雄 | 「VOICEVOX」と「剣崎雌雄」の両方を書く |
  | m4 | 黒沢冴白 | VirVox 規約 |

  青山龍星は「企業が関わる場合は事前確認」があるので使わない。
  クレジットは「VOICEVOX:話者名」の形で、設定画面・エンドロール・App Store の説明に書く（架空の練習生の名前では書かない）
- **アプリ**：Flutter の audioplayers で鳴らす（`lib/game/game_audio.dart`）。消音スイッチに従う。裏に回ったら止める。
  ゲームからは `{"type":"bgm","k","vol"}` `{"type":"voice","f":"f1/0a1b2c3d"}`。決めた曲名・形以外は鳴らさない（bridge で検査）
- **Web 版**：組み立てのときに `app/assets/audio/` を `build/web/audio/` に写す。ブラウザは最初に押すまで音を出せないので、最初のクリックで鳴り始める

## 文章の決まり（2026-10-03 指示「中身の品質を優良レベルに」）

- **つながり**：出来事・お出かけで起きたことは、その審査の本番の描写で1行拾う（`EV_CB`・`OUT_CB`・`cbLine`）。点と食い違う言い方は出さない（良い話のあとに低い点、など）。見どころには、つながりのある子を2人まで入れる。**出来事を足したら `EV_CB` にも足す**
- 気分のひと言・相談の切り出し・雑談への返しは、同じ子でも審査ごとに回る（配列。`moodLine`・`reqText`）。文字列でも配列でも読めるようにしてある
- **個性**：練習生ごとの口癖・出身・学生時代・家族・夢を、本番の入り（口癖、2割強）・視聴者のコメント（出身地・学生時代・実家）・合格のひと言（口癖、2割5分）・エンドロール（夢がかなったか・家族のその後 `FAM_FUT`）に織り込む
- **前回のあらすじ**（`makeStory`・`S.story`）：合否を決めたときに、1位・覚醒・人気上位の脱落・大きな伸び・センターの不振から3行まで作り、次の審査の制作会議の頭に出す。審査名はもともと「」付きなので `qName` を通す（2026-10-03 に「「チーム課題」」と二重になった）
- 文を足したら `node tool/texts.js` を回す。2026-10-03 に配列の入れ子で「undefined」が画面に出たのを、これで見つけた

## TestFlight の試遊の直し（2026-10-04）

- **描き方**：同じ場面の中の操作では、画面を作り直さず差分だけ直す（`sceneKey`・`morphKids`）。場面が替わったとき（`sceneKey` が変わる）だけ作り直す。顔の絵の読み直しと動きのやり直しが「読み込み直し」に見えていた
- **明るさ**：ステージの見た目の背景を明るく、板を一段明るい紫に
- **レッスン**：プルダウンをやめ、歌・ダンス・ラップ・表現・休養・特訓のボタンの列（`trpick`）

## ユーザビリティの決まり（2026-10-03 指示「ユーザビリティの向上を本格的に」）

- **進むボタンはどの画面でも下の固定の帯**（`.foot`）。本文の最後に置いたボタンも、`render0` が下の帯へ移す（evnext・tocrit・tojudge・nightok・nextround・toprep・talkback）。新しい画面を作るときもこの形にする
- **ボタンの文言は行き先どおり**（例：相談がある日は「本番の夜へ」。`nextLbl`）。足りないときは「あと n人選ぶ」
- **取り返しのつかない操作は2回押し**：つづきがあるときの新しく始める・今日のオーディション、シーズンをやめる、再審査（動画）、復活枠、最後の一枠、本番の途中で結果へ、記録の消去。消す前に `keepBak` で予備へ写し、タイトルから1回だけ戻せる
- **まとめて決められる所は1回で**：合否「出来の上位から選ぶ」、書類審査「見えている力で残りを埋める」。決めるのはプレイヤーのまま
- **上限で押したら理由を出す**（toast と振動）。押せない理由は title ではなく画面に書く
- **画面の動き**（2026-10-03「有料アプリレベル」）：合格発表は暗い舞台で1人ずつ光を当て、呼ばれた子が下の席に並ぶ（`.cstage`・`.crev`・`.cseats`）。審査の中で場面が替わると0.9秒のアイキャッチ（`eyecatch`・`EYE`、押す操作は邪魔しない。さくさく・動きを減らす設定では出さない）。画面に入るときは上から順に、シートは下から
- **ノベルに見せない**（2026-10-03 指摘「ただのノベルゲームに見える」）：レッスンのあとに結果画面（`vLres`・`S.lres`、伸びた分を金色のゲージで、大成功は伸び5以上）。会話・出来事の結果には信頼・自信・疲れのゲージ（`gauges`）。上の帯は制作費・視聴率の札と、審査の中の段階（会議〜合否）。数字の変化は文で書かずにゲージと札で見せる
- **タイトル**（2026-10-03 指摘「TOP画面がしょぼい」）：全面の写真・大きな題字・七つの席（真ん中だけ金色）・メニュー（つづきから／新しいシーズン／記録と今日の挑戦／設定）だけ。シーズンの設定は `vTitleNew`、記録・心得・今日のオーディションは `vTitleRec`（`ui.tsub`）。ゲームの画面に入ると `header()` が `ui.tsub` を戻す
- **ステージの見た目**（2026-10-03 指摘「他の画面もしょぼい」）：既定の見た目は `theme:'stage'`（暗い配色＋場面ごとの写真を `body.stg::before` に敷く。場面は `body[data-ph]`、写真の対応は CSS）。札は半透明の暗い板、上と下の帯はすりガラス。設定の「画面の見た目」で明るい・暗い・端末に合わせるも選べる。前に「端末に合わせる」で保存していた人は1回だけステージへ移す（`thv`）
- 文字は12px 以上。新しい部品の class 名は、既存と重ならないか grep してから付ける（2026-10-03 に .flow・.chips・.hl がぶつかって崩れた）
