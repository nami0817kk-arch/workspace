# 動画の質を上げる

2026-09-07 に、公開済みショートの視聴者エンゲージメントが
**「視聴を継続 9.4% / スワイプして消去 90.7%」** だったところから始めた作業の記録と、
残っている手当て。

## 分かっていること

先頭フレームを抜いて見たら、**最初の2.6秒が静止したタイトルカード**だった。
被写体も動きもなく、誰も喋っていない。音を測るとこうなっていた。

| 区間 | 平均音量 |
|---|---|
| 冒頭1.5秒 | -31.5 dB（BGMだけ） |
| 2.6秒以降 | -18.5 dB（ナレーションあり） |

`titles.intro: 2.6` が本編とショートで共通だったため。本編では話の入口として要るが、
58秒しかないショートでは捨てられる時間になる。

**対処済み**（`shorts.portrait()` でカードと章タイトルを外し、`review` に
「ショートの冒頭」を足した）。詳細はコミット 274757b。

## 残っている2つ

どちらも見た目の調整なので、**書き出して目で見るまで終わりにしない**。

### 1. 写真が小さい（優先）

縦1920pxの画面で、被写体が中央の小さな枠に収まっている。実測した公開済みの
ショートでは、写真の幅が画面の3割ほどしかなかった。縦画面は顔を大きく見せるのが定石で、
**サムネイルに顔を必ず入れる**という既存の方針とも揃わない。

- 効いているのは `render._picture` の `max_h = slot_height * 0.72`。
  縦型では高さ側が先に頭打ちになり、幅 `0.62` を使い切っていない
- **横型の値を触らない。** 本編の画面設計は変えない。縦型のときだけ比率を上げる
- 上げすぎるとテロップ・確度バッジ・章ラベルと重なる。**重なりは数値では分からない**ので、
  必ず書き出して確かめる
- 確かめ方は下の「見て確かめる手順」。0.72 → 0.85 → 0.95 のように動かして、
  重なりが出る手前で止める

### 2. 「オープニング」という内部ラベルが左上に出ている

`render._draw_scene_title` が節の名前をそのまま画面に出している。本編では章の
目印になるが、ショートでは「オープニング」という**制作側の言葉**が一等地に出る。

- ショートは2節しか無い（冒頭＋1節）ので、章ラベルの役目がそもそも薄い
- 消すか、本文側の節名（「監督は何と言ったか」など）だけ残すかは、実際に見て決める
- 日付（右上）も同じ話。残すかどうかは一緒に判断する

## 参考チャンネルを見て分かったこと（2026-09-07）

同じ分野の3チャンネルの冒頭を実際に見た。詳しくは
[`news-sources.md`](news-sources.md) の「参考チャンネルの冒頭を見た」。

- **3チャンネルとも縦型のショートを出していない。** 全部が通常動画で、
  上位2つは1分前後。ショートは参考先の無い独自路線になっている
- 伸びている動画は **0秒目から本編が始まり、動画タイトルと同じ文言が
  画面幅いっぱいの極太文字で出ている**。実写映像が常に動いている
- 最初のカット切り替えは**約3秒**

**上の2つ（写真を大きく・章ラベルを消す）は、この観察と同じ方向を向いている。**
順番を付けるならこうなる。

1. 見出しを太く大きく（画面幅いっぱいまで）。**0秒目から出す**
2. 背景を実写のストック動画にする（`background_zoom: 1.12` で寄りは既に効いている）
3. 写真を大きく
4. 内部の章ラベルを消す

**5チャンネル見て、ショートを出しているところは1つも無かった。**
とくに サッカー知恵袋（登録6,280人・動画84本で**63万回**）は、
登録者の100倍を回している小規模チャンネルの手本。そこも縦型は作っていない。
**「ショートを直す」より前に「ショートを出すか」の判断がある。**

その先の手（今日はやらない）:
- 背景をストック**動画**にする。知恵袋の背景はスタジアムの実写で、試合映像ではない。
  Pexels は動画も配っていて、こちらの `stock` は静止画しか取っていない
- 見出しと本文字幕を**2層**にする（知恵袋はそうしている）
- 早い段階で**数字のカード**を出す（知恵袋は4秒でスコアボードを出す）

## 見て確かめる手順

書き出し（VOICEVOX ENGINE を起動しておく。`--no-tts` だと音の判定ができない）:

```bash
python -m src.cli short scripts/<台本>.md --out <出力先>
```

冒頭4秒を0.5秒刻みで並べた1枚を作って、目で見る:

```bash
python - <<'PY'
import imageio_ffmpeg, subprocess
ff = imageio_ffmpeg.get_ffmpeg_exe()
subprocess.run([ff, "-y", "-t", "4", "-i", "<出力先>/video.mp4",
                "-vf", "fps=2,scale=200:-1,tile=8x1", "-frames:v", "1", "first4s.png"])
PY
```

音の入り方は `review` が見る（`short` コマンドが作った直後にも出る）:

```
! 最初の1.5秒が全体より13dB静かです。…
```

## 判断の前提

- **設定ではなく出来上がった動画を見る。** 原因が何であれ、冒頭で喋っていなければ
  視聴者には同じことなので、点検も成果物側に置いてある
- **無音では判定できない。** カードの裏で BGM が鳴っているため、
  「静かかどうか」は全体との差で見る（既定8dB）
- 直したら**点検に足す**。直すだけだと同じ種類が次の動画でまた出る（CLAUDE.md）


## 本編も比べた（2026-09-07）

ショートだけでなく本編（16:9）も、伸びているチャンネルと並べて見た。
比べたのは **サッカー知恵袋の 63万回・1:57**（登録6,280人・動画84本）と、
こちらの `20260907_messi`（2:51）。8秒おきに画面を撮って並べている。

### 向こうの画面（8秒おき・14枚）

- **全編が実写映像。**静止した図は1枚も無い
- **常に4つの層が乗っている**
  1. 実写（試合・選手・スタジアム）
  2. 映像の上に**○印と矢印の図解**（選手を囲む、パスコースを引く）
  3. 上部に太字の解説テロップ
  4. 下部に**ネット民のコメント**（白い吹き出し。「キックえろすぎ」「規格外すぎ」）
- **8秒おきの14枚が、全部ちがう画面**。同じ絵が続くコマが1つも無い
- 途中でデータ画面（パス成功率89%、統計表）を挟む

### こちらの画面

- 背景は**静止画が2種類**（星空風・ピッチ風）。ずっと同じ
- 画面の主役が**英語の長文引用カード**。日本語訳は下に小さく
- **同じカードが20〜30秒張り付く**。その間、変わるのは下のテロップだけ
- 層は実質2つ（カード＋テロップ）

### 測った数字（出力8本）

| | 尺 | 同じカードが続く最長 |
|---|---|---|
| 本編 | 96〜107秒（messi回だけ171秒） | **21.9〜26.5秒** |
| ショート | 33〜36秒 | **17.7〜23.1秒** |

**ショートは尺の6〜7割が同じ絵。**33秒の動画で23秒動かないものがある。
向こうは8秒で必ず変わる。

### 点検の穴

`review._screen_change` は「テロップ＋カード＋画像」の**組**で見ているので、
**テロップだけ変われば通る**。上の20〜30秒はすべてこの検査を通っている。
画面の主役はカードと背景なので、**カードが続く時間を別に見る**必要がある。

## 改善点（2026-09-07 時点、効く順）

1. **同じカードを20秒出しっぱなしにしない。** 向こうは8秒。
   まず `review` に「同じカードが続く時間」を足して、いま何秒なのかを見えるようにする
2. **英語の原文を画面の主役にしない。** 日本語話者向けの動画で、
   画面の6割が英語の長文になっている。日本語を大きく、英語は添える
3. ~~背景を止めない~~ — **すでに動いている**（`motion.background_zoom: 1.12`）。
   2026-09-07 に「1.0で止めたまま」と書いたのは誤り。`config.py` の既定値だけを見て、
   実際の `config/project.yaml` を見ていなかった。**残る手はストック動画**で、
   Pexels は動画も配っているのに、こちらの `stock` は静止画しか取っていない
4. **層を増やす。** 向こうは「実写＋図解＋解説＋ネット民コメント」の4層。こちらは2層。
   **`reactions` というカードの型は既にあるのに、出力8本のどれにも使われていない**
5. **冒頭を0秒目から始める。** 本編もショートと同じ2.6秒の静止カードで始まっている
   （ショートは対処済み。本編は未着手）
6. **尺を守る。** 型は1〜2分。messi回は2:51で、63万回の動画（1:57）より47%長い

**真似しないもの。**向こうの実写は試合映像で、権利の面でこちらは使えない。
真似するのは**構造**（層の数・切り替えの速さ・図解で見せること）であって、素材ではない。


## 直したあと、もう一度並べた（2026-09-07）

同じ0.5秒あたりの画面を、こちらの本編と参考2チャンネルで横に並べた。

| | 画面 |
|---|---|
| こちら | 抽象的な星空の背景。白い細めの見出しが**左寄せで画面幅の半分**、2行 |
| さっかー情報館（8.7万回） | 実写の練習場。**赤の極太＋黄の縁取り**で画面幅いっぱい、2行。上にチャンネルカード |
| サッカー知恵袋（63万回） | 実写のスタジアム。**白の太字＋黒帯**で画面幅の2/3、2行。下に小さいナレーション字幕 |

**今回の見出しの手当ては縦型（ショート）にしか効いていない。**本編は前のままで、
上の差はそのまま残っている。

### ここから出てくる改善点

1. **本編の見出しを大きくする。** いま 74px（幅1920の3.9%）。参考は見た目で
   6〜7%あり、110px 前後に相当する。**縦型と同じ手当てを本編にも入れる**
2. **見出しが画面幅を使えていない。** 枠は幅の85%あるのに、`balanced_wrap` が
   行の長さを揃えるため2行とも半分ほどで折り返している。**幅いっぱいに流す**か、
   枠を広げるかを選ぶ
3. **色で差を付ける。** フォントは既に太字（Meiryo Bold）が選ばれていた。
   足りないのは太さより**色と縁**。参考は赤＋黄縁、または白＋黒帯。
   こちらは白＋細い黒縁で、暗い背景に沈んでいる
4. **背景が抽象のまま。** 実写クリップを敷く仕組みは入ったが、素材が
   `stadium_night.mp4` の1本しかなく、`stadium.png` を使う節にしか効かない。
   `stock` で背景名ごとにクリップを取る
5. **チャンネルカードが無い。** 参考2チャンネルとも、冒頭0.5〜2.5秒に
   チャンネル名と登録ボタンの絵を出している。こちらは出していない

1〜3は本編の見た目を変える判断が要る（全動画に効く）。4は素材集め。5は新規。


## 1〜4に対応した（2026-09-07）

| 手当て | 内容 |
|---|---|
| 見出しを大きく | 74px → **100px**（幅1920の3.9% → 5.2%）。縦型は係数を 0.70 にして、検証済みの約70pxを保つ |
| 幅を使う | `balanced_wrap` は行数を保ったまま狭い幅で折り返す。**幅を埋めるには折り返しではなく文字を大きくする**しかない |
| 色と縁 | 文字の下に黒帯（63万回のチャンネルと同じ方式）。フォントは既に太字（Meiryo Bold）で、足りないのは太さではなく背景との分離だった |
| 実写の背景 | stadium / night / pitch / studio / tactics の5本を `stock` で取得 |

### つまずいた点

- **`moving_background` は draft 時にしか効いていなかった。** 既に書かれた台本は
  `.png` を指したままで、実写に切り替わらない。`backgrounds.py` へ移し、
  `render` からも呼ぶようにして、書き出しのたびに実写を探す形にした
- **素材の当たり外れは目で見ないと分からない。** `studio` 用に取れたクリップが
  サッカーと無関係な人物の顔のアップで、「まとめ」の背景に使われていた。
  写真と同じで、**機械が通しても必ず目で見る**

### 実写背景のコスト（実測）

| 背景 | 書き出し時間 | 素材 |
|---|---|---|
| 静止画 | **3分52秒** | — |
| 実写クリップ | **4分21秒 〜 5分23秒** | 596MB（切り詰め後） |

+30〜40%。1日9本なら15〜20分の増加。**素材の大きさは効かない。**
時間を食っているのは実写の上にフレームを重ねる合成そのもの（`over_video` 経路）で、
1399MB→596MB に切り詰めても速くならなかった（切り詰めは容量にだけ効く）。

`stock` は落としたクリップを30秒に切り詰めるようにした（再エンコードせず入れ物を
詰め替えるだけ）。背景は節ごとに20秒ほどしか映らないため。
