# 動画の質を上げる

2026-09-07 に、公開済みショートの視聴者エンゲージメントが
**「視聴を継続 9.4% / スワイプして消去 90.7%」** だったところから始めた作業の記録と、
残っている手当て。

## 分かっていること

先頭フレームを抜いて見たら、**最初の2.6秒が静止したタイトルカード**だった。
被写体も動きもなく、誰も喋っていない。音を測るとこうなっていた。

| 区間 | 平均音量 |
|---|---|
| 冒頭1.5秒 | -31.5 dB（BGMだけ） |
| 2.6秒以降 | -18.5 dB（ナレーションあり） |

`titles.intro: 2.6` が本編とショートで共通だったため。本編では話の入口として要るが、
58秒しかないショートでは捨てられる時間になる。

**対処済み**（`shorts.portrait()` でカードと章タイトルを外し、`review` に
「ショートの冒頭」を足した）。詳細はコミット 274757b。

## 残っている2つ

どちらも見た目の調整なので、**書き出して目で見るまで終わりにしない**。

### 1. 写真が小さい（優先）

縦1920pxの画面で、被写体が中央の小さな枠に収まっている。実測した公開済みの
ショートでは、写真の幅が画面の3割ほどしかなかった。縦画面は顔を大きく見せるのが定石で、
**サムネイルに顔を必ず入れる**という既存の方針とも揃わない。

- 効いているのは `render._picture` の `max_h = slot_height * 0.72`。
  縦型では高さ側が先に頭打ちになり、幅 `0.62` を使い切っていない
- **横型の値を触らない。** 本編の画面設計は変えない。縦型のときだけ比率を上げる
- 上げすぎるとテロップ・確度バッジ・章ラベルと重なる。**重なりは数値では分からない**ので、
  必ず書き出して確かめる
- 確かめ方は下の「見て確かめる手順」。0.72 → 0.85 → 0.95 のように動かして、
  重なりが出る手前で止める

### 2. 「オープニング」という内部ラベルが左上に出ている

`render._draw_scene_title` が節の名前をそのまま画面に出している。本編では章の
目印になるが、ショートでは「オープニング」という**制作側の言葉**が一等地に出る。

- ショートは2節しか無い（冒頭＋1節）ので、章ラベルの役目がそもそも薄い
- 消すか、本文側の節名（「監督は何と言ったか」など）だけ残すかは、実際に見て決める
- 日付（右上）も同じ話。残すかどうかは一緒に判断する

同じ分野の3チャンネルの冒頭を実際に見た。詳しくは
[`news-sources.md`](news-sources.md) の「参考チャンネルの冒頭を見た」。

- **3チャンネルとも縦型のショートを出していない。** 全部が通常動画で、
  上位2つは1分前後。ショートは参考先の無い独自路線になっている
- 伸びている動画は **0秒目から本編が始まり、動画タイトルと同じ文言が
  画面幅いっぱいの極太文字で出ている**。実写映像が常に動いている
- 最初のカット切り替えは**約3秒**

**上の2つ（写真を大きく・章ラベルを消す）は、この観察と同じ方向を向いている。**
順番を付けるならこうなる。

1. 見出しを太く大きく（画面幅いっぱいまで）。**0秒目から出す**
2. 背景を実写のストック動画にする（`background_zoom: 1.12` で寄りは既に効いている）
3. 写真を大きく
4. 内部の章ラベルを消す

**5チャンネル見て、ショートを出しているところは1つも無かった。**
とくに サッカー知恵袋（登録6,280人・動画84本で**63万回**）は、
登録者の100倍を回している小規模チャンネルの手本。そこも縦型は作っていない。
**「ショートを直す」より前に「ショートを出すか」の判断がある。**

その先の手（今日はやらない）:
- 背景をストック**動画**にする。知恵袋の背景はスタジアムの実写で、試合映像ではない。
  Pexels は動画も配っていて、こちらの `stock` は静止画しか取っていない
- 見出しと本文字幕を**2層**にする（知恵袋はそうしている）
- 早い段階で**数字のカード**を出す（知恵袋は4秒でスコアボードを出す）

## 見て確かめる手順

書き出し（VOICEVOX ENGINE を起動しておく。`--no-tts` だと音の判定ができない）:

```bash
python -m src.cli short scripts/<台本>.md --out <出力先>
```

冒頭4秒を0.5秒刻みで並べた1枚を作って、目で見る:

```bash
python - <<'PY'
import imageio_ffmpeg, subprocess
ff = imageio_ffmpeg.get_ffmpeg_exe()
subprocess.run([ff, "-y", "-t", "4", "-i", "<出力先>/video.mp4",
                "-vf", "fps=2,scale=200:-1,tile=8x1", "-frames:v", "1", "first4s.png"])
PY
```

音の入り方は `review` が見る（`short` コマンドが作った直後にも出る）:

```
! 最初の1.5秒が全体より13dB静かです。…
```

## 判断の前提

- **設定ではなく出来上がった動画を見る。** 原因が何であれ、冒頭で喋っていなければ
  視聴者には同じことなので、点検も成果物側に置いてある
- **無音では判定できない。** カードの裏で BGM が鳴っているため、
  「静かかどうか」は全体との差で見る（既定8dB）
- 直したら**点検に足す**。直すだけだと同じ種類が次の動画でまた出る（CLAUDE.md）

## 1〜4に対応した（2026-09-07）

| 手当て | 内容 |

| 見出しを大きく | 74px → **100px**（幅1920の3.9% → 5.2%）。縦型は係数を 0.70 にして、検証済みの約70pxを保つ |

### つまずいた点

- **`moving_background` は draft 時にしか効いていなかった。** 既に書かれた台本は
  `.png` を指したままで、実写に切り替わらない。`backgrounds.py` へ移し、
  `render` からも呼ぶようにして、書き出しのたびに実写を探す形にした
- **素材の当たり外れは目で見ないと分からない。** `studio` 用に取れたクリップが
  サッカーと無関係な人物の顔のアップで、「まとめ」の背景に使われていた。
  写真と同じで、**機械が通しても必ず目で見る**

### 実写背景のコスト（実測）

| 背景 | 書き出し時間 | 素材 |
|---|---|---|
| 静止画 | **3分52秒** | — |
| 実写クリップ | **4分21秒 〜 5分23秒** | 596MB（切り詰め後） |

### 分かったこと

- **話速は変わらない。**ここは直す必要がない（測って初めて言える）
- **構成が逆になっている。**参考は「事実20〜35秒 → 反応25〜45秒」を2往復し、
  **最後は反応で終わる**。まとめも締めの挨拶も無い。こちらは事実が7割で、
  最後の20秒をまとめに使っている
- **反応は短く刻まれている。**1件2〜4秒。名前も「〜という声」も付けず、
  ぶつ切りで並べる。こちらは1件7秒で、4件しかない
- **1行目がタイトルそのもの。**4本とも、最初の2〜5秒でタイトルを読み上げる。
  クリックした人が「これで合っている」と確認できる。こちらは別の導入文から入る

### 引いた線

文字起こしは相手の制作物なので、**測るためだけに使い、リポジトリには残さない**。
言い回しをこちらの台本に持ってこない。ここで使ったのは、秒数・件数・順番だけ。

### 数え違いを1度した

最初に「こちらは26%・4.2件」と書いた。**「解説」を他人の声に数えていた**ためで、
解説はキャスターと並ぶ語り手（`research.SPEAKERS`）であって他人ではない。
正しくは **14%・2.2件**。差は思っていたより大きかった。

## 全部に手を入れた（2026-09-07）

| 手当て | 中身 |
|---|---|
| 1行目 | `to_script` がタイトルをそのまま読む行から始める。問いは読まず画面に出す（前置きが18秒→12秒） |
| まとめ | 答えの1行だけにした。次の焦点の読み上げと締めの挨拶（毎回同じ8秒）をやめた |
| 反応を増やす | `reactions --say` を追加。読み上げに回せる短い書き込み（4〜30字）を、取材メモの `say:` の形で出す |
| 助言 | `draft` が、他人の声の割合・件数・1件の長さを見てヒントを出す |
| 点検 | `review` に「他人の声の量」「反応の刻み」「1行目」「まとめの長さ」の4つを足した |
| 決まり | CLAUDE.md の「引用は数件まで」を「10〜20件・1件30字まで」に変えた（ユーザー判断） |

**縦型には構成の点検を当てない。**ショートは本編から1節を切り出したもので、
割合を測っても元の台本の話にならない。

### ついでに直した

まとめが1行になったので、`_spoken` の不具合が目立つようになった。
「UEFAは重大な暴行と判断した」が **「判断したです」** になっていた。過去形の
「た」「だ」が `PLAIN_ENDINGS` に無く、名詞止めとして扱われていた。

### 決めなかったこと

**最後を反応で終わらせるところまでは行っていない。**参考4本は答えを出さずに
終わるが、このチャンネルは「なぜそうなったかを、2分で」を名乗っている。
答えを消すなら看板の方を降ろすことになるので、まとめは**答え1行**に縮めた。

## 試合映像の代わりを2つ用意した（2026-09-07）

放送映像は使えない。正規のライセンス（SNTV・Reuters・Getty）は年間契約で、
Getty は見送り済み。引用（著作権法32条）は法的には成立し得るが、**Content ID が
先に効いて収益が権利者に移る**ので、収益化とは両立しない。参考チャンネルが
放送映像をそのまま使えているのは、そこを受け入れているか黙認されているかで、
こちらが真似すべき前提ではない。

### 1. 数字の図（`statboard`）

参考の最高再生（64万回）の中身は、試合映像ではなく**走行距離のスタッツ画面**
だった。数字の図は自分で作れて、権利の問題がまったく無い。

```
python -m src.cli statboard assets/stats/run.png --title 走行距離 --unit km     --row ヴィルツ=12.3 --row ソボスライ=11.6 --row マカリスター=10.4
```

- 既定の下地は**自分で描いた明るい芝**。手持ちの `pitch.png` は夜のスタジアムで
  暗く、一覧に並べたとき何の絵か分からなかった（書き出して確認）
- **下の半分は空ける。**サムネの帯と反応の小窓が乗る。最初に作ったときは
  最後の行が帯に隠れていた
- 図の横に `.statboard.txt` を残す。**自分で作った図だという印**と、数字の
  出どころ。`review` の「サムネの顔」はこの印を見て、顔写真の代わりに通す

### 2. Commons の試合写真（`matchphoto`）

実際の試合の写真が CC BY / CC BY-SA である。

```
python -m src.cli matchphoto assets/images/chelsea Chelsea Arsenal
```

- **顔写真とは確かめ方が違う。**人物は特定しない。指定した言葉が写真の説明に
  出てくることと、ライセンスだけを見る。だから台本でも「その試合の写真」とは書かない
- 建物・記章・ロッカールーム・ユニフォームの写真は名前で落とす。実測で
  `Arsenal Chelsea` の1件目が**ロッカールームの写真**だった
- 通信社の透かしが入っている写真がある（実測で FARS）。帯が下3割を覆うので
  多くは隠れるが、**使う前に必ず見る**

確かめた。**0件なら例外**にする（内部APIなので、形が変わったら気づけるように）。

## ショート中心にはしない（2026-09-07 ユーザー判断）

制作側の実測（yt-analytics）:

| | 本数 | 合計再生 | 1本あたり |
|---|---|---|---|
| ショート | 14本 | 3,079 | 220 |
| 本編 | 24本 | **136** | **5.7** |

桁が2つ違うので「ショートだけにする」という案を出したが、**ユーザーが本編を続けると
決めた。この話は蒸し返さない。**

数字の読み方だけ残しておく。1本6再生は競争に負けた値ではなく、**露出がゼロ**という
値。ショートは登録者0でもフィードに乗り、本編は登録者と履歴が要る。参考3チャンネル
（10.3万・1.73万・6,280登録）は**全員ショートを出していない**のに本編で5〜18万回
出している。**本編が弱いのではなく、こちらにまだ履歴が無い。**

したがって、今日入れた構成の手当て（1行目＝タイトル・反応を4割・まとめ1行・
サムネの型・定型シリーズ）は**そのまま本編に効かせる**。縦型向けの点検を
作り直す必要も、いまは無い。
