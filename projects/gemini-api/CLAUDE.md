# gemini-api

Gemini API を叩いて結果を JSON で返す自分用のゲートウェイ（FastAPI）。
アプリから直接 SDK を呼ぶ代わりにここを経由させ、**APIキーを1か所に閉じ込め、
モデル切り替え・リトライ・キャッシュ・レート制限を共通化する**のが目的。

## 前提

- Python 3.12。依存は `requirements.txt` に `==` で固定。`>=` に緩めない。
- 上流SDKは **`google-genai`**（`from google import genai`）。既定モデルは
  `gemini-3.5-flash`。より新しい `gemini-3.7-flash` は混雑時に 503 が出たため既定から外している。
  `gemini-2.5-*` は新規ユーザーには提供終了しており 404 になる。
- **APIキーは `.env` の `GEMINI_API_KEY`**（gitignore 済み、コミットしない）。
  ゲートウェイ自身を守る `API_KEYS` とは別物なので混同しない。
- **テストは上流をスタブ化してある**（`tests/conftest.py` の `FakeGeminiClient`）。
  APIキーもネットワークも不要で 38 件通る。CI もこの前提。

## よく使うコマンド

```bash
pytest                                   # テスト（APIキー・ネットワーク不要）
python -m uvicorn app.main:app --reload  # 起動 → http://127.0.0.1:8000/docs
```

## 手を入れるときに気をつけること

- **上流の例外を握るのは `app/clients/gemini.py` だけ**。ルーターは SDK の型も例外も触らない。
  新しい上流呼び出しを足すときも `_with_retry` を通し、`GeminiError` に変換して返す。
- リトライ対象は 429/5xx とタイムアウトのみ。**使い切ったとき 429/503 はそのまま透過**する
  （クライアントが再試行を判断できるように）。上流 500 系だけ 502 に丸める。この区別を潰さない。
- **ストリーミング（`/v1/generate/stream`）は本文が流れ始めたら再試行しない。**
  同じ内容が二重に届くため。ヘッダ送信後はステータスを変えられないので、失敗は
  `event: error` フレームで通知し、正常終了の `data: [DONE]` と区別できるようにしてある。
- **キャッシュとレート制限の失敗を本処理の失敗に昇格させない。** Redis が落ちても
  ミス扱いで続行する。この方針で握る例外は必ずログを残す（無言の `pass` に戻さない）。
- レート制限のカウンタは**プロセス内**。uvicorn のワーカーを増やすとワーカー数だけ
  実効上限が緩くなる。厳密にやるなら Redis 側に寄せる。
- **Gemini 3 系は思考にも出力トークンを使う。** `output_tokens: 1` でも
  `total_tokens: 160` になり、課金は合計側。`max_output_tokens` にも思考分が含まれるため、
  小さくしすぎると本文が途中で切れる（実測 200 で短い回答すら切れた）。
- SDK の `tools` を使わないので自動関数呼び出しは無効化してある（有効だと毎回警告が出る）。
  ツール呼び出しを実装するときはここを戻す。

## 未対応

- Redis バックエンドは**実サーバ相手に未検証**（インターフェースと選択ロジックのみテスト済み）。
  実運用に入れる前に一度疎通を確認する。
- 画像・音声など、テキスト以外の入出力。
