# soccer-career

1人の選手を作って、キャリアを進めるゲーム（FC 系のプレイヤーキャリア相当）。
2部の下位クラブから始まり、試合ごとの判断で評価点を積み上げ、成長し、
移籍して上を目指す。**中核は「試合中の選択」**であって、放置でも数字でもない。

## 前提

- Flutter / Dart。依存は `shared_preferences` のみ。
- **国名は実在のもの、リーグ名とクラブ名は架空**（`lib/game/world.dart`）。
  国名は地名であって商標ではないので、そのまま使える（2026-09-08 に架空から変更）。
  リーグ名・クラブ名・連盟の略称・大会名には商標があるので、**そちらは架空のまま**にする
  （「ワールドカップ」も商標なので「世界大会」と呼ぶ）。
  公開と収益化を前提にしているため、この線は動かさない。
  **写しているのは名前ではなく制度**で、現実感の正体はそちら。
- **国のIDは変えない。** `club.id` が "albion-t1-c0" のようにIDを含んでいるので、
  IDを変えると既存の保存データが読めなくなる。表示名だけを差し替える。
- **1シーズン38試合すべてをプレイする**設計（ユーザーの選択）。
  だから **1試合は短くなければならない**。先発で3局面、途中出場で2局面。
  ここを増やすとシーズンが終わらなくなる。
- 局面は**各ポジション18**（7 → 12 → 18、いずれも 2026-09-08）。1試合で3つ引く。
  内訳は**骨格12 ＋ 追いかける展開3 ＋ 守り切る展開3**。骨格だけで1試合ぶんを賄えることを
  テストで縛ってある（骨格が12を切ると、終盤の差し替えが効く前に同じ顔が並ぶ）。
  3つしか無かった頃は毎試合同じ局面が出てすぐ飽きた。
  増やすときは「1試合3つ」との比率を意識する。
- セーブは端末ごとに独立（`shared_preferences`）。クラウド同期はしない。
- **保存データの互換性は必ず保つ。** 項目を足すときは `fromJson` に既定値を置く
  （`Position.parse` の fw/mf/df、`potential`、`agent`、`salary` などが先例）。
  更新した途端にキャリアが消えるのが一番のがっかり。
  **これは `test/save_guard_test.dart` が機械で見張る**。保存データの鍵を
  1つずつ消して `fromJson` にかけ、投げたら落ちる。初版からある骨格41件だけを
  `structural` に並べてあり、**そこに無い項目は既定値が要る**。
  既定値を忘れると `fromJson` が投げ、`SaveRepository.load` はそれを握り潰して
  新規扱いにする——つまり**黙ってキャリアが消える**。エラーも出ない。

## 手を入れるときに気をつけること

- **常に正解になる選択肢を作らない。** 各局面は「難しいが得点に直結する手」と
  「安全だが見返りが小さい手」を対にしてある。どちらを選ぶかがこのゲームそのもの。
  `successChance` が能力＝難易度でも五分を下回るのは意図的で、難しい手にリスクを残すため。
- **評価点が出場機会に効く**（`decideAppearance`）。不調が続くと途中出場→ベンチ外になる。
  この連鎖がキャリアものの緊張感なので、甘くしない。ただし**デビュー前は必ず先発**にする。
  実績ゼロでベンチ外にすると、何もしないまま数試合が過ぎる。
- **直近の出来は、足りないぶんを基準点で埋める**（`MatchEngine.formAverage`）。
  5試合の平均で見ているのに、1試合しか無いときはその1試合が平均になっていた。
  デビュー戦で 4.9 を取ると、次の節にはもうベンチ外だった。足りないぶんを
  6.0 で埋めて、判断が溜まってから効くようにする。出場の見通しも同じ式を使う。
- **ベンチには戻り道を必ず用意する**（`idleRun` / `benchPatience` / `benchRecoveryPerMatch`）。
  外れた試合には評価点が付かないので、窓の中身が更新されない。以前はそのせいで
  **一度ベンチに落ちた選手が永久に出られなかった**（2026-09-08 に報告を受けて修正）。
  外れ続けるほど評価を甘く見て、3試合外れたら必ず一度はベンチに入れる。
  離脱明けも同じ扱いで、まずベンチから戻す。
- **好調でも休まされることがある**（`MatchEngine.rotates`）。疲れているほど確率が上がる。
  これが無いと「途中出場」という状態がほとんど現れず、コンディション管理も効かない。
  ただし先発が8割を切ると主力の実感が無くなるので、確率は 0.22 で頭打ち。
  1シーズンの目安は 先発25・途中9・ベンチ1・離脱1（38節）。
- **順位表は他クラブ同士の試合も毎節シミュレートする**（`_simulateOtherMatches`）。
  自分の試合ぶんしか動かないとリーグが死んで見える。
- **試合のスコアは開始時に決まっていて、時間とともに動く**（`teammateGoalMinutes` /
  `concededMinutes`）。終わってからスコアを作っていた頃は、試合中に「今どうなっているか」が
  存在せず、1点負けている終盤の1本と3点リードでの1本が同じ重さだった。
- **アシストが決まったら、その得点はスコアに乗る**（`_claimTeammateGoal`）。
  「抜け出した味方が決めた」と書いてあるのにスコアが 0-0 のままだった。
  **足すのではなく、この後に入る予定だった味方の得点を今に引き寄せる**。
  足す形にすると自分のクラブだけ点が増え、リーグ優勝が3倍に膨らんだ
  （3743シーズンで 244回 → 842回）。予定が無いときはアシストにならない。
- **アシストの見込みは期待値から出す**（`assistConversionAt`）。予定そのものを
  見ると未来が漏れる（画面に出す数字から、この後に点が入るか分かってしまう）。
  「味方が決める得点の見込み × 残り時間」から確率を出し、画面と自動進行の
  両方がこれを使う。終盤ほど低く、弱いクラブほど低い。
- **自分の得点は味方の得点に上乗せする**（`finish`）。差し引く割合はポジションで変える
  （`teammateGoalShareFor`）。一律で引くと、点を取らない GK や CB のクラブだけが勝てなくなる。
- **追いついた・突き放した得点は評価点が重い**（`decisiveGoalFactor`）。
  終盤（75分以降）で同点以下のときの得点だけ。
- **成長は、その試合で成功した手の能力に偏る**（`grow` の `used`、7割）。
  何を選ぶかが選手を形作るのがキャリアものの面白さで、ただの乱数だと
  何を選んでも同じ選手になる。残り3割を無作為にしてあるのは、偏りすぎて
  一芸だけの選手にしないため。
- **昇格・降格は国のクラブ数に合わせて相対で見る**（上位2が昇格、下から3が降格）。
  16クラブの国と24クラブの国があるので、順位を決め打ちにしない。リーグの名簿は固定なので、
  移ってきたクラブは元の名簿の1クラブと入れ替える（`_leagueContaining`）。
- **クラブ名は地名×命名の型のプールから、部ごとに重ならない区間を切り出す**
  （`World._clubNames`）。開始位置をずらすだけだと一周して上の部と被る（実際に起きた）。
  3部制の国は最大64クラブ要るので、地名は18・型は4で72通り確保してある。
- **外国人の扱いは6つの型の組み合わせ**（`ForeignRule`）。連盟内自由・登録枠・同時出場枠・
  提携国・自国育ち枠・労働許可。**制度を画面の主役にしない**。プレイヤーに見せるのは
  「自分がその国でどう扱われるか」と、オファーの但し書きだけ。
- **労働許可はポイント制**（`Eligibility.checkPermit`）。無名の若手が最上位リーグへ
  直接行けないことで、「規制の緩い国を経由して実績を積む」という現実のキャリア設計が
  自然に生まれる。ここを緩めると世界が平坦になる。
- **同じ国に5年で帰化する**（`advanceSeason`）。外国人枠から外れ、行ける先が広がる。
- **外国人枠の使用数は見積もりで出す**（`Eligibility.usedSlots`）。他クラブの選手を1人ずつ
  持つとデータが重くなるため、クラブの強さから逆算する。**余裕を持たせすぎると枠が
  塞がらず制度が死ぬ**（0.9 を掛けていて実際に死んでいた）。上位クラブは使い切っている前提。
- **登録メンバー25人枠**（`Competitions.registrationFor`）。外国人枠が埋まっているか、
  クラブの中で力が足りないと登録外になり、1試合も出られない。怪我と違って理由が
  分かりにくいので、画面では理由まで書く。
  **線は「オファーで来る範囲」の中に置く**（`squadRegistrationGap` −8）。
  −18 に置いていた頃、この制度は**1140シーズンで一度も起きなかった**——
  オファーはクラブの強さが「総合力 −14」までしか来ないので、加入した時点の差が
  −18 を割ることが構造的に無い。**外国人枠のほうも同じ**で、`canJoin` が枠の
  空きを見てから加入するので、登録の時点で埋まっていることがない。
  実測で、キャリア中の最悪の差は −11、下位1割が −8（`test/reach_sim.dart`）。
  −8 にして 無出場シーズンが 0.00 → **0.15回/キャリア**（全体の 0.8% ほど）。
  ピーク総合力 77.1→77.0、平均評価 7.08→7.07 で、他は動かない。
  **線を動かすときは、必ず届く範囲を測ってから**（当て推量だと −15 も −10 も
  0 のままだった）。
- **大陸カップ・プレーオフ・移籍の窓はシーズンの外側**（`Competitions`）。試合中の操作は
  増やさず、シーズンの区切りで結果として現れる形に保つ。
- **性格は伸ばすものではない**（`Personality`）。経験で1シーズンに1〜2点だけ動く。
  **自信が成功率に効くのは ±3% まで**。ここを大きくすると能力を伸ばす意味が薄れる。
- **市場価値は年俸と別**（`Person.marketValueFor`）。年俸は「今もらっている額」、
  市場価値は「今の値札」。移籍オファーの質と労働許可の審査はこちらを見る。
- **知名度は出場が前提**（`Person.fameFor`）。リーグの格を無条件に足していたため、
  1試合も出ずに在籍しているだけで知名度が伸びていた。代表と大陸カップだけは例外。
- **監督の信頼は出場機会に下駄を履かせる**（`Person.appearanceBonusFrom`）。
  評価点だけで決めると監督との関係が飾りになる。
- **引退**は 33 歳から選べ、37 歳のシーズン終了で強制。引退後は `retired` フラグで
  試合をせず通算成績だけを見せる。古い保存データにはフラグが無いので、無ければ現役扱い。
- 保存データが壊れていたら**捨てて新規扱いにする**（`SaveRepository.load`）。
  例外を投げると、一度壊れたユーザーがアプリを開けなくなる。
- **左右は「役割」ではなく「立つ側」として持つ**（`Side`、`Player.side`）。
  ポジションそのものを左右に割ると、局面プール・能力の重み・適性・初期能力が
  倍に増える。役割は8つのままで、SB と WG だけが側を持つ（`Position.hasSide`）。
  効くのは利き足との噛み合わせで、**合う側なら逆足の局面が減り（0.16）、
  逆サイドなら増える（0.38）代わりに、内へ切り込んでシュートに +4%**。
  片方だけだと逆サイドがただの罰になる。左右を持たせる前の保存データは、
  **利き足に合う側**として読む（既定で右に寄せると左利きが急に不利になる）。
  プログラムから作るキャリア（シミュレーション）は側を持たない＝中央扱いで、
  逆足の頻度は従来どおり。
- **ポジションは8つだが、局面プールは4ファミリー**（GK / 守備 / 中盤 / 前線）。
  SB と CB は同じ守備の局面を引く。ポジションごとに書き分けると量が爆発するので、
  差は能力の重み（`Attributes._weights`）と初期能力で出す。GK だけは局面が別。
- **能力値は22の詳細（`Detail`）で持ち、7カテゴリ（`AttributeKey`）はその平均。**
  局面の選択肢は詳細で判定する（`ScenarioOption.detail`）。**選択肢の detail は必ず key と同じ
  カテゴリに属させる**（テストで検証）。ずれると特性の判定（key で見る）と成長（detail で伸びる）が
  食い違う。練習はカテゴリ単位で、その中の詳細が1つ伸びる。
- **自動進行は3スタイル**（`SimStyle`）。安全＝成功率、バランス＝期待値、勝負＝得点に繋がる手の
  期待値。人が選ぶ癖を3つに絞った。連続進行は負傷・代表ウィーク・シーズン終了で必ず止める。
  止めずに回すと「気づいたら重傷で1シーズン終わっていた」になる。
- **ポテンシャルは隠す。** 画面に出すのは帯（`potentialBand`）だけ。数値を見せると
  「あと何点」の作業ゲームになる。試合の成長も練習も、達したら止まる。
- **最初の練習は、そのポジションの単科で始める**（`TrainingMenu.defaultFor`）。
  既定が「休養」だったので、育成タブを開かないまま1年が過ぎると
  何も伸びていなかった。始めた時点で練習している状態にしておく。
- **最初の選手は自分で決める**（`CreatePlayerScreen` → `startCareer` の
  `side` / `physique` / `look` / `squadNumber` / `countryId` / `tweaks`）。
  決められるのは 立つ側・利き足・身長・体重・能力の割り振り・出身国・
  見た目・背番号。**ポテンシャルは選ばせない**——始めてから分かるのが
  キャリアもの、という前提はここだけ残す。
- **特性は作成画面で見せて、引き直せる**（`startCareer(traits:)` / 2026-09-10、
  ユーザーの指示）。**以前は「選ばせない」側に置いていた**が、2つの長所で
  選手の性格がほとんど決まるのに、それが見えないまま20年ぶんの選択を
  することになっていた。引き直しは**作り直せば同じことができた**ので、
  隠しても稀な特性を狙う遊びは止められない——手間だけが残っていた。
  - **引くのは画面側**。`startCareer` は渡されたものをそのまま使い、
    渡されなければこれまでどおり自分で引く（テストとシミュレーションのため）。
  - **ポジションを変えたら引き直す**。特性はポジションで引ける集合が変わるので、
    ストライカーに「反応の鬼」が付いたまま残る。
  - 効き方の札は `Trait.effects` から作る（`ui/trait_row.dart` を選手タブと
    共用）。画面ごとに書き写すと、数字を変えたとき片方が黙って古くなる。
- **出身国は最初からモデルにあった**（`startCareer` の `countryId`）。
  画面から渡していなかっただけで、始めるリーグ・代表・外国人としての扱いが
  ここで決まる。作った仕組みを画面に出していないことがある、という例。
- **割り振りは合計0**（`_tweakSum == 0` でなければ始められない）。基準値から
  ±6 まで動かせるが、増やしたぶんはどこかを削る。**総合力を稼げると、
  割り振りが「正解探し」になる**（40人ぶんの平均で差が3未満であることを
  テストで縛ってある）。基準値は `CareerEngine.startingBaseFor` の1か所から出す。
- **特性は上位互換を作らない。** どれも得意な場面と苦手な場面がある（勝負師↔職人、
  早熟↔大器晩成は排他）。表示する成功率は特性・コンディション込みの `chanceFor` を使い、
  判定と同じ値にする。表示と判定がずれると「70%と書いてあったのに」になる。
- **特性は62種**（長所52・欠点10。2026-09-08 に 22 → 45 → 62）。引ける長所が少ないと、
  同じ能力値の選手ばかりになる。効き先は試合の中だけではない——練習の効き・疲労の溜まり方・
  離脱の長さ・気持ちの落ち込み・波の入りやすさ・居残りの伸び・警告の受けやすさ・休養で戻る量・
  無失点の評価・知名度・監督の信頼・相手への慣れ・停滞期・限界突破・慣れないポジションの減点。
  **新しい特性を足すときは、必ず既存のどれかと噛み合わない組み合わせを `_exclusive` に入れる**
  （本番強者↔本番に弱い、国際派↔ホームシックなど）。テストで「何も効いていない特性」が
  無いことを見ている。**新しい効き先を足したら、`sim_test` のその一覧にも足す**。
- **特性の効き方は「条件＋数値」のデータで持つ**（`Trait.rules` / `TraitRule`）。
  `chanceBonus` は規則の合計で、画面の「後半30分以降 +8%」も同じ規則から文にする。
  以前は switch の中に数字が直書きされていて、画面には名前と説明しか出せなかった。
  試合の外の効きも各倍率の getter から文を作る（`offPitchEffects`）ので、
  数字を変えれば画面も変わる。**表示用に別の式を書かない**のは成功率の内訳と同じ理屈。
- **特性が効いた回数を数える**（`MatchInProgress.traitHits` → `CareerState.traitHits`）。
  手を選んだ瞬間に成功率を動かしていた特性を数え、選手タブに「今季 12回の局面で効いた」と
  出す。名前だけでは付いている意味が分からず、「まだ効く局面が来ていない」と
  「効いていない」の区別も付かなかった。シーズンの起点で空にする。
- **稀な特性は確率で釣り合いを取る**（`Trait.rare` / `rareChance` 5% / `rareFlawChance` 2%）。
  天才・鋼の身体・生まれながらの主役・大一番の申し子・ガラスの身体（欠点）。
  「上位互換を作らない」の線を意図して踏み越えている——**滅多に付かないことが代償**。
  ユーザーの指示（2026-09-08「発生確率低いが天才という特性」「一定のランダム性がある要素」）。
  それでも排他は付ける（天才↔大器晩成・練習嫌い、鋼の身体↔頑丈系）。
  **判定は普通の引きが終わったあと**に置く。前に置くと乱数の並びがずれて、
  稀が外れた選手まで別の特性になる（種で再現している既存テストが全部動く）。
  天才のポテンシャル上乗せは生まれたときにだけ効くので、特性をポテンシャルより先に引く。
  `strengths` / `flaws` に稀なものは入れない（ガイドの一覧と普通の引きの両方に効く）。
- **超越の特性は、1つの詳細能力だけ上限を 99 → 109 にする**（`Trait.transcendDetail` /
  `Formulas.ceilingBreak` / `Player.ceilingFor`）。イーグルアイ（視野）ほか8種、1人に1つ。
  ユーザーの指示（2026-09-08「視野の能力値が上限を10超えることが可能」）。
  **ポテンシャルに達しても、その1つだけは伸び続ける**——ただし助走が要る
  （`transcendRunway` 89 以上）。無条件に伸び続けると、4人に1人の選手で
  ポテンシャルの意味が消える。**上限を超えた値は保存にも乗る**ので、
  `Attributes.fromDetails` の丸めは `absoluteMax`（109）で行う（99 で丸めると
  読み込んだ瞬間に消える）。判定に使う `effective` も同じ上限で丸める。
  `Dependencies.capFor` は土台を持つ能力を 99 で丸めない（丸めると 99 に達した
  能力の成長が土台へ流れ、実測で代表経験が 57%→63% に膨らんだ。99 で止めるのは
  `bumpDetail` の側で、これは以前からそう）。
- **特性はポジションに合うものからだけ引く**（`Trait.fitsPosition` / `roll(position:)`）。
  ストライカーに「反応の鬼」が付くと、2つしか無い長所の片方が死ぬ。
  GK 専用・フィールド専用・守備の選手専用の3つの集合で絞る。
  ポジションを渡さなければ全部から引く（シミュレーションと古い呼び出しのため）。
- **終盤は足が止まる**（`MatchInProgress.lateFatigue`）。70分から時間とともに
  成功率が落ちる。**スタミナで薄まり、累積疲労で深くなる**。
  局面の時間は表示・特性・展開の差し替えには効いていたのに、成功率そのものには
  入っていなかった。累積疲労もローテーションと怪我にしか効いておらず、
  **試合の中では何も起きなかった**。ここで初めて、スタミナを鍛える理由と、
  休養・リカバリー・ローテーションの意味が試合の中に出る。
  60分から 0.06 で始めたら 平均評価が 7.07→6.99 まで落ちた（1試合3局面のうち
  2つが対象になるため）。70分・0.05 で 7.03。上限 0.20 で理不尽を止める。
- **コンディションは練習と休養のトレードオフ。** 練習は伸びるが疲れ、疲れると
  試合の成功率が落ちる。休養は戻すだけ。ここが無いと練習を毎週押すだけになる。
- **休養とリカバリーは別の道具**（`Formulas.restFatigueRelief`）。リカバリーは
  コンディションの戻りが大きく怪我も減るので、休養はただの下位互換だった。
  休養（完全オフ）だけが累積疲労を抜く（1週で3）。8 にしたら平均疲労が 65→10 に
  落ちて疲労の仕組みが消えたので、3 で平均 35 に置いてある。自動休養の週も抜ける。
- **疲れ切ったら自動で休む**（`CareerState.autoRestBelow`、既定40）。毎週の操作を
  忘れたまま疲れた身体で練習を続けると、伸びないうえに怪我をして数試合を失う。
  しきい値は選べて、0 にすれば切れる。**居残りも一緒に止める**
  （居残りだけ残すと、休んだつもりで怪我をする）。**判定は試合ぶんの消耗を引いたあとの
  値で行う**（`MatchEngine.conditionAfterMatch`）。試合前の値で見ると、出場した週に
  疲れ切った状態で練習させてしまう。**黙って差し替えない**——効いた週は結果画面に書く。
- **契約更改は撤回されない**（`negotiate`）。移籍オファーは上乗せに失敗すると引かれることがある。
  残る権利まで消すと、失敗した瞬間に無所属になって詰む。
- **出ていない試合に評価点を付けない**（`finish`）。ベンチ外と負傷離脱はどちらも
  `rating: null`。付けると平均評価・出場数・出場機会の判断（`decideAppearance`）が
  まとめて狂う。実際に負傷離脱だけ抜けていてテストで見つかった。
- **カードは試合の選択から出る**（`ScenarioOption.foul` / `cardChanceFor`）。
  荒い手は失敗したときだけ笛が鳴り、気性（`temper`）で確率が上がる。
  ここまで気性は関係の悪化にしか効いておらず、ほぼ死んだ軸だった。
  **2枚目でその試合は終わる**（`isFinished` が `sentOff` を見る）。
  累積5枚で1試合、退場で2試合の出場停止。警告はシーズンをまたぐと消え、
  出場停止は持ち越す。出場停止は `Appearance.suspended` として記録し、
  **評価点は付けない**（ベンチ外・負傷離脱と同じ扱い）。
- **「止めるための反則」は損なだけの手にしない**（`preventsGoal`）。
  選べば必ず警告になる代わりに、これから入るはずだった失点を1つ消す。
  失点の時間は試合開始時に決まっているので、そこから1つ抜くだけで表現できる。
  **`expectedDelta` にカードと失点阻止の両方を入れる**——片方だけだと、
  自動進行が「安いだけの手」か「損なだけの手」のどちらかに倒れる。
- **負傷は治って終わりにしない。** 重傷は能力とポテンシャルを恒久的に削る
  （`applySevereInjury`）。数試合休むだけなら、ただの足踏みで緊張感が出ない。
  練習した週だけ練習中の負傷を判定する。休養にリスクを付けると休む理由が消える。
- **代表戦はリーグと混ぜない**（`MatchResult.international`）。節に数えず、順位表も
  監督の目標も動かさない。キャップと代表ゴールだけが通算で積み上がる。
  `matchday` と `seasonStats` は `leagueResults` を見る。
- **代表は実力だけでは呼ばれない**（`shouldCallUp`）。総合力と直近の出来の両方が要る。
  片方だけで呼ぶと、招集が「強くなった通知」になってしまう。
- **契約が残っている間は移籍オファーが来ない**（`offersFor`）。毎年オファーが来ると
  移籍が軽くなる。残り1年になって初めて話が動く。
- **移籍の窓は画面に出す**（`CareerController.transferWindowLabel`）。
  `Competitions.windowAt` は計算していたのに、**どこにも出ていなかった**
  （`transferWindow` も `TransferWindow.isOpen` も誰も読んでいなかった）。
  「契約が残っているから来ないのか、時期ではないのか」が分からないので、
  クラブタブに理由まで書く。**窓そのものはまだ何も判定していない**——
  冬の窓に実際の移籍を入れるなら、順位表と日程がクラブ1つ前提なので、
  そこを作り直す必要がある。

### 育成（段階①②）

- **身体データは能力値を書き換えない**（`Physique.bonusFor`）。試合の判定にだけ効かせる。
  増量した週に「伸びた」ように見えると、練習で積み上げた数字の意味が濁る。
  補正は ±6 で頭打ち。身体だけで能力が決まると、練習の意味が消える。
- **能力には土台がある**（`Dependencies`）。土台の平均 +18 までしか伸びない。
  頭打ちの週は、一番低い土台のほうが伸びる。「筋力20のまま最高速だけ99」を作らせない。
- **練習はメニュー単位**（`TrainingMenu`）。複合メニューは2か所に触れる代わりに
  1か所あたりが伸びにくく、よく疲れる。カテゴリを直接選ばせていた頃の保存データは
  `TrainingMenu.forKey` で読む。
- **居残り（セットプレー）は総合力に乗らない**（`SetPieceSkills`）。55 に届くとクラブの
  キッカーを任され、そこで初めて試合の得点に出る。積んでも報われない期間があることに意味がある。
- **専属スタッフと生活習慣は自腹**（`StaffTeam` / `Habits`）。人件費は手取りから引き、
  払えなければ契約は切れる。稼ぎの使い道を「豪遊か、身体への投資か」にするための仕組み。
- **整えた生活はプロ意識になる**（`Habits.disciplined` / `reckless` → `Person.evolve`）。
  この2つは「プロ意識が上がりやすいか」と書いてあるのに**どこからも読まれていなかった**。
  生活習慣は練習の効き・怪我・回復にしか効いておらず、肝心の「生活が人を作る」が
  死んでいた。**毎季必ずは動かさない**（半分の確率）——繰り返し動かすと、プロ意識が
  練習の効きを押し上げて総合力が膨らむ（出来事のときに実際に膨らんだ）。
- **収支は雇う前に見せる**（`Finances.budgetFor` / `CareerState.budget` /
  `ui/budget_lines.dart`）。年俸だけを見て世界的なコーチを雇い、シーズン末に貯蓄が尽きて
  **黙って全員が離れる**という壊れ方をしていた（年俸860万に対して人件費800万でも
  何も言わなかった）。**見込みは `afterSeason` と同じ式から出す**。別に計算すると、
  画面の数字とシーズン末の結果がずれる（テストで一致を縛ってある）。
  尽きたときは見出しにも残す（`Newsroom.staffDismissed`）。
- **生活水準は操作できる**（`setLifestyle`）。モデルには最初からあったのに、
  変える手段がどこにも無く、ずっと「普通」に固定されていた。下げれば手取りが増え、
  上げれば気持ちが少し上向く（`Finances.moraleShift`、既定は0なので過去の数字は動かない）。
  **見返りが無いと「質素」がただの正解になる**ので、小さく返す。
- **育てる方向を選べる**（`CareerState.focus`、最大3つ）。練習も試合の成長も、
  伸びる先が無作為だったので、何を選んでも似た選手になっていた。方向を入れると、
  練習ではそのカテゴリの中でその項目が優先して伸び、試合の成長の無作為ぶんも
  そこに乗る。**伸びる量は変えない**——どこに乗るかだけを変える
  （量まで変えると、方向を選ぶことが強くなる手段になってしまう）。
  試合の選択肢には「重点」と出して、方向と試合を繋ぐ。
  **上限まで入っているときは、黙って古いものを落とさない**（何が外れたのか
  分からなくなる）。長期的には個人技（`Signature`、詳細78）に届くので、
  「育てる方向」にはあといくつで覚えるかを出す。
- **プレイング・アイデンティティは偏ってはじめて付く**（`Development.identity`）。
  30回以上選んだうえで、上位が全体の1/3を超えたときだけ。何でも選ぶ選手は何者にもならない。
- **相手クラブの戦い方はIDから決める**（`ClubStyle.of`）。保存しないのに毎回同じになるので、
  「あそこは苦手だ」という記憶が成立する。ハッシュではなく符号の和で出すのは実行ごとに変わらないため。
- **大一番は経験と自信で薄まる**（`MatchInProgress.bigMatch`）。格上との対戦と代表戦が対象。
  若く自信の無い選手は呑まれ、積み上げた選手は平常どおり出せる。
- **逆足の局面は試合開始時に決める**（`weakFootMoments`）。呼ぶたびに引き直すと、
  画面に出した成功率と判定がずれる。
- **限界突破の条件は厳しく保つ**（`breaksThrough`）。頭打ち・若さ・プロ意識・経験の
  4つが揃って初めて確率で起きる。緩めるとポテンシャルが飾りになる。
- **停滞期が無いと右肩上がりになる**（`Development.afterGrowth`）。12回伸びたら数試合止まる。

### 制度と人（段階③）

- **違約金は出口**（`releaseClauseFor` / `clauseTriggered`）。伸びた選手は自分の違約金を
  追い越し、契約が残っていても話が動き出す。安く囲うことのリスクをクラブ側に置いている。
- **ローンは出番の無い若手にだけ**（`_loanOffers`）。成績は問わない。出られないことが理由だから。
  保有元との契約は凍り、1年で戻る。買い取りオプションは結果を出したときだけ行使される。
- **国内カップは一発勝負**（`runDomesticCup`）。格差がそのまま出るならカップの意味が無いので、
  勝ち上がりは5分に近い。優勝すれば翌季の大陸カップ出場権が付き、弱いクラブに居ても
  上の舞台に届く道が1本残る。
- **ワールドカップは4年に1度**（`isWorldCupYear`）。だから1回が重い。知名度への効きも桁を変えてある。
- **監督は戦術と要求を持つ**（`Manager`）。相性は出場機会に効き、成績が期待を下回れば飛ぶ。
  代われば信頼は白紙。信頼の厚かった監督は恩師として残り、よそのクラブから呼ぶことがある。
- **監督は「何を選んだか」を見る**（`Manager.trustShift` / `MatchInProgress.favoured`）。
  `fitFor` は**能力値だけ**を見ていた——監督は「あなたの数字」を採点する装置で、
  試合の選択はどこにも届いていなかった。これが「各機能が独立している」の正体。
  求める形（`Tactic.favours`）に沿った手・逆らった手を数え、信頼に返す。
  **監督に合わせるか、自分の型（identity）を通すか**が毎試合の緊張になり、
  監督が代われば求められる形も変わる＝移籍の重みが増す。
  1試合で動くのは1未満なので、端数を `CareerState.tacticCredit` に持ち越す
  （切り捨てると永遠に何も起きない）。選択肢には「監督好み」と出す。
  **自動進行にも見せる**（`tacticPickBonus`）——見ないと自動で進めるだけで
  信頼を失い続け、実測で代表経験が 58%→51% に落ちた。人が押す「区切りまで」も
  同じ道を通るので、入れないと自動進行そのものが罠になる。
- **監督の期待を、試合の中に持ち込む**（`CareerState.objectiveReach`）。
  「得点関与 あと1」はクラブタブのカードにあるだけで、**局面を選ぶ画面には
  無かった**。3つのうち2つ目に届くときだけ局面の側に出す。同じ局面が、
  シーズンのどこにいるかで意味を変える。
- **相方との呼吸は、選択で育てる**（`MatchResult.assistAttempts`）。
  出場するだけで +2 だった＝プレイヤーの関与がゼロだった。
  味方を活かす手を選んだぶんが、そのまま呼吸になる。
- **同僚は3人だけ**（`Teammate`）。競争相手・相方・メンター。名前のある他人を増やしても
  管理が増えるだけで、効くのはこの3つだけ。相方との呼吸は移籍で失われる。
- **ポジション適性は総合力から引く**（`Aptitude.penaltyFor`）。本職なら0。適性を持たない
  古い保存データは減点しない（`isUnknown`）。過去のキャリアの総合力が突然落ちるのを防ぐ。
- **方針は「優先したぶん諦める」形にする**（`Directive`）。通る通らないの判定にしない。
- **リハビリは早く戻るほど再発する**（`RehabPlan`）。復帰後3試合は再発の危険が高い。
- **条件で選ばれない話は別枠で持つ**（`_marketOffers` の `special`）。恩師のラブコールと
  古巣へのラストダンスは、年俸順に3件へ切る処理で必ず消えてしまうため、切った後に足す。

### 人生の周辺（段階④）

- **ピッチ外の出来事は物語であって罠ではない**（`LifeEvents`）。効きはすべて小さく、
  1回で人生が決まらない（テストで上限を検証している）。一度きりの出来事は `seenEvents` で抑える。
- **名前のある他人は、出来事に出てきて初めて人になる**（`PersonKind` / `withNames`）。
  監督・競争相手・相方・メンター・同期・代理人が居るのに、出来事に一度も
  出てこなかった。文中に `<mentor>` のようなしるしを置き、出す前に名前を埋める。
  **しるしを使う出来事には、必ずその人を条件に付ける**（付け忘れると画面に
  しるしがそのまま出る。テストで縛ってある）。
- **繰り返し起きる出来事（`once: false`）は性格を動かさない。** 性格は
  「経験で1シーズンに1〜2点」動くもの。毎年何度も動かすと、プロ意識が
  練習の効きを押し上げて総合力が膨らむ（実際に膨らんだ）。
- **出来事で伸びる能力は、ポテンシャルを超えない。** 練習も試合の成長も上限で
  止まるのに、出来事だけが突き抜けると上限そのものが意味を失う。
  **能力が伸びる選択肢は「練習の中の出来事」に寄せる**。人との出来事にまで
  能力を配ると、成長の本流が練習でも試合でもなくなる（配ったら 代表経験が
  50%→66% まで膨らんだ）。
- **気持ちと疲労は別のもの**（`Morale` / `Fatigue`）。コンディションは1週間で戻るが、
  累積疲労は戻らずオフでだいたい抜ける。気持ちは出番と私生活で動き、成功率と練習の効きに
  小さく効く（±3%まで）。
- **波（ゾーン／スランプ）は数試合で明ける**（`Form`）。実力どおりの成績が延々と続くより、
  起伏があるほうが1シーズンを追う気になる。
- **キャプテンは数字では回ってこない**（`offersCaptaincy`）。監督とロッカールームの両方に
  認められ、若すぎないこと。移籍すれば腕章は外れる。
- **背番号と愛称は「有名になった実感」**（`squadNumberFor` / `nicknameFor`）。
  エースナンバーは実績を積んでから。愛称は知名度50から、選択の癖に沿って付く。
- **引退で終わりにしない**（`secondCareerFor`）。現役でやってきたことが次の道の適性になる。
- **引退した選手は消さない**（`models/legend.dart` / `HallRepository` / 2026-09-10、
  ユーザーの指示）。引退画面に「この選手の記録は消えます」と書いてあって、
  **本当に消えていた**——20年ぶんの選択の結果が、次の選手を作るために捨てられていた。
  - **キャリアとは別の鍵に置く**（`hall_v1`）。同じ鍵に入れると、新しいキャリアを
    始めた瞬間に一緒に消える。`SaveRepository.clear()` はキャリアだけを消す。
  - **引退した時点で写す**。引退画面のボタンを押したときにすると、
    押さずに終える人の記録が消える。
  - **`CareerState` をそのまま残さない**。重いし、形式を変えるたびに読めなくなる。
    必要なぶんだけ写し取って、以後はそのかたちで持つ（`Legend`）。
  - **総合力は引退時ではなくピークを残す**。衰えた後の数字だけが残るのは、
    その選手の記録として正しくない。
  - **改変の印（`tampered`）は殿堂にも持ち込む**。落とすと、改変済みの記録が
    普通の記録に紛れる。
  - **殿堂の読み書きは失敗してもキャリアを壊さない**（try/catch で握り潰す）。
    ここが投げると引退そのものが失敗する。殿堂はあると嬉しいものであって、
    キャリアを進めるのに要るものではない。
  - `SaveRepository` に足さずに別クラスにしてあるのは、
    テストの偽物（`implements SaveRepository`）を全部壊さないため。
  - 入口は3つ: 引退画面・選手作成画面・拠点の ⋮。

- **引退させた選手が、次のキャリアの世界に居る**（`Manager.fromLegend` /
  `Teammate.fromLegend` / `Hall.castFor` / 2026-09-10）。殿堂は記録を残す場所に
  なったが、**見るだけの場所**だった。20年かけて育てた選手が、次のキャリアの
  ロッカールームにも監督室にも居ない。並んでいるだけで、次の20年が何を目指すのかも
  どこにも書いていなかった。
  - **引退後の道（`SecondCareer`）がそのまま役になる。** 監督になった選手は監督として、
    育成コーチはメンターとして現れる（4割）。**footballから離れた人は出てこない**——
    解説者も実業家も静かな暮らしも、ピッチには戻らない。
  - **能力も戦術も動かさない。名前と印を差し替えるだけ。** 強くなる引き継ぎを入れると、
    2周目のほうが簡単になり、**1周目の20年が軽くなる**。ここは崩さない。
  - **新任の監督だけが対象**（`tenure == 0`）。在任中の監督が突然別人になるのはおかしい。
  - **新しく引退した人から先に見る**（`Hall.castFor` は `legends` の順）。
    40人から均等に引くと「さっき引退させた選手」が出る確率が 1/40 になり、
    繋がりがまるで感じられない。
  - **印は保存に乗る**（`fromLegend`、既定 false）。名前を差し替えるだけだと
    同姓同名と区別が付かない。
- **歴代の記録を的として出す**（`HallRecord` / `Hall.records`）。通算ゴール・通算出場・
  タイトル・ピーク総合力の4つを、持ち主の名前と一緒に殿堂の一番上に置く。
  **0の項目は出さない**（0ゴールの「歴代最多」は的にならない）。
  **「歴代1位」の札は2人目から**（1人しか居ないうちは全部その人になる）。

### バランス（2026-09-08 に200キャリア・3730シーズンで調整）

数字を触るときは `flutter test test/balance_sim.dart` を回して、10通りの遊び方で
引退までの数字を見る（20秒ほど）。CI では `test/balance_test.dart` が数人ぶんだけ
回して、桁が変わっていないかを見張る。

調整で分かったことと、その結果:

- **決定機は必ず点にならない**（`goalConversion` / `assistConversion`）。手が通ることと
  点が入ることを分けていなかった頃は、強気に行くだけで1試合1.5点、通算600ゴールになっていた。
  今は前線の選手で1試合0.5点前後。画面では「成功率」と「ゴール◯%」を別々に出す。
- **契約は減る**（`renewalOffer`）。残留のたびに新しい契約年数を配っていたため、
  残り1年に届かず、移籍の話が**100キャリアで0.13件**しか来なかった。契約が残っている間の
  残留は「1年減るだけ」で、条件は動かない。
- **年俸は実力に見合う額を軸にする**（`renewalOffer` の clamp）。前年の年俸に倍率を
  掛け続けていたため、平均11億・最大200億円になっていた。今は最高年俸の平均が1.1億円。
- **違約金は市場価値の4倍**（`releaseClauseFor`）。年俸基準だと市場価値の10倍以上になり、
  一度も発動しなかった。
- **若いほど伸びる**（`growthByAge` と `rapidGrowthAge`）。一律だった頃は25歳で総合力63、
  引退までポテンシャルに届かなかった。今は21歳で69、25歳で73、ピーク76、到達率36%。
- **成長はポジションの重みで割り戻す**（`growthShareFactor`）。GK は総合力の6割が GK 能力に
  乗るので、割り戻さないと GK だけ9割がポテンシャルに到達していた。
- **無失点は守備者にとってのゴール**（`cleanSheetBase` ほか）。得点とアシストしか評価点に
  乗らなかった頃、GK のキャリア平均は6.39、ストライカーは7.33 だった。評価点は移籍・代表・
  出場機会すべての入口なので、この差は「GK は上に行けない」と同義だった。今はどのポジションも
  7.0〜7.4 に収まる。
- **決定機を作ったぶんも評価に乗る**（`ratingPerChance` 0.06）。無失点の項を入れたあと、
  今度はストライカーが 6.8〜6.9 に沈んでいた。枠内シュートを止められた手と横パスが同じ
  +0.32 だったため。**0.15 にすると全体が 7.02→7.28 に膨らむ**——自動進行の物差し
  （`expectedDelta`）にも入るので、バランス型まで得点の手を選ぶようになる。0.06 で
  ST 6.86→6.98、全体 7.02→7.12。
- **GK のセービングにも土台を置く**（`Dependencies.supports` の `reflexes`）。
  総合力の6割を占める能力に土台が無く、GK だけ何にも縛られず伸びていた
  （ピーク総合力が他より3〜4高く、ポテンシャル到達 90%）。敏捷性とジャンプを土台にして
  他のポジションと同じ縛りにした。GK のピークは 80.4→77.5。
- **怪我は年1〜2回、離脱は年6〜8試合**（`injuryBaseChance`）。0.045 の頃は年2.7回・14試合を
  失っていた。自動休養が入ってからは「休まない」遊び方も年5〜6試合で収まる
  （自動休養が受け止めるため）。休養の意味は疲労抜き（上記）に移した。
  **自動休養（既定40）を入れてから、200キャリアの平均は 怪我1.63回→1.24回、
  離脱7.7試合→5.9試合、通算出場530→558、ピーク総合力75.9→76.4、平均評価6.95→7.03**。
  「疲れたまま練習し続ける」という踏み外しを潰したぶんだけ全体が上向いている。
  数字を戻したいときは既定値を下げるか、切った状態で測る。
- **代表は上位だけ**（`callUpOverall` 77）。72 の頃は育てた選手の94%が代表に入っていた。
- **国内カップは勝ち抜き5回**（`runDomesticCup`）。1回戦ごとの確率を上げすぎると、強豪で
  毎季3割が優勝する。今はキャリアに1回ほど。
- **上の国へ行くには名前が要る**（`reachableCountries`）。総合力だけで届くと、
  普通に育てた選手の半数以上が最上位の国の1部に流れ着く。代表歴を条件に足してある。
- **上の国へは一段ずつしか上がれない**（`reachPrestige` を `clamp(0, 1)` / 2026-09-10）。
  条件を足しても、**一度に2段上がれると 19シーズンあれば誰でも最上位に着く**。
  一段ずつにすると、格3の国から格5へ行くには格4を経由する必要が出る。
  実測（72キャリア）: 到達した国の格が 3:24% / 4:32% / **5:43%** → 3:29% / 4:33% / **5:36%**。
  ピーク総合力・平均評価・代表経験は動かない。
- **「1部到達 100%」は平坦さの証拠ではなかった**（2026-09-10）。ずっと
  「世界が平坦」の根拠として見ていたが、測ったら **60キャリア全員が移籍で到達**
  していて、昇格で到達した者は0人。そして 19シーズン・550試合を戦うプロが
  どこかの1部に届くのは普通のこと。**平坦だったのは到達する国の格のほう**で、
  直すべき数字はそちらだった。**指標そのものを疑う。**
- **自動休養の既定値は 40 のまま**（2026-09-10 に測って決定）。下げる提案を
  していたが、実測（144キャリア）で **25 は 0 とほとんど同じ**（しきい値に
  届く前に他の仕組みが受け止める）で、**40 だけが効いている**:
  0 → ピーク75.6・評価7.00・怪我1.45・出場539 /
  25 → 75.6・6.99・1.46・538 / **40 → 75.9・7.04・1.26・552**。
  「週の選択を奪う」ことが気になっていたが、`TrainingEffort.easy`（流す）が
  入ったことで**踏み込みを緩める道は別に用意できている**。この話は蒸し返さない。

### 見た目

- **選手の似顔はその場で描く**（`ui/player_portrait.dart`）。画像素材を持つと
  権利と容量の話になる。クラブの色と背番号がそのまま乗るので、**移籍すると
  見た目も変わる**。**顔は目鼻を描かない**——実在の人物を思わせないためと、
  少ない線で「自分の選手」に見せるため。
- **髪は頭の輪郭に沿わせて上から被せ、生え際を肌色で削り出す**
  （`_paintHair` の `cap`）。頭と別の形で描くと、額に隙間が空いて鉢巻きに見える
  （最初はそうなっていた）。**書き出して目で見るまで気付けない**ので、
  作り込むときは `RepaintBoundary.toImage` で PNG に落として確認する。
- **選手証で始める**（`ui/player_banner.dart` / 2026-09-10）。選手タブは
  **白いカードに文字が並ぶだけ**で、このゲームで唯一手で描いているもの
  （`PlayerPortrait`）は 64px の丸で隅に居た。クラブの色を背に敷いて、
  似顔・名前・背番号・総合力を大きく出す。移籍すれば選手証ごと色が変わる。
  **背に乗る文字色は明るさから決める**（`estimateBrightnessForColor`）——
  白で固定すると、明るいクラブで文字が飛ぶ。クラブの色は12色あって
  明るいものも暗いものもある。
- **能力は形で見せる**（`ui/attribute_shape.dart`）。棒が6本並んでいるだけでは
  **数字を読まないと選手の形が分からなかった**。カテゴリを多角形の頂点に置き、
  今の形と開幕時の形を重ねる。**棒は残す**——正確な値はそちらで読むもので、
  形は輪郭を覚えるためのもの。GK だけ頂点が7つになる（`keys` を渡す側で決める）。
  目盛りの中心に穴を空けてある（0 から描くと低い能力が1点に集まって形が読めない）。
- **`CustomPainter` の中の文字も、テーマの書体から取る**（2026-09-10 に踏んだ）。
  `TextStyle` を素で作ると同梱フォントに乗らず、**Web で豆腐（□）になる**。
  `font_test` は「その文字がフォントにあるか」を見るので、**この壊れ方は拾えない**。
  書き出して目で見て初めて分かった。
- **次の一戦はエンブレムで出す**（`_Fixture`）。一番よく見るカードなのに、
  相手は文字でしか出ていなかった。左がホーム、自分のクラブだけ濃く出す。
- **クラブタブにも帯を置く**（`_ClubBand`）。制度の説明ばかりで、
  **どこに所属しているのかが文字の中に埋もれていた**。
- **局面はピッチの絵にする**（`ui/pitch_view.dart` / `models/pitch.dart` / 2026-09-10）。
  試合画面は最後まで文字だった。「ライン間で前を向いて受けた。中央は密集、
  外は空いている」と書いてあっても、**自分がどこに居て相手がどう構えているかは
  読んで想像するしかなかった**。局面ごとに `PitchSpot`（74局面ぶん、既定値なし）を
  持たせ、横向きのピッチに自分と相手のブロックを描く。**いつも右へ攻める**——
  向きが局面ごとに変わると、どちらへ攻めているのか分からなくなる（GKの局面も同じ向き）。
- **絵に描くのは判定に効いているものだけ**。ピッチに置くのは自分の位置と、
  `ClubStyle` が作る相手のブロック（前3人・後4人、高さと幅が戦い方で変わる）。
  味方を人数ぶん置くと、**判定に無いものが画面にあること**になる。
  文章と場所が食い違わないことは `test/pitch_test.dart` が見張る
  （GKの局面は自陣、「自陣で」と書いてある局面が敵陣に描かれていない、など）。
- **相手の丸は白で縁取る**。クラブの色は12色あって芝と近い緑もある。
  色に頼らず形で分かるようにしておく。
- **引退した選手は額（プラーク）で残す**（`ui/screens/hall_screen.dart` の `HallPlaque`）。
  殿堂が白いカードに文字が並ぶだけで、**大陸を獲った選手と10試合で辞めた選手が
  同じ見た目**だった。色を決めるのは**カードにすでに書いてあるもの**——
  大陸カップ優勝なら金、リーグか国内カップなら銀、無ければ銅。
  見た目のためだけの数字は作らない。帯は選手証と同じ `KitBackground` を使う。
- **画面を PNG に落とす道具を常備する**（`test/shots.dart`、手動実行）。
  「書き出して目で見る」は前から決まりにしていたのに**道具が無く**、
  毎回その場で書いていた。8画面を `shots/` に書き出す（`.gitignore` 済み）。**アイコンは□になる**——
  テストのフォントに MaterialIcons が入っていないだけで、実機では出る。
  引退させる画面を撮るので、殿堂の保存先は差し替える（`ui_test.MemoryHall`）。
  実物は SharedPreferences を待つので、渡さないと `retire()` で止まる。
- **画像素材は持たない**（2026-09-10 決定）。起動画面の1枚と背景の地紋を提案して
  見送りになった。取得系（Pixabay/Pexels、無料）でも生成系でも入れない——
  調達手段の問題ではなく、**このアプリに画像を持たない**という判断。
  見た目は全部その場で描く。**再提案しない。**
- **見た目は試合の判定に一切効かない**（`PlayerLook`）。能力や特性と混ぜると、
  見た目を選ぶことが最適解探しになる。色は番号で持つ（名前で持つと、
  色を足したときに保存データが読めなくなる）。
- **アプリ全体を所属クラブの色で染める**（`main.dart` の `_themeFor`）。
  移籍すれば色が変わるので、どこに居るのかが画面を開いた瞬間に分かる。
  **MaterialApp ごと購読する**——中だけを購読すると、移籍しても色が変わらない。
- **クラブの見た目はIDから決める**（`ui/club_identity.dart`）。色とエンブレムの形を
  保存せずに毎回同じにするので、「あの青いクラブ」という記憶が成立する。名前だけが
  並ぶ画面は、自分がどこに居るのか分からなくなる。**実在クラブを想起させない**よう、
  形は幾何学的なものだけにしてある。
- **色は落ち着いた12色だけ**（`ClubIdentity.palette`）。彩度を上げると20クラブ並んだ
  順位表が読めない。
- **試合の流れを残す**（`MatchInProgress.timeline` → 結果画面）。数字だけの結果は
  38試合ぶん並べても記憶に残らない。「78分に決めて追いついた」が残ると物語になる。
- **推移のグラフは2シーズン目から**（`_CareerChartCard`）。点が1つでは形が分からない。
  評価点は5.5〜8.0の範囲だけを映す（全域だと差が潰れる）。総合力は
  `SeasonRecord.overall` に記録する（古い保存データは0で、線から飛ばす）。

### キャリアらしさ（2026-09-08）

「仕組みは揃っているのに、選手のキャリアを歩んでいる感じがしない」という指摘への答え。
足りなかったのは機能ではなく、**自分のしたことが世界に映り返ってくること**だった。

- **見出しを出す**（`Newsroom`）。ハットトリック・決勝点・大敗・不調・デビュー・
  通算100試合・代表初キャップ・移籍・優勝を、その節の記事として残す。
  **毎試合は書かない**。全部に見出しが付くと、どれも記事に見えなくなる。
  1シーズンで10本前後が目安（テストで「節数より少ない」ことを縛っている）。
- **同じ言い回しを並べない**（`_vary`）。**節番号だけで選んでいた頃は4節ごとに
  同じ文が回ってきて**、記録タブに「◯◯に称賛の声」が並んでいた
  （画面を書き出して初めて見えた。13本中7本が重複）。
  いまは**すでに出ている見出しを避けて**言い回しを選ぶ。
  乱数は持たない——同じ状態からは必ず同じ文になる、という性質は残す。
- **同じ種類の見出しを続けて出さない**（`sameKindGap` 6節）。言い回しを増やしても
  足りなかった。**1シーズンに酷評が11本**出ていたのが本体で、記録タブが
  「また悪かった」の羅列になっていた。新聞は不調を11回書かない。
  間隔を空けて、1シーズンの見出しは11本前後（うち酷評5本）に収まる。
- **見出しはキャリアの記録**。`advanceSeason` と `retire` で必ず引き継ぐ
  （最初は引き継ぎ忘れていて、シーズンを跨ぐたびに消えていた）。
- **その試合の意味**（`stakeFor`）。古巣との対戦・ダービー・首位攻防・残留争い。
  順位が絡むものはシーズンが半分過ぎてから出す（開幕直後の順位に意味は無い）。
  ダービーはクラブIDの隣接で決める（保存しないのに毎回同じ相手になる）。
- **外から見える節目は見出しに残す**（`Newsroom.lifeMoment`）。腕章・スポンサー・財団。
  出来事は33種あって毎季何度も起きるのに、**見出しには一度も残っていなかった**
  （`NewsKind.life` を使っていたのはスタッフ解散だけ。`test/reach_sim.dart` で
  1140シーズン回して分かった）。**断った話は世の中に出ない**——起きなかったことは
  記事にならない。全部の出来事に見出しを付けると、どれも記事に見えなくなる。
- **得点ランキング**（`ScorerRace`）。他クラブの選手を1人ずつ持つ代わりに、
  クラブごとに「点を取る選手」を1人だけIDから決めて置く。節が進むと積み上がり、
  保存も乱数の持ち越しも要らずに毎回同じ数字になる。得点王が「見えている相手」になる。

### 自分の位置（2026-09-08）

「トレーニングが試合に結びついているか分からない」「自分のリーグのレベルが比較できない」
「選手としてのレベルが分からない」への答え。どれも**手元の数字に物差しが無い**という
同じ問題で、能力値78やクラブ強さ61が高いのか低いのかがどこにも書いていなかった。

- **今季の伸びを控えておく**（`CareerState.seasonStart` / `seasonGrowth`）。能力値は
  毎週1ずつしか動かないので、画面を見ているだけでは伸びたことに気付けない。
  開幕時の能力値を保存しておき、差として見せる（`_TrainingEffectCard`）。
  古い保存データには無いので null を許し、その場合は差を出さない。
- **伸びを成功率に翻訳する**（`Ranking.chanceGainPercent`）。能力+1 = 局面の成功率 +0.9%。
  `successChance` の傾きをそのまま使う。テストで両者が一致することを縛っている。
  ここを別に書くと、片方を触ったときに画面が嘘をつく。
- **その能力で実際に何回勝負したかを数える**（`momentAttempts` / `momentSuccesses`）。
  伸ばしているのに数字が動かないとき、局面が来ていないのか相手が強いのかが分かる。
  シーズンごとにリセットする。**今週の練習の対象は、まだ動いていなくても行に出す**
  （効いていないのか記録が無いのかが区別できないのが一番困る）。
- **試合中の選択肢に、今季の伸びを ↑ で添える**（`_OptionButton` の `growth`）。
  練習と試合が繋がる瞬間はここしかない。
- **リーグは世界で並べる**（`Ranking.leagues`）。クラブの強さの平均で全リーグを一列にし、
  S〜D の格を付ける。**格は順位ではなく平均の絶対値で切る**（順位で切ると、リーグを
  1つ足しただけで全部の格が動く）。**平均が同じリーグは同着**にする。
  prestige 5 の3か国は強さが同じなので、順位差を付けると存在しない差を見せることになる。
- **選手の水準は割合ではなくしきい値で言葉にする**（`Ranking.gradeFor`）。世界のクラブの
  大半が下部リーグなので、割合で切ると総合力70で「上位13%」という実感と合わない数字が出た。
  代表招集の水準（`callUpOverall`）を「一流」の線に置き、ガイドにも同じ数字を書く。
- **クラブの強さ = そこで主力を張る選手の総合力**として扱う（`standingIn` /
  `starterClubs`）。登録も移籍もこの数字で判定しているので、比べても嘘にならない。

### 展開に噛み合う試合（2026-09-08）

局面を毎回まったくの無作為で引いていたため、**終盤に2点を追っていても
「いったん外へ預けて作り直す」局面が来た**。スコアは試合中に動いているのに、
中身がそれを見ていなかった。

- **局面に出どころを持たせる**（`ScenarioTempo`）。`any`（骨格）・`chase`（追う）・
  `hold`（守る）。試合の骨格は `any` からだけ引き、`chase` / `hold` は控えに回す。
  全部を状況で決めると試合が型どおりになるので、差し替わるのは終盤の1つだけ。
- **差し替えは局面に入った瞬間に1度だけ**（`_adapt`）。表示のたびに引き直すと、
  画面を開き直すだけで局面が変わる。得点の時間は試合開始時に決まっているので、
  その局面の時間でのスコア（`margin`）がそのまま使える。
- **2点差はもう少し早くから**（`bigDeficitMinute` 58 / `situationalMinute` 70）。
  1点差は終盤に入ってから、2点差は残り30分から勝負になる。
- **差し替わったら理由を画面に出す**（`situationLabel`）。局面だけが変わって
  「1点ビハインド・終盤」が出ていないと、ただの気まぐれに見える。
- 実測で、出場した試合の **39% に追いかける局面、18% に守り切る局面**が出る。
  多すぎない（毎試合出ると特別ではなくなる）。

### 1つのゲームにする（2026-09-08）

「各機能が独立している感がある」という指摘への答え。原因は、**積み上げたものが
働く瞬間に、それが見えていなかった**こと。特性も個人技も型も相方も気持ちも、
`chanceFor` の中で数字に溶けていて、画面には合計の％しか出ていなかった。
練習を決める画面には相手も監督の期待も無く、出場機会の式はどこにも出ていなかった。

- **成功率の内訳を出す**（`ChanceFactor` / `factorsFor`）。**表示用に別の式を書かない。**
  `chanceFor` は「地力 ＋ 内訳の合計」で出す。テストで両者の一致を縛ってある
  （ここがずれると、このゲームで一番やってはいけない「表示と判定の食い違い」になる）。
- **共通のものと、その手だけのものを分ける**（`sharedFactors` /
  `distinctFactorsFor`）。分類は手で持たず、**その局面の3つの手で値が同じかどうか**で
  機械的に決める。相手の格・コンディション・気持ちは3つとも同じ値なので局面の側に、
  特性・個人技・型・相手の戦い方・相方・逆足は手ごとに違うので手の側に出る。
  分けないと「格下の相手 +16%」が3つとも並び、選ぶ材料が埋もれる。
- **今週なにをするかを1か所に集める**（`WeekPlan`）。練習は育成タブ、相手はクラブタブ、
  監督の期待は試合タブと、判断に要るものが3か所に散っていた。決めるのは1つなので、
  決める場所に材料を持ってくる。離脱 → 疲労 → 次の相手 → 監督の期待 → 平常、の順に1つだけ。
  **勧める練習は、そのポジションで選べるものに限る**（GK 以外に GK 練習を勧めない）。
- **次に出られるかを見せる**（`SelectionOutlook`）。出場機会は評価点・監督の信頼・方針・
  競争相手で決まるのに、その式はどこにも出ていなかった。落ちた理由が分からないまま
  数試合が過ぎるのが一番きつい。`decideAppearance` と同じ式から出す。
  **出られない理由は評価点より先に見る**（離脱 → 出場停止 → 登録外 → 評価点、
  `startNextMatch` と同じ順）。これを飛ばしていたので、**怪我をしていても
  「先発の見込み」と出ていた**（`headline` の injured / suspended に到達しなかった。
  2026-09-10 に管理画面の「効き」を作っていて見つかった）。
- **相手への慣れがここで初めて見える**（`adaptationFor`）。26回戦った相手なら
  「−5% のはずが −1% まで戻っている」と書ける。積み上げが効いていることの証拠になる。
- **今日の意味を1枚に**（`MatchBrief` / 2026-09-10）。監督の求める形・目標の残り・
  順位・得点王レース・相手の戦い方が、**4つの別々の画面**に散っていた。
  試合に入る直前に「今日の1本が何に効くのか」を見返す場所が無いので、
  どの機能も独立した飾りに見える。次節カードの1ブロックに集める。
  **判定に使う式は増やさない** — 既にある `Manager.tactic.favours` /
  `SeasonObjective` / `leaguePosition` / `ScorerRace` を1か所に集めるだけ。
  スマホ1画面に収める制約があるので、**中身の無いものは出さない**
  （開幕5節までの順位表、達成済みの目標項目、届かない得点王レース）。
- **経験点で自分に振る**（`Development.points` / `experienceCost` / 2026-09-10）。
  成長は**全部自動**で、伸ばす先を選ぶ余地が無かった。練習の種類でカテゴリは
  選べても、その中のどれが伸びるかは運任せ。伸びるはずだった1回ぶんを
  経験点にして持ち越し、自分で振れるようにする。
  - **既定は自動のまま**（`autoSpend` 既定 true）。今まで自動で伸びていたものが
    ある日から自分で振らないと伸びなくなるのは、続きから遊ぶ人にとって
    不意打ちでしかない。1タップで切り替えられる形にしてある。
    保存に `autoSpend` が無ければ自動（＝今までどおり）で読む。
  - **上に行くほど値段が上がる**（`experienceCost`）。平らにすると、
    一番得意なところに全部注ぐのが常に正解になる。
  - **付与量と値段を釣り合わせる**（`pointsPerGrowth` 4 ≒ 65 のときの値段）。
    ここがずれると、切り替えるだけで成長速度が変わる。
    実測（120キャリア）: 自動 ピーク76.7 / 自分で振る 77.4。
    **選べることの見返りは +0.7**（伸ばす先を選べること自体であって、
    伸びる量ではない）。
  - **カテゴリを跨いでは使えない**。パスの練習で守備は伸びない。
  - **土台が足りなければ土台のほうが伸びる**（練習と同じ `Dependencies.resolve`）。
    別の式にすると、自分で振ったときだけ土台を無視できてしまう。
  - 貯めたまま忘れると伸びない選手になるので、`今の状態` に
    「振っていない経験点 ◯点」を出す。

- **取り返しのつかないところを作る**（2026-09-10）。このゲームで戻せないのは
  **怪我だけ**だった。信頼は下がっても、出れば評価点で戻せる。だから積み上げた
  選択に値段が付かない。
  - **構想外**（`CareerState.frozenOut` / `frozenOutTrust` 12）。登録メンバーには
    入っているが、この監督の下では使われない。**出られないので評価点も付かず、
    評価点で戻す道だけが閉じている**。戻るのは監督交代・移籍・出来事での歩み寄り。
    実測で15%のキャリアが一度は落ちる（自動進行・60キャリア）。
  - **落ちる前に必ず画面に出す**（`trustAtRisk` / `trustWarning` 28）。
    予告なしに落とすのは理不尽。警告は45%のキャリアで出る（落ちるのは15%）。
  - **無理を通した代償**（`severeShareFor`）。累積疲労は**終盤の落ち込みにしか
    効いていなかった**。疲れ切った身体ほど、引くのは重いほうの怪我にする
    （重傷はポテンシャルを削る＝戻らない）。**怪我の回数は二重に増やさない** —
    `Fatigue.injuryFactor` が既に回数に効いている。
  - 最初 `severePerFatigue` を 0.0022 に置いたら、**重傷が 1.16 → 2.85回/キャリア**
    になった。0.0008・上限0.13 で 1.85回。走り続けた選手だけが壊れる幅に置く。

- **出来事を週の主役にする**（2026-09-10）。頻度は 6節に1回（0.16）で、
  「たまに何か出る画面」だった。0.24（3〜4節に1回）に上げ、出来事を14本足した。
  - **選択肢に「何に効くか」を出す**（`LifeEffect.summary`）。名前だけの三択は
    どれを押しても同じに見え、選ぶ材料が一つも無かった（結果は押した後に出る）。
    **表示に使う一覧と判定が同じ値**。効きの無い選択肢は「何も動かない」と書く
    （黙って空欄にすると、書き忘れと区別が付かない）。
  - **自分が選んだことが出来事になって返ってくる**。追い込んでいる週・
    約束している最中・身体が落ちているときにだけ出る話を用意した。
  - **一緒に練習している相手の話が3倍出やすい**。週の選択（誰と組むか）が
    ピッチの外にも返る。
  - **直前に出た話は続けて出さない**（`recentEvents`、6件）。頻度を上げたぶん、
    同じ話が近くで繰り返されると出来事そのものが安っぽく見える。
  - **ピッチの外で伸びるにも身体を使う**（`eventTrainFatigue`）。
    出来事は**ただの上乗せ装置**になりやすい。頻度を 0.34 まで上げたら
    ピーク総合力 76.4 → 77.5、代表経験 53% → 63% に膨らんだ。
    0.24 に戻して +0.6 / +3pt まで抑えた（**頻度がそのまま強さになる**）。

- **カップ戦を実際に戦う**（`lib/models/cup.dart` / `lib/game/cups.dart` / 2026-09-10）。
  カップ戦は `runDomesticCup` / `runContinental` が**シーズン末に結果だけ**を
  振っていた。到達ラウンドは年俸にも評判にも記録にも効くのに、
  プレイヤーは1分もプレーしない。「優勝した」と書かれるだけで、そこに試合が無かった。
  - **1週1試合の刻みは変えない**（`Cups.weeksFor`）。カップ戦はリーグ戦の
    合間の週に入る（代表ウィークと同じ扱いで、節は進まない）。
    **節を決め打ちにしない** — 16クラブの国は30試合しかないので、
    シーズンの長さから散らす。代表ウィークとも、もう一方のカップとも重ねない。
  - **カップ戦の週は練習ができない。** ここが要。リーグ戦のぶんに足して練習まで
    積めると、カップ戦は「試合数が増えて強くなるだけ」の装置になる。
    深く勝ち上がるほど**育成の時間を失う**（実測で 限界突破 11%→8%）。
    現実でも中2日で練習はできない。
  - **国内カップは一発勝負5回**（1回戦・16強・準々・準決・決勝）。引き分けはPK戦で、
    **PKは実力ではほとんど決まらない**（`shootoutBase` 0.5）。ここを実力差にすると
    一発勝負の意味が消える。
  - **抽選は現実と同じで、早いラウンドは自分と同じか下の部**（`drawDomestic`）。
    一律に1部から引いたら、2部のクラブは**72シーズン中51回1回戦で消えた**
    （カップが年2試合の飾りになる）。自分の部を基準に振り直して 40回。
  - **大陸カップはグループ6試合 → 決勝トーナメント（16強・準々・準決は2戦合計）
    → 決勝1試合**の13試合。**決勝だけ中立地の一発勝負**。
    2戦目は第1戦の合計を背負う（`CupTie.aggregateFor`）。
  - **早いラウンドは控えと若手が出る場**（`cupRotationBonus` / `cupRestChance`）。
    素通しにするとカップは「主力の試合数が増えるだけ」になり、
    若手が出番を掴むという現実の構図が消える。
  - **リーグと混ぜない**（`MatchResult.cup` / `isLeague`）。順位表・平均評価・
    監督の目標・約束はリーグ戦だけで数える。カップの試合数はクラブの勝ち上がりで
    変わるので、そこに目標を乗せると年ごとに難しさが変わる。
  - **到達ラウンドは戦った結果から決まる**。ただし**カップ戦を持たない保存データは、
    これまでどおりその場で振って埋める**（黙って不出場にすると、続きから遊ぶ人の
    シーズンから大会が1つ消える）。
  - **予定を取りこぼすと大会がそこで止まる**（`_scheduleCup` は `<=` で見る）。
    `played` が増えないので、次の週も同じ予定を待ち続けることになる。
  - 世界大会（代表）はこれまでどおり**結果だけ**。4年に1度・オフの大会なので、
    リーグの週を使わない。

- **週を選ぶゲームにする**（`TrainingEffort` / `TrainingCompanion` /
  `TrainingOutcome` / 2026-09-10）。週の選択は「どのメニューか」だけで、
  **踏み込む/流すの判断も、誰と組むかの判断も無かった**。毎週同じ画面で
  同じものを選ぶだけなので、練習の週に手応えが無い。決めるのは3つにする:
  **何をするか・どこまで踏み込むか・誰と組むか**。
  - **伸びの倍率は持たせない。手応え（大成功・空回り）の出方そのものを動かす。**
    倍率と確率の両方を動かすと、どちらが効いているのか画面から追えなくなる。
    大成功なら伸びの抽選を2回、空回りなら0回引く（「大成功で2つ伸びた」と数えられる）。
  - **疲れているほど空回りする。** これが無いと「追い込む」を毎週押すのが
    最適解になる。コンディションとプロ意識で手応えが動く。
  - **組む相手にも消耗を払わせる。** ただで手応えが上がるなら、組める相手が
    居る限り「一人でやる」を選ぶ理由が一つも無くなる。
  - **相手が移籍で居なくなったら黙って一人に戻す。** 居ない相手と組んだことに
    して手応えだけ上がるのが一番まずい。
- **コツ**（`lib/game/knacks.dart` / `Trait.knackKey` / 2026-09-10）。
  特性は**生まれ持ったもの**で伸ばせない、という前提でずっと来た。
  そのぶん、20年やってきたことが選手の「性質」には一切乗らなかった——
  パスばかり選び続けた選手も、最後まで司令塔にはならない。
  キャリアで**1つだけ**、やってきたことが特性になる道を開ける。
  - **経験点では買わせない。** 自動で振る側（既定）は経験点が貯まらないので、
    値段を経験点にすると**既定のまま遊ぶ人だけ一生掴めない**。
    条件は 試合経験350・練習の大成功26回・その場面で40回勝負したこと。
  - **候補はキャリアから決まる**ので、待っても引き直せない。引き直せると
    「良いコツが出るまで待つ」が最適解になり、何をやってきたかが関係なくなる。
  - **生まれつきでしか手に入らないものは掴めない**（稀なもの・欠点・
    早熟/大器晩成）。`Trait._knackKeys` に載っている15種だけ。
  - 実測（108キャリア）: **流す 0% / 普通 77%（29.0歳）/ 追い込む 94%（23.6歳）**。
    **流し続けたキャリアはコツを掴めない**——限界突破と同じ形にしてある。
    掴めない理由は育成タブに書く（「練習の大成功があと◯回」）。

- **追い込んだ週だけが、届く高さを変える**（`Development.greatWeeks` /
  `breakthroughGreatWeeks` / 2026-09-10）。ここが一番大事な発見。
  練習の効きを上げても、**ポテンシャルで止まるので同じ選手になる**
  （実測: 流す 74.0 / 普通 74.5 / 追い込む 74.8 — 週あたりの伸びは
  0.59 / 1.00 / 1.36 も違うのに、キャリアの結果はほぼ同じ）。
  練習で大成功した週を数え、それを**限界突破の条件**にした。
  これで週の選択が「ピークに着く速さ」ではなく「届く高さ」を変える。
  結果: 限界突破 流す 0% / 普通 8% / 追い込む 25%。
  育成タブに「限界突破の下地まであと◯回」を出す（見えないと選ぶ理由が分からない）。
- **週の設定はシーズンを跨いで残す**。`advanceSeason` に渡し忘れると
  毎年こっそり「普通・一人」に戻る。**実測で見つけた**（追い込むを選び続けても
  大成功が 46回 にしかならず、流すの 41回 とほぼ変わらなかった）。

- **毎週の選択を、選択にする**（`Development.strain` / `Formulas.driftStrain` /
  2026-09-10）。`test/week_sim.dart` を40キャリア×条件で回して分かったこと:
  **3択のうち1つが死んでいて、残り2つの差も薄かった。**

  | | ピーク | 平均評価 | 怪我/季 | 通算出場 | コツ | 限界突破 |
  |---|---|---|---|---|---|---|
  | 流す | 73.0 | 6.91 | 1.11 | 562 | 3% | 0% |
  | 普通 | 74.7 | 6.99 | 1.19 | 545 | 88% | 8% |
  | 追い込む | 75.1 | 6.99 | 1.33 | 538 | 98% | 28% |

  **「流す」に上振れが一つも無い。** 見返りは怪我が年 0.22回減ることと
  通算出場が +24試合（+4%）だけで、**リスクを避けたことに固有の勝ち筋が無い**。
  「一人でやる」も全指標で最下位だった（ピーク 74.7 / 大成功 40 で、組む3つはどれも上）。
  20年で760回ある選択が、「追い込む＋誰かと組む」を押し続ける作業になっていた。

  - **身体の消耗（`strain` 0〜100）を持つ。** コンディション（週で上下する）とは
    別のもので、**最近どう踏み込んできたか**を映す。衰え始めの年齢（±2歳）と
    重傷の引きやすさ（×0.82〜1.20）を動かす。
  - **累積ではなく、落ち着き先へ寄せる**（`driftStrain`、1シーズンでほぼ着く）。
    累積にすると若い頃の1年で残りが決まり、**30歳で流し始めても何も起きない**。
    寄せる形にして初めて「若いうちは追い込み、歳を取ったら引く」が手になる。
  - **境目は落ち着き先ではなく、実際に着く値で切る**（`strainNeutral` 38）。
    疲れた週は自動休養が踏み込み方を「流す」に落とすので、追い込み続けても
    消耗は 86（落ち着き先）には行かない（実測 56）。落ち着き先で切っていた頃、
    **追い込んだ選手に代償が一つも付かなかった**。
  - **「一人でやる」は空回りが減る**（`flatRelief` 0.05 / 組むと 0.015〜0.025）。
    大成功は出ないが崩れもしない、という振れ幅の小さい手にする。
    **掛け算にしてはいけない**——`flat` の大きい「流す」だけが救われて、
    ピークが 73.0→75.0 に跳ね、3択がまた平らになった（実際にやって戻した）。
  - 実測（切り替える型を足して測った）:

    | | ピーク | 引退時 | 重傷 | 通算出場 | 33歳以降 |
    |---|---|---|---|---|---|
    | ずっと追い込む | 74.6 | 73.4 | 2.55 | 516 | 90試合 |
    | 26歳から流す | 74.8 | 74.1 | 1.82 | 540 | 102試合 |
    | 29歳から流す | 74.8 | 73.9 | 2.30 | 535 | 102試合 |

    **途中で引いたほうが全部良い。** 一定の踏み込み方しか測っていないと
    この手は測れないので、`Playstyle.easeFrom` を足してある。

- **性格が全員天井に張り付いていた**（`Personality.origin` / `settleToward` /
  2026-09-10）。40キャリア**全部**がプロ意識 20（上限）で引退していた。
  自信 15.8・野心 15.4 も同じ。原因は**性格を動かす道が全部足し算だった**こと:
  生活イベントの「+1 プロ意識」が19か所あって**下げるものが1つも無く**、
  `Person.evolve` も条件が続く限り足し続けていた。
  練習効率（`trainingFactor`）も衰え始めの年齢も、**20年やれば誰でも同じ**になり、
  性格で選手が違ってくる部分が消えていた。
  - **生まれ持った値を覚えておく**（`Personality.origin`、入れ子は1段だけ）。
    落ち着き先は**生まれ持った値＋今の立場**で、`evolve` は1シーズンに1歩だけ寄せる。
    立場が変われば戻る。知らない保存データは「今の値が生まれ持った値」として読む
    （10 に寄せると、続きから読み込んだ選手の性格が跳ねる）。
  - **生活イベントで性格が動くのは転機だけ**（19か所 → 3か所）。
    ふつうの選択に +1 を配ると、数だけで天井に着く。
  - **イベントで動ける範囲に壁を置く**（`driftMin` 4 / `driftMax` 16）。
    生まれ持った幅（5〜15）はそのまま。外へ向かう変化だけ止め、
    真ん中へ戻る向きは止めない。
  - **練習効率の中心は動かさない**（`0.7 + 0.03p` → `0.66 + 0.05p`）。
    天井に張り付いていた頃この式は**全員に 1.30 を返していて**、バランスは
    その値で取れている。中心はそのままに傾きだけ立てた（5〜16 で 0.91〜1.46）。

- **何が試合を動かしているかを測る**（`test/influence_sim.dart` / 2026-09-10）。
  「積み上げと個人技があまり意味をなしていない」という指摘を、当て推量ではなく
  数字で確かめるための道具。自動進行と同じ手を選びながら、選ぶ直前に
  `factorsFor` を覗いて**仕組みごとの効いた回数・平均の大きさ・持ち分**を出す。
  24キャリア・41944局面で分かったこと:

  | 仕組み | 効いた局面 | 平均 | 持ち分 |
  |---|---|---|---|
  | 気持ち・波 | 98.4% | +3.75% | 16.5% |
  | コンディション | 98.8% | −0.30% | 11.5% |
  | 相方との呼吸 | 57.4% | +4.80% | 10.8% |
  | 型（組み立てる選手） | 98.2% | +1.50% | 8.7% |
  | 個人技（ノールックパス） | 49.6% | +3.08% | 6.0% |
  | **大一番** | 15.9% | **−0.10%** | 1.1% |
  | 相手の戦い方（4つ合計） | — | — | **1.1%** |

  **積み上げの側はどれも「常に少しだけ効く飾り」だった。**
  個人技は1人あたり 2.83個（上限3）＝**誰でも3つ揃い、選ぶ余地も
  使いどころの判断も無い**。大一番は経験が重圧を完全に打ち消していて実質ゼロ。
  相手への慣れは全部合わせても増減の 1.1%。
  **一番大きく効いているのは、プレイヤーが今この瞬間に動かせないもの**
  （気持ち・コンディション）だった。

- **切り札**（`MatchInProgress.armed` / `Formulas.signatureArmedBonus` / 2026-09-10）。
  個人技を**受け身の +3%** から**使いどころの判断**にする。
  1試合に1回だけ「この局面で出す」と構えられ、乗る手に +15%。
  - **その局面に出せる手が無ければ構えられない**（`armable`）。覚えた技と
    目の前の局面が噛み合ったときだけ選択肢になる。
  - **外すと、その試合の残りが −5%**（力んだ）。代償が無いと
    「乗る局面が来たら必ず構える」が正解になり、判断がまた消える。
  - **乗らない手を選べば使い切らない。** 構えるだけならただ、では困る一方、
    間違えて別の手を選んだら1枚失う、も理不尽。
  - **自動進行にも見せる**（`autoArm`）。見ないと自動で進めるだけで
    切り札が一度も使われず、個人技が飾りに戻る（監督の求める形と同じ理屈）。
  - 実測: 局面の **20.4% で切り札が乗る**（3局面のうち約0.6、つまり
    6割の試合で1枚使う）。平均評価は 7.00 → 7.07。

- **積み上げに効き目を持たせる**（同 2026-09-10）。
  - **型は上乗せではなく偏り**（`identityBonusFor` +3%/−1% → **+5%/−4%**）。
    平均するとほぼ増減しない。型を持つことは強くなることではなく、尖ること。
    ここで初めて「型を通すか、監督の求める形に合わせるか」が痛い選択になる。
  - **相手の戦い方は、慣れで消しきれるところまで深くする**
    （`styleMismatch` 5% → **8%**、`adaptationFor` の上限 0.04 → **0.08**）。
    上限 0.04 では苦手を薄めきる前にキャリアが終わっていた。
    32回（3〜4シーズン）で消える——速すぎると苦手が最初の1年で終わる。
  - **大一番の重圧を深くして、経験で埋める**
    （`bigMatchPressure` 5% → **10%**、`composure` 上限 0.05 → **0.10**）。
    浅いままだと、経験が打ち消した瞬間に**両方とも消える**。
    深くすると、若い選手の大一番は本当に怖く、20年の経験に値段が付く。
  - **全部入れて 平均評価 7.00 → 7.07 / ピーク 75.0 → 74.9**。
    効き目を大きくしても、バランスは動かさない。

- **監督との約束**（`ManagerPromise` / `PromiseOffers` / 2026-09-10）。
  監督の `SeasonObjective` は**向こうから降ってくる数字**で、受け取るだけだった。
  約束は逆に、**自分から数字を口にする**。第8節までに1つだけ、取り消せない。
  果たせば信頼と契約更改の年俸が乗り、届かなければ両方を失う。
  口にした時点で記事になる（胸に留めておけるなら、それは約束ではない）。
  - **難しさの順は実測で決める**（`test/promise_sim.dart`、2304シーズン）。
    言葉の響きで並べた最初の案（出場+2 / 得点関与+3 / ゴール+4）では、
    **順当（23.5%）が大きく出る（27.0%）より難しい**という逆転が起きていた。
    今は 出場（67%）／平均評価 +0.4（52%）／ゴール（30%）の順。
  - **見返りと罰は達成率で割り戻す**。「大きく出るほど罰も大きく」を素直に
    実装すると、3回に1回しか通らない `bold` が押してはいけないボタンになる。
    どの出方も期待値がわずかに前向きになる幅（+4/-6、+11/-11、+30/-12）に置いた。
  - **年俸に効くのは契約更改の年だけ**（契約が残っていれば条件は動かない）。
    画面には「契約更改 +25%」と書く。「年俸 +25%」では動かない年に嘘になる。
  - 約束は**交渉の枠ごと**動かす。上限に丸めた後で掛けると、良いシーズンで
    上限に張り付いた瞬間に効き目が消える（実測で、果たしても破っても同じ
    1350万円になっていた）。
  - 信頼は監督が代われば白紙に戻る。**果たした見返りが消えることがある**のは
    そのまま（監督が代わるのはキャリアで一番よくある転機なので、ここは崩さない）。
- **得点王レースに自分を乗せる**（`ScorerRace.chaseFor` / `rankOf` / 2026-09-10）。
  得点ランキングは**他人の数字を眺めるだけの表**だった。`rankOf` は書いてあるのに
  どこからも呼ばれておらず、6人表示の末尾に付け足された自分の番号は
  「7」と出ていた（本当は14位でも）。終盤で首位に手が届くときだけ、
  次節カードと**局面を選ぶ画面**に「得点王まであと2点」を出す。
  シーズンのどこにいるかで、同じ1本の意味が変わる。
  **序盤には出さない**（残り10節を切ってから）。届かない差なら煽らない。

### 画面の作り

- **拠点は5つのタブに分ける**（`_MatchTab` / `_PlayerTab` / `_TrainingTab` /
  `_ClubTab` / `_CareerTab`）。1枚のリストに全部載せていた頃は、次の試合に入るのに
  6画面ぶんスクロールが必要だった。1タブ = 1つの目的に保つ。
- **一番よく押すものは FloatingActionButton に置く**（`_PrimaryAction`）。
  試合へ／代表戦へ／欠場する／シーズンを終える、を状況で切り替える。
  どのタブに居ても、スクロール位置に関係なく押せることが大事。
  **ただし試合タブでは出さない**。カードの中に同じボタンがあるうえ、FAB が
  その下の「この試合」「区切りまで」に被さって押せなくなっていた。
  シーズン終了時だけは試合タブでも出す（カードの側が別のものに変わるため）。
- **毎週の操作は、毎週通る場所に出す**（`_NextMatchCard` の「今週の練習」）。
  練習は一度決めると続くので、育成タブを開かないと今の設定が見えなかった。
  試合へボタンのすぐ上に置けば、忘れようがない。
  **元気なのに休んでいたら「伸びない」と書く**（`CareerState.restingWhileFresh`）。
  実際に遊んでいて、コンディション100のまま「休養」で9節進み、
  何も伸びていないのにどこにもそう書いていなかった（休養が既定だった頃の
  保存データは、育成タブを開かない限りずっと休養のまま）。
  **自動休養の週とは出し分ける**——そちらは休むのが正しい週なので。
- **その場で終わる操作は、画面を移らせない**（`ui/training_sheet.dart`）。
  最初はタブへ飛ばしていたが、戻るのに2手かかりスクロール位置も失う。
  毎週触るものはシートで完結させる（居残りも同じシートに置く）。
- **説明をツールチップだけに置かない。** スマホでは長押ししないと読めない。
  選んでいる練習メニュー・オフの過ごし方は、本文として画面に出す。
- **押せるものは押せるように見せる。** ピッチ外の出来事の選択肢は
  カードと同じ色の塗り（`FilledButton.tonal`）で、地の文と見分けが付かなかった。
  枠線と「>」を付けてある。終わった試合の行も、開けることが分からなかったので
  同じ印を付けた。
- **毎週触らない設定は畳む**（`_SupportCard` の ExpansionTile）。専属スタッフと
  生活習慣は、開いた瞬間に20個近い選択肢が並んで練習を選ぶ邪魔になっていた。
- **選択肢が10を超えたら小見出しで割る**（練習メニューの「1か所を鍛える」「2か所を同時に」）。
- **待っている話は状態カードに出す**（`_StatusCard`）。腕章やスポンサーの打診は
  ランダムな出来事が来るまで気づけないので、先に見えるところへ置く。
- **画面の構造はウィジェットテストで縛る**（`test/ui_test.dart`）。スマホ幅（390px）で
  開いてタブを移動し、崩れないことと、主要な動作が常に出ていることを見る。
- **日本語フォントは同梱する**（`assets/fonts/NotoSansJP-*.ttf`）。入れていなかった頃、
  Web版（CanvasKit）が足りない字形を `fonts.gstatic.com` から取りに行き、取りきれなかった
  字が豆腐（□）で残っていた。公開中の画面に「監□の期待」「得□関□」「契約更□の年□」が
  出ていた（督・点・与・改・俸・効・悪が欠けていた）。**ほとんどの字は出るので、
  テストでは気付けない**——実際に公開ページを開いて初めて分かった。
  選手名は自由入力なので、ソースに出てくる文字だけに絞る形にはしない。
- **広い画面では本文の幅を止める**（`ui/readable_width.dart`、520px）。スマホの縦画面を
  前提に組んであるので、PC のブラウザでは1行が画面幅いっぱいまで伸びて読めなかった。
  タブバーも同じ幅に収める（5つが端まで散ると、隣のタブへ移るのに画面を横断する）。
  ウィジェットテストで 1400px 幅を開いて縛ってある。
- **画面に出す文字は、必ず同梱フォントの中から選ぶ**（`test/font_test.dart`）。
  ソースの文字列リテラルに出てくる全文字が `NotoSansJP` の cmap にあることを検査する。
  これを入れた初回に `·`（U+00B7）と `◯`（U+25EF）が引っ掛かった——どちらも cp932 に
  無いので、外部フォントに頼って表示されていた。`・` と `○` に置き換えてある。
  **区切り記号を足すときは、まず cp932 にあるかを疑う。**
- **公開まわりのメタ情報は雛形のままにしない**（`web/index.html` / `web/manifest.json`）。
  `description` が "A new Flutter project."、`name` が `soccer_career`、`theme_color` が
  Flutter の水色のまま公開していた。検索結果とリンク共有に出るのはここ。
  アイコンは `tool/make_icons.py` で作る（web / Android / iOS を一度に書き出す）。
- **起動を待つ間の画面を置く**（`web/index.html` の `#boot`）。Flutter は本体と
  フォントを読み終えるまで何も描かない。初回は圧縮後で約5.7MB あるので、
  置かないと数秒間まっ白なページを見せることになる。`flutter-first-frame` で消す。
- **セーブの持ち出しは、こちらから促す**（`ui/transfer_code.dart` /
  `CareerState.backedUpYear`）。保存は端末の中にしか無いので、ブラウザのデータを
  消せば消える。iOS はしばらく開かないサイトの保存領域を自分で消す。
  「⋮」の奥に置いてあるだけでは気付かないまま何年も進んでしまうので、
  シーズン終了画面に常設し、3年ぶん控えていなければ色を変える。
- **終わった試合を開けるようにする**（`_MatchDetail`）。結果画面を閉じると、
  その試合で何があったかは二度と見られなかった。得点した時間は
  `MatchResult.goalMinutes` に残す（セットプレーぶんは時間が分からないので入らない）。
  その節の見出しも一緒に出す。
- **オフライン対応は入っていない。** Flutter 3.47 は自分を消すだけの
  サービスワーカーしか吐かず（`--pwa-strategy` は無くなった）、自前で書くしかない。
  書いてはみたが、この環境のブラウザがサービスワーカーの登録を拒むため
  **オフラインで開けることを確認できなかった**ので入れていない。
  壊れたサービスワーカーは古いビルドに利用者を固定するので、
  実機で確認できるまで入れない。
- **遊び方ガイドは実装から作る**（`ui/screens/guide_screen.dart`）。特性・練習メニュー・
  方針・スタッフの一覧は enum をそのまま並べ、しきい値は `Formulas` から引く。
  手で書き写すと、仕様を足したときに黙って古くなる。

### 管理画面（開発用・公開ビルドには入らない）

稀な特性は20人に1人、超越が効くのは能力89から、引退は33歳から——**作った仕組みの多くは、
普通に遊んで確かめようとすると数十シーズンかかる**。稀な特性の確認に400シードを回した
ことがあり、それが管理画面を作った理由。

- **入れるか入れないかはビルド時に決める**（`lib/dev/admin.dart` の `kAdmin`）。
  `bool.fromEnvironment('SOCCER_ADMIN') || kDebugMode` の const なので、
  公開ビルドではコードごと落ちる。隠しジェスチャーや合言葉にはしない——
  それだと**コードは残る**ので、解析すれば誰でも開ける。
  手元の release で見たいときは `flutter build web --release --dart-define=SOCCER_ADMIN=true`。
- **参照そのものを `kAdmin` で囲む。** メニュー項目を `if (kAdmin)` で囲んだのに
  `switch` の `case 'admin':` を囲み忘れていて、**公開ビルドに管理画面が丸ごと
  残っていた**（`case 'admin' when kAdmin:` で解決。ビルドが 37KB 減った）。
  テストでは気付けないので、**`flutter build web --release` して
  `python tool/check_release.py`** で見る。日本語は `\uXXXX` に落ちるため、
  そのまま grep しても当たらない（当たらないことを「入っていない」と読み違えた）。
- **中身は4タブ**。特性（75種を名指しで付け外し）・状態（能力22項目とポテンシャル・
  気持ち・信頼・お金・規律）・局面（72局面を指定して試合に入る）・時間（シーズン消化と
  N年進める）。式は画面に書かず `AdminActions` に集める（テストが同じ道を通れる）。
- **書き換えたキャリアには印を付ける**（`CareerState.tampered`）。引き継ぎコードで
  持ち出せてしまうので、**印は保存にも乗せ**、シーズンを跨いでも引退しても消さない。
  印は選手タブに出る——この表示だけは公開ビルドにも入っている（改変済みのセーブを
  読み込んだときに何も出ないと、普通の記録に見えてしまう）。
- **時間を飛ばす操作には印を付けない。** 自動進行と同じ道を通るだけなので、
  印が指すのは「数字を書き換えた」ことだけにする。
- **変えた結果、ゲームの何が動くかを同じ画面に出す**（`AdminImpact`）。
  値をいじれるようにしただけでは「それで何が変わるのか」が見えなかった。
  総合力と水準・次の試合・局面の成功率・怪我の確率・伸びしろ・お金・規律の7行を、
  どのタブに居ても見える位置に置き、**操作のたびに前後の差分**
  （「局面の成功率 +6% → -9%」）を出す。
  **ここに式を書かない。** 全部、実際に判定している関数から引く
  （`Ranking.gradeFor` / `SelectionOutlook` / `MatchEngine.injuryChance` /
  `MatchInProgress.conditionModifier` / `CareerState.budget`）。テストで一致を縛ってある。
  そのために `rollInjury` から確率だけを `MatchEngine.injuryChance` に、
  土台の確率を `CareerController.injuryBaseChanceFor` に切り出した。
- **「動かなかった」ことも書く**（`_changes` が null か空か）。無言だと
  「効かない操作をした」のか「押せていない」のか区別が付かない。
  天才を付けても今の数字は動かない——効くのは成長のときだから、そう書く。
- **いまは公開サイトにも入れてある**（2026-09-10、ユーザーの指示で一時的に）。
  `soccer-career-pages.yml` の Build web に `--dart-define=SOCCER_ADMIN=true` が付いている。
  **公開サイトを開いた誰でも右上の ⋮ → 管理 を触れる状態**なので、
  収益化やストア申請の前には必ず外す。**戻すのはその1行から `--dart-define` を消すだけ。**
  この間は `tool/check_release.py` が「入っています」と出るのが正しい。
  **2026-09-10 に「当面このままでよい、ストア提出前にまた聞いてくれ」と確認済み。**
  こちらから外す提案を繰り返さない——**提出・収益化の話が出たときに1度だけ言う。**

## まだ無いもの

- 収益化（広告・課金）。ストア申請も未着手。`soccer-manager` の `STORE_LISTING.md` が先例。
- 他クラブの選手を1人ずつ持っていない（外国人枠も序列も見積もりで出している）。
- 移籍金はクラブ間の数字として表示するだけで、クラブの財政は持っていない。

## 公開

Web版は master への push で Cloudflare Pages に自動デプロイされる
（`.github/workflows/soccer-career-pages.yml`）。
**公開URLは https://soccer-career-49p.pages.dev/ **。
`soccer-career.pages.dev` は別アカウントの別アプリが取っているので、そちらを見ても
このアプリは出てこない（Pages のサブドメインは全体で先着）。
検証は `soccer-career-ci.yml` に分けてあり、公開設定のミスでテストまで赤くならない。

**セーブは端末ごとに独立**（localStorage）。PC で進めた内容とスマホの内容は別物になる。
持ち運ぶときは、右上のメニューの**引き継ぎコード**（`SaveRepository.encode` / `decode`）を使う。
クラウド同期は置かない代わりに、自分でコピーして移せる形にしてある。
**読めないコードで今のキャリアを消さない**（復元できたときだけ上書きする）。

## テスト

対象を絞って回すときは workflow_dispatch の `target` を使う。

**`CareerController` を作るときは `random:` にも種を渡す。** 渡さないと
出場機会の判断と出来事だけが実行ごとに変わり、同じ種なのに結果が揺れる。
